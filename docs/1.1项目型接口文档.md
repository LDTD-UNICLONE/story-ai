# 1.1 项目型接口文档

## 1. 文档范围

本文档对应当前后端代码中的普通项目型工作流：项目、章节、章节处理、资产分析与管理、资产图像、分镜制作、故事板图像、分镜视频、生成历史和任务查询。

本文档不包含：Agent 项目、对话型接口、作品中心和管理端接口。

- API 前缀：`/api/v1`
- 项目资源前缀：`/api/v1/projects`
- 资源 ID：UUID
- 时间：北京时间 ISO 8601
- 所有 DELETE 均为软删除

普通项目接口只允许访问当前用户、`is_enabled=true` 且 `project_kind=standard` 的项目。已知 Agent 项目 UUID 也不能通过本文档中的嵌套路由访问。

## 2. 认证与响应

除模型和风格查询外，本文档中的接口均需登录：

```http
Authorization: Bearer <access_token>
Content-Type: application/json
```

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": "2026-08-20T18:30:00+08:00"
}
```

业务失败仍使用相同包装结构。Pydantic 参数校验失败时 HTTP 状态为 `422`、业务码为 `42200`。

异步任务提交接口还可能返回：

```http
X-Next-Poll-Seconds: 5
```

前端应优先使用响应体 `next_poll_seconds`，其次使用该响应头。

## 3. 标准工作流

1. `GET /styles` 获取风格，`GET /models/options` 获取模型。
2. `POST /projects` 创建普通项目。
3. `POST /projects/{project_id}/chapters` 创建章节。
4. `POST .../processing` 异步处理章节原文。
5. `POST .../asset-analyses/{asset_type}` 分别分析人物、场景、道具。
6. 管理资产；可上传 URL 到 `reference_image`，也可调用资产生图接口。
7. `POST .../storyboards/analyze` 根据 `processed_content` 制作分镜。
8. 手动新增、修改、移动、合并或拆分分镜。
9. 可选调用 `refine` 和 `storyboard-prompt-generation`。
10. 生成故事板图像和分镜视频，并在生成历史中选择最终版本。
11. 所有异步任务通过 `/task-records` 查询；关闭页面不影响 Celery 后台执行。

章节处理、资产分析、分镜分析、提示词生成和媒体生成的 POST 每次调用都会创建新任务，并可能重新扣费。当前普通项目接口没有客户端幂等键，前端必须防止按钮连点和自动重复提交。

## 4. 公共选项

### 4.1 模型选项

`GET /api/v1/models/options`

当前无需登录。

| 查询参数 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- |
| `vendor` | 否 | 最长 64 | 厂商标识，例如 `apimart` |
| `model_type` | 否 | 最长 64 | `text`、`image`、`video` |

返回数组字段：`id`、`nickname`、`model_id`、`vendor`、`model_type`、`remark` 和统一的 `configuration`。业务接口提交的是数据库 UUID `id`，不是厂商 `model_id`。不同厂商可以有相同 `model_id`，前端不能把它当作全局主键。请求能力、计费和维护状态均从 `configuration` 读取。

`GET /api/v1/models/{ai_model_id}` 返回已启用模型详情，当前也无需登录。

### 4.2 风格选项

- `GET /api/v1/styles`：返回已启用风格的 `id`、`name`、`cover`、`version`。
- `GET /api/v1/styles/{style_id}`：额外返回 `prompt`、`is_enabled`、创建和更新时间。

这两个接口当前无需登录。项目响应中的 `style` 只使用精简结构，不返回风格提示词。

## 5. 核心数据对象

### 5.1 Project

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id`、`user_id`、`style_id` | UUID | 项目、用户和风格 ID；响应中的 `style_id` 类型允许 null |
| `name` | string | 项目名 |
| `cover`、`description` | string | 封面 URL 和描述，数据库中不为 null |
| `generation_ratio` | string/null | 项目默认画面比例 |
| `project_kind` | `standard` \| `agent` | 本文档接口只返回 `standard` |
| `style` | object/null | `id`、`name`、`cover`、`version` |
| `is_enabled` | boolean | 软删除标记 |
| `created_at`、`updated_at` | datetime | 时间 |

### 5.2 ProjectChapter

主要字段：`id`、`project_id`、`user_id`、`ai_model_id`、`title`、`content`、`processing_prompt`、`processed_content`、`process_status`、`sort_order`、`extra`、`is_enabled`、`created_at`、`updated_at`。

`process_status` 的常用值为 `draft`、`pending`、`running`、`success`、`failed`。`extra` 在输出前会脱敏。

### 5.3 项目资产

三个资产共享：`id`、`project_id`、`user_id`、`source_chapter_id`、`name`、`description`、`prompt`、`reference_image`、`source_content`、`extra`、`is_enabled` 和时间字段。

- 人物：`aliases`、`identity`、`gender`、`age`、`appearance`、`personality`、`relationship`、`costume`。
- 场景：`location`、`time_of_day`、`environment`、`atmosphere`。
- 道具：`category`、`appearance`、`function`。

### 5.4 ProjectStoryboard

分镜响应字段：

```text
id, project_id, chapter_id, user_id, ai_model_id,
shot_number, title, source_content,
scene_name, scene_state, shot_size, camera_angle, camera_movement,
screen_execution, characters, props, action, event_goal,
character_action, character_expression, dialogue, sound_effect, atmosphere,
image_prompt, video_prompt, duration_suggestion, production_focus,
negative_prompt, ending_frame, split_reason,
extra, is_enabled, created_at, updated_at
```

`event_goal` 和 `split_reason` 实际存放在 `extra` 中，但作为顶层只读字段响应。`extra` 会脱敏。

## 6. 项目接口

### 6.1 项目列表

`GET /api/v1/projects`

| 参数 | 默认值 | 约束 |
| --- | --- | --- |
| `keyword` | null | 最长 64；匹配名称或描述 |
| `page` | 1 | >= 1 |
| `page_size` | 20 | 1–100 |

只返回当前用户启用中的普通项目，按 `created_at DESC, id DESC` 排序。`data` 为 `items`、`total`、`page`、`page_size`。

### 6.2 创建项目

`POST /api/v1/projects`

```json
{
  "name": "仙侠短剧",
  "cover": "https://oss.example.com/cover.png",
  "description": "项目描述",
  "generation_ratio": "16:9",
  "style_id": "00000000-0000-0000-0000-000000000001"
}
```

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `name` | 是 | 去除首尾空格后 1–128 字符，不允许纯空白 |
| `cover` | 否 | 最长 512；省略或传 null 会保存为空字符串 |
| `description` | 否 | 省略或传 null 会保存为空字符串 |
| `generation_ratio` | 是 | `21:9`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16` |
| `style_id` | 是 | 已启用风格 UUID |

后端固定创建 `project_kind=standard`。

### 6.3 详情、更新、删除

- `GET /api/v1/projects/{project_id}`
- `PATCH /api/v1/projects/{project_id}`
- `DELETE /api/v1/projects/{project_id}`

PATCH 支持 `name`、`cover`、`description`、`generation_ratio`、`style_id`。字段可省略，但只要提交就不能为 null；`name` 也不能是纯空白。`cover`、`description` 可用空字符串清空。

删除项目会：

1. 将项目 `is_enabled` 设为 false。
2. 在同一数据库事务中中止该项目所有 `pending/running` 任务。
3. 同步相关章节、资产或分镜的失败状态，并按任务现有规则退回已预扣积分。

## 7. 章节接口

### 7.1 列表和详情

- `GET /api/v1/projects/{project_id}/chapters?page=1&page_size=20`
- `GET /api/v1/projects/{project_id}/chapters/{chapter_id}`

列表按 `sort_order ASC, created_at ASC, id ASC` 稳定排序，`page_size` 为 1–100。

### 7.2 创建章节

`POST /api/v1/projects/{project_id}/chapters`

```json
{
  "title": "第一章",
  "content": "章节原文",
  "sort_order": 0,
  "processing_prompt": null
}
```

- `title`：必填，去空格后 1–128 字符。
- `content`：必填，不允许纯空白。
- `sort_order`：默认 0，必须 >= 0。
- `processing_prompt`：可选，非 null 时至少 1 字符。

新章节状态为 `draft`。

### 7.3 更新和删除章节

- `PATCH /api/v1/projects/{project_id}/chapters/{chapter_id}`
- `DELETE /api/v1/projects/{project_id}/chapters/{chapter_id}`

PATCH 字段：`title`、`content`、`processed_content`、`sort_order`、`processing_prompt`。

- 提交 `title`、`content` 或 `sort_order` 时不能为 null。
- `processed_content` 可传 null；非空时状态为 `success`，空或 null 时为 `draft`。
- 修改 `content` 或 `processing_prompt` 且未同时提交 `processed_content` 时，后端清空旧处理结果并回到 `draft`。
- `processing_prompt=null` 可清除自定义处理提示词。

删除章节会软删除章节并中止 `extra.chapter_id` 指向该章节的活动项目任务，必要时退回积分。

### 7.4 章节文本处理

`POST /api/v1/projects/{project_id}/chapters/{chapter_id}/processing`

```json
{
  "ai_model_id": "文本模型 UUID",
  "processing_prompt": "可选的系统处理规则",
  "extra": {
    "temperature": 0.3
  }
}
```

- `ai_model_id` 必须是已启用文本模型。
- 章节 `content` 必须非空。
- 传 `processing_prompt` 时，它作为系统规则，原文作为用户输入；不传时使用内置系统提示词。
- `extra` 会经过文本分析参数规范化，不能覆盖后端组织的原文和消息。
- 提交时校验账户余额达到文本模型的 `configuration.billing.base_points`，但不预扣；任务发送到 `story_ai_text` 队列，成功后按厂商成本或 Token usage 结算。

响应：

```json
{
  "chapter": {"process_status": "pending"},
  "task_record_id": "任务 UUID",
  "points_cost": 1,
  "next_poll_seconds": 5
}
```

## 8. 资产分析

`POST /api/v1/projects/{project_id}/chapters/{chapter_id}/asset-analyses/{asset_type}`

`asset_type` 只能为 `character`、`scene`、`prop`。

```json
{
  "ai_model_id": "文本模型 UUID",
  "analysis_prompt": null,
  "extra": {}
}
```

前置条件：章节存在且 `processed_content` 非空，模型为已启用文本模型。

不传 `analysis_prompt` 时分别使用后端人物、场景或道具分析提示词；传入时使用自定义分析规则，但后端仍把章节处理结果作为模型输入。任务成功后，后端在项目级锁下按名称/别名等现有合并规则新建或合并资产，不会简单地把每次结果全部重复插入。

响应字段：`task_record_id`、`asset_type`、`status`、`points_cost`、`next_poll_seconds`。

## 9. 资产管理

### 9.1 通用查询

`GET /api/v1/projects/{project_id}/assets/options`

| 参数 | 必填 | 默认值/约束 |
| --- | --- | --- |
| `asset_type` | 是 | `character`、`scene`、`prop` |
| `keyword` | 否 | 最长 64 |
| `limit` | 否 | 默认 100，1–300 |

响应项包含 `id`、`asset_type`、`name`、`reference_image`、`source_chapter_id`，并按类型补充人物别名/身份、场景地点/时间或道具类别。响应使用 `exclude_none=true`。

每种资产也有单独 options 接口：

- `GET /projects/{project_id}/characters/options`
- `GET /projects/{project_id}/scenes/options`
- `GET /projects/{project_id}/props/options`

查询参数均为 `keyword` 和 `limit`。

### 9.2 人物 CRUD

- `GET /projects/{project_id}/characters`
- `POST /projects/{project_id}/characters`
- `GET /projects/{project_id}/characters/{character_id}`
- `PATCH /projects/{project_id}/characters/{character_id}`
- `DELETE /projects/{project_id}/characters/{character_id}`

```json
{
  "name": "沈砚",
  "aliases": ["阿砚"],
  "identity": "主角",
  "gender": "男",
  "age": "18",
  "appearance": "清瘦坚毅",
  "personality": "克制",
  "relationship": "主角",
  "costume": "深色短衫",
  "description": "人物描述",
  "prompt": "生图描述",
  "reference_image": "https://oss.example.com/character.png",
  "source_chapter_id": "章节 UUID",
  "source_content": "原文证据",
  "extra": {}
}
```

创建时 `name` 必填且不能纯空白，`aliases` 默认 `[]`，`extra` 默认 `{}`。PATCH 字段均可省略；`name`、`aliases`、`extra` 一旦提交就不能为 null，其他 nullable 字段可用 null 清除。

### 9.3 场景 CRUD

- `GET /projects/{project_id}/scenes`
- `POST /projects/{project_id}/scenes`
- `GET /projects/{project_id}/scenes/{scene_id}`
- `PATCH /projects/{project_id}/scenes/{scene_id}`
- `DELETE /projects/{project_id}/scenes/{scene_id}`

场景特有字段：`location`（最长 255）、`time_of_day`（最长 64）、`environment`、`atmosphere`。创建时 `name` 必填；PATCH 的 `name` 和 `extra` 不能为 null。

### 9.4 道具 CRUD

- `GET /projects/{project_id}/props`
- `POST /projects/{project_id}/props`
- `GET /projects/{project_id}/props/{prop_id}`
- `PATCH /projects/{project_id}/props/{prop_id}`
- `DELETE /projects/{project_id}/props/{prop_id}`

道具特有字段：`category`（最长 64）、`appearance`、`function`。创建时 `name` 必填；PATCH 的 `name` 和 `extra` 不能为 null。

三个列表均支持 `keyword`、`page=1`、`page_size=20`，`page_size` 范围 1–100，并按 `created_at DESC, id DESC` 排序。`source_chapter_id` 非空时必须指向同项目、同用户、未删除章节。

删除资产会软删除，并中止 `extra.asset_id` 指向该资产的活动生图任务。

## 10. 资产图像生成与历史

### 10.1 提交生成

- `POST /projects/{project_id}/characters/{character_id}/image-generation`
- `POST /projects/{project_id}/scenes/{scene_id}/image-generation`
- `POST /projects/{project_id}/props/{prop_id}/image-generation`

```json
{
  "ai_model_id": "图像模型 UUID",
  "generation_mode": "general",
  "prompt": "补充要求",
  "extra": {}
}
```

- `ai_model_id` 必须是已启用图像模型。
- `generation_mode` 默认 `general`，最长 64；`card`、`data_card`、`profile-card`、`资料卡` 会规范化为 `profile_card`。
- 生成模式必须存在对应后端常量提示词，否则返回 400。
- 最终提示词由项目风格、模式提示词、资产剧情化字段、用户 `prompt` 和固定主体约束组成。
- 比例默认取项目 `generation_ratio`；厂商参数在 `extra` 中按模型能力校验。
- APIMart 图像模型的普通参数从模型能力 `request_keys` 读取，包括比例、分辨率、生成数量、参考图和模型专属的联网增强/透明背景/组图/反向提示词。`advanced_request_keys` 为可省略高级项；`platform_parameters` 不可编辑。
- APIMart 图像请求固定 `nsfw_check=true`，Seedream 5/4.5 固定 `watermark=false`。

响应字段：`task_record_id`、`asset_type`、`asset_id`、`status`、`points_cost`、`next_poll_seconds`。成功结果写入历史并默认选为 `reference_image`。

### 10.2 资产生成历史

- `GET /projects/{project_id}/assets/{asset_type}/{asset_id}/generation-history?page=1&page_size=20`
- `POST /projects/{project_id}/assets/{asset_type}/{asset_id}/generation-history/{history_id}/select`

选择请求：

```json
{"result_url": "https://oss.example.com/result.png"}
```

`result_url` 可省略；指定时必须属于该历史记录的可选结果 URL。选择成功后更新资产主记录的 `reference_image`。

## 11. 分镜制作与管理

### 11.1 分镜列表

`GET /projects/{project_id}/chapters/{chapter_id}/storyboards?page=1&page_size=50`

`page_size` 为 1–200。按 `shot_number ASC, created_at ASC, id ASC` 稳定排序。

### 11.2 模型分析分镜

`POST /projects/{project_id}/chapters/{chapter_id}/storyboards/analyze`

```json
{
  "ai_model_id": "文本模型 UUID",
  "analysis_prompt": null,
  "extra": {}
}
```

必须先得到非空 `processed_content`。后端把章节处理文本和当前项目人物、场景、道具资产一起提交给文本模型。自定义 `analysis_prompt` 作为系统规则，模型参数不能覆盖后端输入。响应为标准异步分析响应。

### 11.3 手动创建分镜

`POST /projects/{project_id}/chapters/{chapter_id}/storyboards`

创建体支持 5.4 节列出的可编辑分镜字段，另有：

| 字段 | 规则 |
| --- | --- |
| `insert_after_storyboard_id` | 优先插到指定启用分镜后 |
| `shot_number` | >= 1；没有前一字段时作为插入位置 |
| `title` | 默认 `新分镜`，不能纯空白，最长 128 |
| `source_content` | 默认空字符串 |
| `characters`、`props` | 默认 `[]` |

新增时锁定所属章节并连续重排全部启用分镜，避免并发请求产生重复序号。

### 11.4 详情、修改、删除

- `GET /projects/{project_id}/chapters/{chapter_id}/storyboards/{storyboard_id}`
- `PATCH /projects/{project_id}/chapters/{chapter_id}/storyboards/{storyboard_id}`
- `DELETE /projects/{project_id}/chapters/{chapter_id}/storyboards/{storyboard_id}`

PATCH 可编辑全部业务分镜字段。约束：

- `shot_number`、`title`、`source_content`、`characters`、`props`、`extra` 提交时不能为 null。
- `title`、`source_content` 不能纯空白。
- `shot_number` 会被解释为移动目标位置，后端锁定章节后连续重排，不直接制造重复编号。
- 单纯移动不作废已有媒体；修改其他内容会将已选中的图像/视频状态和历史标记为 `invalidated`。
- `event_goal`、`split_reason` 非 null 时合并到 `extra`；传 null 当前不会清除旧值。
- ID、归属、模型、启用和时间字段不可通过 PATCH 修改；部分旧字段会被后端忽略，其他未知字段返回 422。

删除会中止该分镜活动任务、软删除并连续重排剩余分镜。

### 11.5 合并分镜

`POST /projects/{project_id}/chapters/{chapter_id}/storyboards/merge`

```json
{
  "storyboard_ids": ["分镜 UUID 1", "分镜 UUID 2"],
  "title": null,
  "source_content": null,
  "event_goal": null,
  "scene_name": null,
  "characters": null,
  "props": null,
  "action": null,
  "dialogue": null,
  "split_reason": null,
  "extra": null
}
```

至少两个不重复、同章节且启用中的分镜。未提交覆盖字段时，后端按现有内容自动拼接或合并。原分镜软删除，新建合并分镜，并在章节锁内连续重排。响应为该章节当前完整分镜列表。

### 11.6 拆分分镜

`POST /projects/{project_id}/chapters/{chapter_id}/storyboards/{storyboard_id}/split`

```json
{
  "units": [
    {
      "title": "动作开始",
      "source_content": "原文一",
      "event_goal": "目标一",
      "scene_name": "旧宅",
      "characters": ["沈砚"],
      "props": ["木门"],
      "action": "推门",
      "dialogue": "",
      "split_reason": "独立动作",
      "extra": {}
    },
    {
      "title": "进入旧宅",
      "source_content": "原文二",
      "action": "迈入屋内"
    }
  ]
}
```

`units` 至少两项；每项必填非空 `title`、`source_content`、`action`。原分镜软删除，新分镜继承原模型关联并连续重排。响应为完整分镜列表。

```json
{"ai_model_id": "文本模型 UUID", "extra": {}}
```

后端使用当前分镜、相邻分镜连续性和项目资产生成结构化拍摄字段。该接口不接收自定义提示词。任务成功后更新对应分镜。

### 12.2 故事板提示词

`POST /projects/{project_id}/chapters/{chapter_id}/storyboards/{storyboard_id}/storyboard-prompt-generation`

```json
{"ai_model_id": "文本模型 UUID", "extra": {}}
```

后端使用当前分镜和项目资产生成 `image_prompt`、`video_prompt`、建议时长、负面规避和结尾画面等字段。响应与 refine 相同：`task_record_id`、`status`、`points_cost`、`next_poll_seconds`。

## 13. 故事板图像

`POST /projects/{project_id}/chapters/{chapter_id}/storyboards/{storyboard_id}/image-generation`

```json
{
  "ai_model_id": null,
  "aspect_ratio": "16:9",
  "prompt": "补充光线要求",
  "character_ids": ["人物 UUID"],
  "scene_ids": ["场景 UUID"],
  "prop_ids": ["道具 UUID"],
  "uploaded_images": ["https://oss.example.com/ref.png"],
  "extra": {"quality": "2k", "n": 1}
}
```

- `ai_model_id` 可选；不传时查找已启用且 `model_id=gpt-image-2` 的默认模型，传入时可选择其他已启用图像模型。
- `aspect_ratio` 默认 `16:9`，可选 `16:9`、`9:16`、`1:1`、`4:3`、`3:4`、`3:2`、`2:3`、`21:9`。
- 显式资产 ID 优先；不传时按分镜人物、场景和道具名称自动匹配。
- `uploaded_images` 可传 URL 字符串，也兼容带 `url`、`image_url`、`file_url`、`oss_url` 的媒体对象，后端规范化为 URL。
- 最终提示词包含项目风格、分镜内容、资产和用户补充要求，固定要求纯画面，不生成参数标注、镜头编号、时长、字幕、气泡文字或水印。
- `extra` 中的 APIMart 图像参数仍使用上述三组能力契约；普通页面只提交 `request_keys`。透明背景选中后后端自动使用 PNG。

响应字段：`task_record_id`、`storyboard_id`、`aspect_ratio`、`status`、`points_cost`、`next_poll_seconds`。

## 14. 分镜视频

`POST /projects/{project_id}/chapters/{chapter_id}/storyboards/{storyboard_id}/video-generation`

```json
{
  "ai_model_id": "视频模型 UUID",
  "generation_mode": "reference",
  "resolution": "720p",
  "return_last_frame": true,
  "prompt": "补充：镜头节奏更慢",
  "character_ids": ["人物 UUID"],
  "scene_ids": ["场景 UUID"],
  "prop_ids": ["道具 UUID"],
  "uploaded_images": ["https://oss.example.com/ref.png"],
  "first_frame_url": null,
  "last_frame_url": null,
  "extra": {}
}
```

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `ai_model_id` | 是 | 已启用视频模型 UUID |
| `generation_mode` | 否 | `text_to_video`、`reference`、`first_last_frame`、`storyboard`；默认 `reference`，兼容代码中的中英文别名 |
| `resolution` | 否 | `360p`、`480p`、`540p`、`720p`、`768P`、`1080p`、`2K`、`4k`；默认 `720p`，还需通过具体模型能力校验 |
| `return_last_frame` | 否 | 默认 false |
| `prompt` | 否 | 用户补充要求，至少 1 字符 |
| 资产 ID 数组 | 否 | 人物、场景、道具参考图 |
| `uploaded_images` | 否 | 普通参考图 |
| `first_frame_url`、`last_frame_url` | 否 | 最长 2048，首尾帧模式使用 |
| `extra` | 否 | 时长、比例和厂商能力允许的多模态参数 |

模式语义：

- `text_to_video`：不依赖参考媒体。
- `reference`：使用上传图和资产参考图；厂商支持时也可从 `extra` 读取参考视频/音频。
- `first_last_frame`：首帧必需，尾帧可选；后端清除会与首尾帧冲突的普通参考媒体。
- `storyboard`：必须先存在 `video_prompt` 和已生成的故事板图像，只使用该故事板图作为主要视觉参考。

`first_frame_url`、`last_frame_url` 兼容代码中的 camelCase、start/end/tail 等别名，也能从顶层或 `extra.media_items/media/content` 中按 `role=first_frame/last_frame` 提取。新前端应只使用标准字段。

时长优先读取 `extra.duration/duration_seconds/seconds`，否则从 `duration_suggestion` 提取并向上取整；最终还受模型能力约束。积分按规范化后的真实参数预扣，成功后结算。APIMart、Comfly 和火山等厂商差异由模型 `configuration.request.capabilities` 与后端适配器处理，前端不要根据厂商硬编码字段。

APIMart 时长契约：

| 模型 | 可控时长 | 特殊规则 |
| --- | --- | --- |
| `seedance-2.0`、Fast、Mini | 4–15 秒整数 | 默认 5 秒 |
| `seedance-2.5` | 4–30 秒整数 | `-1` 表示厂商自动时长，按 30 秒上限预扣 |
| `MiniMax-H3` | 4–15 秒整数 | 默认 5 秒 |
| `pixverse-v6` | 1–15 秒整数 | 首尾帧模式只能为 5 或 8 秒 |
| `gemini-omni-flash-preview` | 不可显式控制 | 成片范围 3–10 秒，由厂商决定 |

前端从 `GET /models/options?model_type=video` 的 `configuration.request.capabilities.duration` 读取 `min`、`max`、`default`、`controllable`、`special` 和 `mode_values`。只有 `controllable=true` 才显示可编辑时长控件。用户显式时长超出范围时返回 HTTP 400；后端不会静默截断。模型分析得到的 `duration_suggestion` 会按所选 APIMart 模型范围规范化。

APIMart Seedance 2.0 系列或 Seedance 2.5 使用人物参考图时，后端会将本次 `character_ids` 解析出的人物主图作为真人素材审核对象。审核位于视频厂商任务之前：2.0 系列提交 `/v1/seedance2/private-avatar`；2.5 提交 `/v1/seedance2/private-avatar/assets` 并携带 `model=seedance-2.5`。平台轮询审核任务，将通过结果替换为 `asset://...`，然后自动恢复原分镜视频任务。两代模型共用审核后的素材；人物主图审核结果按用户和原图 URL 持久化复用，场景、道具和普通上传图不会被当作人物图。

审核期间平台任务保持 `running`，`extra.provider_stage=private_avatar_review`，`extra.private_avatar.progress_percent` 为审核进度。审核失败时不会提交视频生成；视频任务终止并按现有任务规则退回预扣积分。Seedance 视频请求同时默认提交 `nsfw_check=true`。

Seedance 2.5 的视频请求由后端固定提交 `watermark=false`，项目接口不提供开启水印的参数。

响应字段：`task_record_id`、`storyboard_id`、`generation_mode`、规范化后的 `resolution`、`return_last_frame`、`status`、`points_cost`、`next_poll_seconds`。

## 17. 删除、积分与一致性规则

- 每个模型可配置独立 `configuration.billing.policy`：文本成功后按 Token 实际量结算；图片按数量和分辨率计算；视频按规范化时长、分辨率和图片/视频/音频/多模态参考类型计算。空策略使用后端内置计费规则。
- APIMart 成功响应包含厂商成本时，真实人民币成本为 `credits_cost × 0.7`，真实成本积分为 `ceil(credits_cost × 7)`；文本和视频均按当前平台率（默认 1.2）结算，资产图和分镜图片使用管理端 `configuration.billing.base_points` 或图片策略，不会被厂商实际成本改写用户扣费。
- APIMart 文本响应只含 `usage` 时，按模型 `apimart_credits` 策略中配置的“我们的价格” Credits 费率、Token 阶梯和平台率 1.2 结算，不使用官方价格。
- 实际费用超过预扣时仍会完整补扣并允许结算后的余额为负；用户补足欠额前不能提交新的模型任务，返回业务码 `40003`。
- 任务创建时冻结计费快照，运行中的任务不会因管理端改价而改变最终积分。
- 删除项目：中止整个项目活动任务。
- 删除章节：中止匹配该章节的活动任务。
- 删除资产：中止匹配该资产的活动任务。
- 删除分镜：中止匹配该分镜的活动任务。
- 被中止任务标记为 `failed`、`interrupted=true`，并同步业务失败状态；已预扣积分按现有退款规则处理。
- 章节内分镜新增、移动、删除、合并、拆分都使用数据库行锁并连续重排。
- 生成成功的资产和分镜媒体都会保留历史；切换选择不会删除旧结果。
- 修改分镜内容会把已有媒体历史标记为失效，但不会物理删除历史记录。

## 18. 常见错误

| HTTP | 常见含义 |
| --- | --- |
| 400 | 业务前置条件、生成模式、模型参数、首尾帧或任务 ID 不合法 |
| 401 | 未登录或 Token 无效 |
| 404 | 普通项目、风格、模型、章节、资产、分镜、历史或任务不存在 |
| 409 | 业务状态冲突 |
| 422 | 请求体、路径或查询参数校验失败 |
| 429 | 积分不足、用户活动任务过多或接口限流 |
| 500/502/503 | 本地服务、队列或外部模型服务异常 |

前端不要根据业务码猜测任务是否成功；异步任务以任务记录的 `status`、`stop_polling` 和业务资源刷新结果为准。
