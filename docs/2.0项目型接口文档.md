# 2.0 项目型接口文档

代码核对日期：2026-09-30。范围为当前注册的普通项目（`project_kind=standard`）接口，共 **26 个方法/路径组合**。普通项目只有画布模式；独立 Agent 不属于本文范围。

跨业务的注册登录、上传、模型、任务和积分见[通用接口](0.0通用接口文档.md)；本项目及全站请求字段声明见[全量接口索引](0.1全量接口与请求字段索引.md)。

### 1.1 请求与响应

- 本文路径以默认 API 前缀 `/api/v1` 为基准，下列表格省略此前缀；部署修改 `api_prefix` 时按实际配置替换。
- 所有 `/projects` 接口要求 `Authorization: Bearer <token>`，资源 ID 均使用 UUID 字符串。
- JSON 请求使用 `Content-Type: application/json`；上传使用 `multipart/form-data`，文件字段为 `file`。
- 项目、画布、素材导入/批量、生成提交/选择/批量的请求 Schema 拒绝未声明字段。只读响应字段不能原样回传。
- 下列项目接口成功均为 HTTP 200，业务 `code=0`，包括创建与删除。不要按 message 文字判定成功。
- 返回时间为 ISO 8601 字符串；日期对象按服务器配置时区序列化。使用返回的 revision 做并发判断，不使用时间戳。
- 所有响应经过公共序列化及脱敏处理，不依赖供应商原始报错。空字符串、null 指针、空列表本身不代表生成失败。

统一外层结构（后文的“响应”均指 `data`）：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": "2026-09-30T12:00:00+08:00"
}
```

异常同样返回 code/message/data/timestamp；字段校验失败为 HTTP 422/code 42200，data 是包含 type/loc/msg 的数组。鉴权失败使用 401，账号禁用使用 403。不存在、非本人、已删除或为 Agent 的项目统一返回 HTTP 404/code 40407。

### 1.2 ID 与版本

| 名称 | 用途 |
| --- | --- |
| project_id / canvas_id | 项目与画布 |
| node_id / edge.id | 画布内节点与连线；新增时由客户端提供 UUID |
| media_id | 项目素材 ID，用于节点/图片连线绑定 |
| image_id | 用户级图片审核记录 ID；不是 media_id |
| generation_id | 画布生成记录 ID，用于历史查询、结果选择、生成批量查询 |
| task_record_id | 通用异步任务 ID，用于任务轮询 |
| ai_model_id | 平台模型 UUID；不是供应商的 model_id 字符串 |
| revision | 画布版本，编辑/布局/删除使用 expected_revision |
| content_revision | 节点内容版本，提交生成/选结果使用 expected_content_revision |

## 3. 项目管理合同

### 3.1 创建项目

`POST /projects`，请求 Schema：`ProjectCreateRequest`。

```json
{"name":"自由创作","cover":"","description":""}
```

| 字段 | 必填 | 类型与限制 |
| --- | --- | --- |
| name | 是 | string，输入长度 1–128；再去首尾空白，处理后不能为空 |
| cover | 否 | string 或 null；默认空字符串，最长 512；null 存为空字符串 |
| description | 否 | string 或 null；默认空字符串，null 存为空字符串；Schema 未设置长度上限 |

cover 只作为字符串保存，不触发上传或审核。后端设置 user_id、project_kind=standard、is_enabled=true；客户端不能指定这些字段。创建项目不会自动创建画布、媒体或任务。响应为 ProjectOut，message 为“创建成功”。

### 3.2 项目列表与详情

`GET /projects`：keyword 可选，最长 64，按名称或描述 ILIKE 匹配；page 默认 1/最小 1；page_size 默认 20/范围 1–100。只列出本人启用的普通项目，按 created_at、id 倒序。

响应为 `{items: ProjectOut[], total, page, page_size}`；空页 items=[]。`GET /projects/{project_id}` 返回单个 ProjectOut。

| ProjectOut 字段 | 类型 | 说明 |
| --- | --- | --- |
| id / user_id | UUID string | 项目与所有者 |
| name / cover / description | string | cover、description 可以为空字符串 |
| project_kind | string | 普通项目入口返回 standard；复用 Schema 还定义了 agent |
| is_enabled | boolean | 正常可访问项目为 true；删除响应为 false |
| created_at / updated_at | datetime string | 创建、更新时间 |

响应不包含 style_id、style、generation_ratio；模型及生成参数保存于各节点的 content.generation。

### 3.3 修改项目

`PATCH /projects/{project_id}`，请求 Schema：`ProjectUpdateRequest`。

```json
{"name":"雨夜故事","description":""}
```

只允许 name、cover、description；省略保持原值，显式 null 全部拒绝。字符串限制同创建；cover/description 用 `""` 清空，name 不能清空。允许 `{}`，仍更新 updated_at。无项目级 expected_revision。返回更新后的 ProjectOut，message 为“更新成功”。

### 3.4 删除项目

`DELETE /projects/{project_id}`，无请求体、无版本参数。返回完整 ProjectOut（is_enabled=false），message 为“删除成功”；不是 204，也不是 `{id,deleted}`。

同一事务内软删除项目，将其 pending/running 项目任务标记为 failed，并按现有积分逻辑退还已扣积分。已结束任务不再次按活动任务退款。此操作不物理删除文件，也不保证撤回已提交给供应商的调用。再次通过项目入口访问/删除返回 404。

## 4. 删除行为对照

| 对象 | 请求方式 | 数据变化 | 活动任务/素材 |
| --- | --- | --- | --- |
| 项目 | DELETE 项目 | is_enabled=false；所有嵌套项目接口失去访问权限 | 活动项目任务失败并处理退款；文件不物理清理 |
| 画布 | DELETE 画布，查询 expected_revision | 物理删除画布及其节点、连线；允许删除最后一张 | 不取消任务、不自动退款；项目素材与生成历史保留 |
| 普通节点 | PATCH 画布的 delete_node_ids | 删除节点及相邻连线 | 不取消任务；素材与历史保留 |
| 分组节点 | 同上 | 默认只删分组，直接子节点 parent_id 置 null | 要删除整个分组内容，显式提交所有待删后代 ID |
| 连线 | PATCH 画布的 delete_edge_ids | 删除连线；目标输入变化时增加节点内容版本 | 不删除源节点、素材或历史 |

删除画布后，其详情、编辑、候选、tasks 接口返回 404；仍可通过原 canvas_id/node_id 读取生成历史，或通过 generations/batch 读取保留结果，前提是项目仍存在且可访问。项目删除后这些项目入口也不可访问；通用 task-records 的权限规则独立，不能把项目软删除解释为任务记录已物理删除。

## 5. 前端依赖的共享接口

这些接口不计入上面的 26 项。模型两条路由当前未声明登录依赖；任务与审核两类要求登录。

| 方法 | 路径 | 请求与响应要点 |
| --- | --- | --- |
| GET | `/models/options` | 可选 vendor/model_type（各最长 64）；返回模型选项数组，使用其 id 作为 ai_model_id |
| GET | `/models/{ai_model_id}` | 返回启用模型详情及 configuration；最终参数仍受画布白名单和供应商校验约束 |
| POST | `/task-records/batch` | JSON ids 为 1–50 个 task_record_id；响应 items/total/stop_polling/next_poll_seconds |
| GET | `/task-records/{task_record_id}` | 单条通用任务，含 stop_polling/next_poll_seconds |
| GET | `/uploads/images/{image_id}` | 返回 SeedanceImageOut，读取 review.image_id 对应记录 |
| POST | `/uploads/images/{image_id}/retry-review` | 请求体可省略或为 {}；confirm_resubmit 默认 false，返回 SeedanceImageOut |

通用任务对象包含 id/user_id/ai_model_id/points_transaction_id/business_type/business_id/generation_type/status/title/prompt/result/points_cost/extra/created_at。其 result 是 string 或 null，与画布生成记录的 result 对象不同；不要混用。

| 批量接口 | ID 类型 | 上限 | 缺失 ID | 用途 |
| --- | --- | --- | --- | --- |
| media/batch | media_id | 100 | 返回 missing_ids | 素材及已有审核信息 |
| generations/batch | generation_id | 100 | 返回 missing_ids | 生成状态与结果，不含 snapshot |
| task-records/batch | task_record_id | 50 | 直接省略，无 missing_ids | 通用任务及轮询提示 |

三者均按请求 ID 去重后读取。通用任务查询会检查任务超时；画布 tasks、generations/batch 仅查询本地记录。通用任务 batch/detail 和画布 tasks/generations/batch 返回 Cache-Control: no-store。审核重试不等于生成重试，不能作为轮询方法。

## 6. 能力边界与代码依据

当前没有普通项目章节/分类资产/分镜模式，没有单独素材删除、素材改名、画布复制、服务端撤销、全图自动执行、自动执行上游节点、普通用户单独取消画布任务或通用生成 retry 路由；画布生成使用轮询，没有专用 WebSocket/SSE 推送路由。

文本引用对应数据库迁移 `0068_canvas_text_references`；部署完整功能需升级到该迁移或之后并重启 API、Worker。旧模式数据迁移见[画布唯一模式改造计划](../优化计划/项目画布唯一模式改造计划.md)。本文核对代码，不代表已替部署环境执行迁移。

- 请求/响应：`app/schemas/project.py`、`project_canvas.py`、`project_media.py`、`canvas_generation.py`、`upload.py`。
- 业务：`app/services/projects/` 中 lifecycle、queries、canvases、canvas_inputs、canvas_text_references、canvas_generations、canvas_results、media、image_reviews。
