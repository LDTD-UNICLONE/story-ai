## 编号与维护规则

- 文件命名为“分类编号 + 文档名称.md”，每类从 `.0` 开始，后续文档按 `.1`、`.2` 顺序追加。跨业务共享接口归入 0.x。
- 编号用于文档分类，不是 API 版本；现有 API 前缀仍为 `/api/v1`。正文内部章节编号独立保留。
- 同一业务的接口细则、专题说明和前端接入指南归入同一编号系列。共用模型、上传、任务接口在各业务文档说明调用关系。
- 作品文档包含审核流程背景，管理端接入的统一入口为 5.0。
- 重命名或新增文档时，同步维护本目录、[项目 README](../README.md)及其他引用。
- 开发计划和历史验收记录仍保留在 `优化计划/`，不作为现行接口合同。
- 代码变化时同时核对路由注册、Schema 自定义验证、服务权限/状态机和最终响应序列化；全量索引不能替代业务语义核对。API、审核配置、部署数据库与外部服务可用性仍以运行环境为准。
