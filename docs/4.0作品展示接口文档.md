# 4.0 作品展示接口文档

| 项目 | 内容 |
| --- | --- |
| 文档编号 | 4.0 |
| 代码核对日期 | 2026-09-30 |
| API 前缀 | `/api/v1` |
| 鉴权方式 | `Authorization: Bearer <access_token>` |
| 适用范围 | 作品上传、发布、公开展示、点赞、媒体访问和管理端审核 |

当前作品路由共 12 个方法/路径组合，另有 6 个管理端作品操作（统一归入 5.x）。完整查询参数与请求字段见[全量接口索引](0.1全量接口与请求字段索引.md)，登录与个人信息见[通用接口](0.0通用接口文档.md)。本文依据当前后端路由、Pydantic Schema、权限校验和数据库查询逻辑编写。作品展示前端不得直接使用数据库中保存的 OSS 地址，必须使用接口返回的应用媒体地址。

## 1. 整体流程

```text
登录用户上传图片或视频
  → 获得 upload_id 和私有预览地址
  → 使用一个或多个 upload_id 创建草稿或发布作品
  → public + published 作品进入公开作品列表
  → 匿名用户可查看列表、详情和媒体
  → 登录用户可点赞或取消点赞
  → 管理员可修改权限、通过、下架或删除作品
```

作品媒体使用私有 OSS 对象。应用接口完成权限校验后返回短期签名地址的 HTTP `307` 重定向。

## 2. 权限矩阵

| 能力 | 匿名用户 | 登录用户 | 作品作者 | 管理员 |
| --- | --- | --- | --- | --- |
| 查看公开作品列表 | 允许 | 允许 | 允许 | 允许 |
| 查看 `public + published` 详情和媒体 | 允许 | 允许 | 允许 | 允许 |
| 查看私有作品 | 不允许 | 不允许 | 允许 | 允许 |
| 查看草稿、下架作品 | 不允许 | 不允许 | 允许 | 允许 |
| 上传作品媒体 | 不允许 | 允许 | 允许 | 允许 |
| 创建作品 | 不允许 | 允许 | 允许 | 允许 |
| 修改、删除作品 | 不允许 | 不允许 | 仅自己的作品 | 管理接口允许 |
| 点赞、取消点赞 | 不允许 | 仅公开且已发布作品 | 仅公开且已发布作品 | 仅公开且已发布作品 |
| 审核、下架 | 不允许 | 不允许 | 不允许 | 允许 |

公开读取接口支持可选登录凭证：

- 不提交 `Authorization` 时按匿名用户处理。
- 提交有效 Token 时返回当前用户的 `liked_by_me`。
- 提交无效或过期 Token 不会降级为匿名访问，而是返回 HTTP `401`。

## 3. 状态和可见性

### 3.1 可见性 `visibility`

```text
public  公开
private 私有，仅作者和管理员可查看
```

### 3.2 作品状态 `status`

```text
draft      草稿
published  已发布
hidden     管理员已下架
deleted    已删除
```

作者创建和修改时只能主动选择：

```text
draft | published
```

`hidden` 和 `deleted` 是管理状态：

- 管理员下架后的作品，作者可以继续修改标题、描述、媒体和可见性，但不能自行修改发布状态。
- 管理员调用通过接口后，`hidden` 可恢复为 `published`。
- `deleted` 作品不可恢复或修改。

### 3.3 公开展示条件

公开列表和匿名详情必须同时满足：

```text
is_enabled = true
status = published
visibility = public
```

作品创建时直接选择 `published` 不需要先经过管理员审核。管理端接口承担发布后的内容治理和下架职责。

## 4. 通用响应

### 4.1 JSON 成功响应

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": "2026-08-21T12:00:00+08:00"
}
```

### 4.2 JSON 失败响应

```json
{
  "code": 40045,
  "message": "发布作品至少需要一个媒体文件",
  "data": null,
  "timestamp": "2026-08-21T12:00:00+08:00"
}
```

HTTP 参数校验失败统一返回业务码 `42200`。线上排查时同时保存 HTTP 状态码、业务 `code` 和响应头 `X-Request-ID`。

### 4.3 媒体重定向响应

媒体预览、播放和缩略图接口成功时不返回 JSON，而是返回：

```http
HTTP/1.1 307 Temporary Redirect
Location: https://<private-oss-signed-url>
Cache-Control: private, no-store
Pragma: no-cache
X-Content-Type-Options: nosniff
X-Robots-Tag: noindex, nofollow
```

当前 OSS 签名地址默认有效期为 600 秒，以服务端配置为准。前端不要持久化 `Location`，过期后重新请求应用媒体接口。

## 5. 上传作品媒体

### 5.1 上传图片或视频

```http
POST /api/v1/works/uploads
Authorization: Bearer <access_token>
Content-Type: multipart/form-data
```

表单字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | 图片或视频二进制文件 |

约束：

- 只接受图片和视频，不接受音频或普通文档。
- 文件不能为空。
- 单文件默认最大 100MB，以 `MAX_UPLOAD_SIZE_MB` 配置为准。
- 图片根据真实文件头识别格式，不只依赖扩展名或浏览器 MIME。
- 视频必须通过对应容器文件头校验。
- OSS 对象使用私有 ACL。
- 单用户作品存储默认上限为 2048MB，以配置为准。
- 未绑定作品的上传记录默认保留 24 小时，然后由维护任务清理。

响应：

```json
{
  "upload_id": "11111111-1111-1111-1111-111111111111",
  "media_type": "image",
  "url": "/api/v1/works/uploads/11111111-1111-1111-1111-111111111111/preview",
  "filename": "cover.png",
  "content_type": "image/png",
  "size": 245760,
  "preview_url": "/api/v1/works/uploads/11111111-1111-1111-1111-111111111111/preview"
}
```

`url` 和 `preview_url` 当前保持相同值，用于兼容已有前端。二者都不是原始 OSS 地址。

### 5.2 预览尚未绑定的上传文件

```http
GET /api/v1/works/uploads/{upload_id}/preview
Authorization: Bearer <access_token>
```

只有上传者本人可以访问尚未绑定作品的上传文件（`is_used=false`）。成功返回 HTTP `307` 到短期 OSS 签名地址；不存在、不属于当前用户或已经绑定作品，均返回 `40422`。绑定成功后改用作品响应中的 `media_items[].stream_url`，不再使用上传预览地址。

## 6. 创建作品

```http
POST /api/v1/works
Authorization: Bearer <access_token>
Content-Type: application/json
```

请求：

```json
{
  "title": "雨夜旧宅",
  "description": "AI 漫剧片段",
  "visibility": "public",
  "status": "published",
  "media_items": [
    {
      "upload_id": "11111111-1111-1111-1111-111111111111",
      "sort_order": 0
    },
    {
      "upload_id": "22222222-2222-2222-2222-222222222222",
      "sort_order": 1
    }
  ]
}
```

字段约束：

| 字段 | 必填 | 默认值 | 约束 |
| --- | --- | --- | --- |
| `title` | 是 | 无 | 去除首尾空格后 1～128 字符 |
| `description` | 否 | `null` | 去除首尾空格后最多 2000 字符；纯空格转为 `null` |
| `visibility` | 否 | `public` | `public` 或 `private` |
| `status` | 否 | `published` | `draft` 或 `published` |
| `media_items` | 否 | `[]` | 最多 20 项 |
| `media_items[].upload_id` | 是 | 无 | 必须属于当前用户且尚未绑定其他作品 |
| `media_items[].sort_order` | 否 | `0` | 大于等于 0 |

业务规则：

- `published` 至少需要一个媒体项。
- `draft` 可以没有媒体。
- 同一请求不能重复使用相同 `upload_id`。
- `upload_id` 成功绑定后不能再次用于创建或更新其他作品。
- 媒体按 `sort_order ASC, created_at ASC, id ASC` 排序。列表预览和详情采用同一规则，同序号、同创建时间时由媒体 ID 确定顺序。

成功消息为：

```text
draft     → 保存草稿成功
published → 发布成功
```

## 7. 公开作品展示

### 7.1 公开作品分页列表

```http
GET /api/v1/works?page=1&page_size=20
Authorization: Bearer <access_token>  # 可选
```

查询参数：

| 字段 | 默认值 | 约束 |
| --- | --- | --- |
| `page` | `1` | 大于等于 1 |
| `page_size` | `20` | 1～100 |

排序规则：

```text
like_count DESC
created_at DESC
id DESC
```

列表查询只返回每个作品排序最前的一项媒体作为预览，但 `media_count` 返回作品完整媒体数量。这样可以避免列表页一次加载所有媒体。

首页“创作者为核心，技术服务创意”板块没有独立接口，使用：

```http
GET /api/v1/works?page=1&page_size=10
```

即可得到当前点赞排序前 10 个公开作品。

列表响应：

```json
{
  "items": [
    {

      "user_id": "44444444-4444-4444-4444-444444444444",

      "description": "AI 漫剧片段",
      "visibility": "public",
      "status": "published",
      "like_count": 128,

```

匿名请求的 `liked_by_me` 固定为 `false`。登录请求会批量查询当前用户的点赞状态，不会逐作品查询。

### 7.2 作品详情

```http
GET /api/v1/works/{work_id}
Authorization: Bearer <access_token>  # 可选
```

详情返回全部 `media_items`。

- 匿名用户可读取公开且已发布作品。
- 作者可读取自己的草稿、私有和下架作品。
- 管理员可读取所有作品。
- 普通用户读取他人非公开作品时返回 `40321` 或 `40420`，取决于作品状态。
- 每次成功读取公开且已发布的详情，`view_count` 原子加 1。

## 8. 我的作品

### 8.1 作者作品列表

```http
GET /api/v1/works/mine?visibility=public&status=published&page=1&page_size=20
Authorization: Bearer <access_token>
```

查询参数：

| 字段 | 可选值 |
| --- | --- |
| `visibility` | `public`、`private` |
| `status` | `draft`、`published`、`hidden` |
| `page` | 大于等于 1，默认 1 |
| `page_size` | 1～100，默认 20 |

作者列表按 `created_at DESC, id DESC` 排序，并返回每个作品的全部媒体。

`deleted` 不属于作者列表筛选项。删除后的作品不可恢复，只能由管理员在管理端列表中查询审计记录。

### 8.2 修改作品

```http
PATCH /api/v1/works/{work_id}
Authorization: Bearer <access_token>
Content-Type: application/json
```

所有字段均为可选；只修改请求中实际提交的字段。

```json
{
  "title": "雨夜旧宅·完整版",
  "description": null,
  "visibility": "public",
  "status": "published",
  "media_items": [
    {
      "media_id": "55555555-5555-5555-5555-555555555555",
      "sort_order": 0
    },
    {
      "upload_id": "66666666-6666-6666-6666-666666666666",
      "sort_order": 1
    }
  ]
}
```

`media_items` 更新规则：

- 每一项必须且只能包含 `media_id` 或 `upload_id`。
- `media_id` 表示保留当前作品已有媒体并可更新顺序。
- `upload_id` 表示加入当前用户尚未使用的新上传文件。
- 未出现在数组中的旧媒体会被移除，并进入 OSS 删除队列。
- 不能重复提交相同 `media_id` 或 `upload_id`。
- `media_items=[]` 表示清空全部媒体；目标状态为 `published` 时不允许清空。
- `media_items=null` 或不提交表示不改变媒体集合。

其他规则：

- `title`、`visibility`、`status` 显式提交 `null` 返回 `42200`。
- `description=null` 表示清空描述。
- 发布状态始终要求至少一个媒体文件。
- 作者不能修改其他用户作品，返回 `40320`。
- 管理员已下架的作品不能由作者自行改变状态，返回 HTTP `409`、业务码 `40052`。
- 已删除作品不能修改。
- 编辑、删除、管理员审核和下架会锁定同一个作品行，并重新读取最新状态后校验，防止并发请求使用过期状态绕过下架或恢复已删除作品。
- 媒体集合仍采用全量替换：并发操作按获得锁的顺序执行。如果提交的 `media_id` 已被前一个请求移除，返回 `40049`；前端应刷新作品详情后重新编辑。

### 8.3 删除作品

```http
DELETE /api/v1/works/{work_id}
Authorization: Bearer <access_token>
```

仅作者可调用。删除行为：

```text
status = deleted
is_enabled = false
媒体对象写入 OSS 删除 Outbox
提交数据库事务
尽力立即执行 OSS 删除；失败时由维护任务重试
```

这是业务软删除，但媒体对象会进入物理删除流程，不能恢复。数据库提交后，OSS 清理失败会保留删除任务并记录日志，接口仍返回已提交的成功结果，避免前端误认为删除或媒体替换失败。

## 9. 点赞

### 9.1 点赞作品

```http
POST /api/v1/works/{work_id}/like
Authorization: Bearer <access_token>
```

只有 `public + published + is_enabled` 作品可点赞。

- `(work_id, user_id)` 有数据库唯一约束。
- 重复点赞是幂等操作，不会重复增加 `like_count`，也不会因为唯一约束冲突而返回 500。并发点赞、取消点赞和作品状态变更均先锁定作品，按最新状态校验。
- 首次点赞使用数据库原子更新增加计数。

### 9.2 取消点赞

```http
DELETE /api/v1/works/{work_id}/like
Authorization: Bearer <access_token>
```

同样只允许操作当前公开且已发布作品。

- 未点赞时重复取消是幂等操作。
- 删除到实际点赞记录时才减少 `like_count`。
- `like_count` 大于 0 时才执行减 1，避免出现负数。
- 取消点赞会先执行作品可见性校验，不会通过响应泄露私有作品详情。

点赞和取消点赞均返回完整 `WorkOut`。

## 10. 媒体播放和缩略图

### 10.1 播放或查看原媒体

```http
GET /api/v1/works/{work_id}/media/{media_id}/stream
Authorization: Bearer <access_token>  # 可选
```

权限与作品详情一致。成功返回 HTTP `307` 到 OSS 签名地址。

### 10.2 获取缩略图

```http
GET /api/v1/works/{work_id}/media/{media_id}/thumbnail
Authorization: Bearer <access_token>  # 可选
```

响应同样是 HTTP `307`。列表和详情只有在数据库存在 `thumbnail_object_key` 时才返回非空 `thumbnail_url`。直接调用该路由而媒体没有缩略图时，当前代码回退到原媒体对象。

### 10.3 媒体响应字段

| 字段 | 说明 |
| --- | --- |
| `id` | 作品媒体 ID |
| `media_type` | `image` 或 `video` |
| `url` | 应用内播放地址；当前与 `stream_url` 相同 |
| `filename` | 原始文件名 |
| `content_type` | 后端确认后的 MIME |
| `size` | 字节数 |
| `width`、`height` | 可为空；当前上传链路不保证写入 |
| `duration_seconds` | 可为空；当前上传链路不保证写入 |
| `sort_order` | 排序值 |
| `stream_url` | 应用内媒体地址 |
| `thumbnail_url` | 缩略图地址，无缩略图时为 `null` |
| `created_at` | 创建时间，北京时区序列化 |

## 11. 管理端作品接口

所有管理接口都要求管理员 Token。普通用户调用返回 `40301`。

### 11.1 管理端作品列表

```http
GET /api/v1/admin/works?user_id=&visibility=&status=&page=1&page_size=20
Authorization: Bearer <admin_access_token>
```

查询参数：

| 字段 | 可选值或约束 |
| --- | --- |
| `user_id` | 用户 UUID |
| `visibility` | `public`、`private` |
| `status` | `draft`、`published`、`hidden`、`deleted` |
| `page` | 大于等于 1 |
| `page_size` | 1～100 |

排序规则为 `like_count DESC, created_at DESC, id DESC`。管理端列表返回每个作品的全部媒体。

### 11.2 管理端作品详情

```http
GET /api/v1/admin/works/{work_id}
Authorization: Bearer <admin_access_token>
```

可查看所有状态和权限的作品。管理端查看不会增加 `view_count`。

### 11.3 修改可见性或状态

```http
PATCH /api/v1/admin/works/{work_id}
Authorization: Bearer <admin_access_token>
Content-Type: application/json
```

```json
{
  "visibility": "private",
  "status": "hidden"
}
```

- `visibility` 可为 `public`、`private`。
- `status` 可为 `draft`、`published`、`hidden`、`deleted`。
- 显式提交 `null` 返回 `42200`。
- 目标状态为 `published` 时，作品必须至少有一个媒体文件。
- 设置为 `deleted` 时同步设置 `is_enabled=false`，并把媒体加入 OSS 删除队列。
- 已删除作品不能恢复或修改。

### 11.4 审核通过

```http
POST /api/v1/admin/works/{work_id}/approve
Authorization: Bearer <admin_access_token>
```

将作品状态设为 `published`、`is_enabled=true`。作品必须存在至少一个媒体文件，且不能是已删除作品。

### 11.5 下架作品

```http
POST /api/v1/admin/works/{work_id}/hide
Authorization: Bearer <admin_access_token>
```

将作品状态设为 `hidden`，保留数据库和媒体。已删除作品不能下架。

### 11.6 删除作品

```http
DELETE /api/v1/admin/works/{work_id}
Authorization: Bearer <admin_access_token>
```

将作品设为 `deleted`、`is_enabled=false`，并通过 OSS 删除 Outbox 清理媒体对象。

## 12. 关键错误码

| 业务码 | HTTP | 说明 |
| --- | --- | --- |
| `40007` | 400 | 上传文件为空 |
| `40040` | 400 | 作品上传了非图片、非视频文件 |
| `40041` | 400 | 重复选择同一个上传文件 |
| `40042` | 400 | 作品可见性参数错误 |
| `40043` | 400 | 作品状态参数错误 |
| `40044` | 400 | 上传文件不存在、非当前用户所有或已经被使用 |
| `40045` | 400 | 发布作品没有媒体 |
| `40046` | 400 | 当前作品不可点赞或取消点赞 |
| `40047` | 400 | 已删除作品不能审核通过 |

## 13. 前端推荐对接顺序

### 13.1 发布新作品

1. 为每张图片或视频调用 `POST /works/uploads`。
2. 使用 `preview_url` 展示上传预览。
3. 保存返回的 `upload_id`，按展示顺序设置 `sort_order`。
4. 调用 `POST /works` 创建草稿或直接发布。
5. 创建成功后丢弃本地 `upload_id` 临时状态，使用返回的 `media_items[].stream_url` 展示媒体；后续保留旧媒体时，把响应的 `media_items[].id` 填入更新请求的 `media_id`。

### 13.2 编辑已有作品

1. 调用 `GET /works/{work_id}` 获取完整媒体列表。
2. 保留旧媒体时，将响应中的 `media_items[].id` 作为请求中的 `media_id`。
3. 新媒体先上传，再提交其 `upload_id`。
4. 把最终完整媒体集合提交到 `PATCH /works/{work_id}`；未提交的旧媒体会被删除。

### 13.3 首页展示前 10 个作品

1. 调用 `GET /works?page=1&page_size=10`。
2. 使用列表中唯一的 `media_items[0]` 作为卡片预览。
3. 使用 `media_count` 判断作品是否还有其他媒体。
4. 点击卡片后调用 `GET /works/{work_id}` 获取全部媒体，并使用 `stream_url` 播放。
5. 未登录用户点击点赞时先进入登录流程；不要匿名调用点赞接口。

## 14. 对接注意事项

- 公开列表、详情和媒体允许匿名访问，但点赞必须登录。
- 首页不需要单独的 Top 10 接口，公开列表本身按点赞数排序。
- 列表只携带一个预览媒体，详情才返回全部媒体。
- 不要从数据库字段或历史响应拼接 OSS URL。
- 对 HTTP `307` 应允许客户端跟随重定向。
- 签名 URL 过期后重新请求 `stream_url`，不要把签名 URL写入数据库。
- `url` 与 `stream_url`、上传响应中的 `url` 与 `preview_url` 当前是兼容字段，前端新代码优先使用 `stream_url` 和 `preview_url`。
- 点赞和取消点赞可以安全重试，但并未提供单独的幂等键。
- 作者不能解除管理员下架状态；需要管理员调用审核通过或修改状态接口。
- 作品接口没有轮询要求。
