# 1.0 对话型接口文档

## 1. 文档范围

本文档对应当前后端代码中的普通“对话型”功能，包括文本对话、图像生成和视频生成。本文档不包含 Agent 项目、项目型生成或管理端接口。

- API 前缀：`/api/v1`
- 对话资源前缀：`/api/v1/conversations`
- 时间格式：北京时间 ISO 8601，精确到秒
- 资源 ID：UUID
- 普通接口响应：JSON
- 流式接口响应：`text/event-stream`

## 2. 认证和通用响应

除模型选项接口外，本文档中所有对话接口都需要 Access Token：

```http
Authorization: Bearer <access_token>
Content-Type: application/json
```

JSON 成功响应统一结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": "2026-08-20T17:30:00+08:00"
}
```

JSON 失败响应也使用同一包装结构：

```json
{
  "code": 40405,
  "message": "会话不存在",
  "data": null,
  "timestamp": "2026-08-20T17:30:00+08:00"
}
```

请求参数未通过 Pydantic 校验时，HTTP 状态码为 `422`，业务码为 `42200`，`data` 是经过脱敏的校验错误数组。

## 3. 前端接入主流程

1. 调用模型选项接口，按 `model_type` 获取已启用模型。
2. 使用模型 UUID 创建对话。
3. 发送消息，保存响应中的 `task_record_id` 和 `assistant_message.id`。
4. 文本对话优先连接 SSE；图像和视频任务可通过 SSE 或 JSON 状态接口获取任务进度。
5. 收到 `completed` 或 `failed` 后停止等待，并可重新获取消息列表。

文本消息建议每次都传入前端生成且在重试时保持不变的 `client_message_id`。

## 4. 数据对象

### 4.1 Conversation

| 字段                | 类型                         | 说明                       |
| ------------------- | ---------------------------- | -------------------------- |
| `id`                | UUID                         | 对话 ID                    |
| `user_id`           | UUID                         | 所属用户 ID                |
| `title`             | string                       | 会话标题                   |
| `conversation_type` | `text` \| `image` \| `video` | 对话类型                   |
| `ai_model_id`       | UUID                         | 当前默认模型 ID            |
| `is_enabled`        | boolean                      | 是否启用；删除后为 `false` |
| `created_at`        | datetime                     | 创建时间                   |
| `updated_at`        | datetime                     | 更新时间                   |

### 4.2 ConversationMessage

| 字段                | 类型                                                    | 说明                               |
| ------------------- | ------------------------------------------------------- | ---------------------------------- |
| `id`                | UUID                                                    | 消息 ID                            |
| `conversation_id`   | UUID                                                    | 对话 ID                            |
| `user_id`           | UUID                                                    | 所属用户 ID                        |
| `role`              | string                                                  | `user` 或 `assistant`              |
| `content`           | string                                                  | 用户输入、生成结果或任务状态文本   |
| `message_type`      | string                                                  | `text`、`image` 或 `video`         |
| `extra`             | object                                                  | 媒体、模型参数、任务状态等扩展数据 |
| `ai_model_id`       | UUID                                                    | 本次消息使用的模型 ID              |
| `turn_id`           | UUID \| null                                            | 文本对话轮次 ID                    |
| `sequence_no`       | integer \| null                                         | 文本对话顺序号                     |
| `status`            | `pending` \| `running` \| `success` \| `failed` \| null | 文本消息状态                       |
| `client_message_id` | string \| null                                          | 文本用户消息的幂等键               |
| `created_at`        | datetime                                                | 创建时间                           |

后端会在序列化时脱敏 `content` 和 `extra`，不应依赖厂商原始错误、密钥或内部网络信息出现在响应中。

## 5. 模型选项

### GET `/api/v1/models/options`

获取已启用模型。该接口当前不要求登录。

查询参数：

| 参数         | 必填 | 约束    | 说明                       |
| ------------ | ---- | ------- | -------------------------- |
| `vendor`     | 否   | 最长 64 | 厂商标识，例如 `apimart`   |
| `model_type` | 否   | 最长 64 | `text`、`image` 或 `video` |

示例：

```http
GET /api/v1/models/options?model_type=text
```

`data` 为数组，每项包含 `id`、`nickname`、`model_id`、`vendor`、`model_type`、`remark` 和统一的 `configuration`。创建对话时提交这里的数据库 UUID `id`，不是厂商的 `model_id`。不同厂商可以有相同 `model_id`，前端不能把它当作全局主键。请求能力、计费和维护状态均从 `configuration` 读取。

## 6. 对话管理

### 6.1 对话列表

`GET /api/v1/conversations`

查询参数：

| 参数        | 默认值 | 约束       |
| ----------- | ------ | ---------- |
| `page`      | `1`    | 大于等于 1 |
| `page_size` | `20`   | 1–100      |

仅返回当前用户且 `is_enabled=true` 的对话，按 `created_at DESC, id DESC` 排序。

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "total": 0,
    "page": 1,
    "page_size": 20
  },
  "timestamp": "2026-08-20T17:30:00+08:00"
}
```

### 6.2 创建对话

`POST /api/v1/conversations`

```json
{
  "title": "剧本设定对话",
  "ai_model_id": "00000000-0000-0000-0000-000000000001",
  "conversation_type": "text"
}
```

| 字段                | 必填 | 约束                                                  |
| ------------------- | ---- | ----------------------------------------------------- |
| `title`             | 是   | 原始输入 1–128 字符；保存前去除首尾空白，不允许纯空白 |
| `ai_model_id`       | 是   | 已启用模型 UUID                                       |
| `conversation_type` | 否   | 默认 `text`；只能是 `text`、`image`、`video`          |

模型 `model_type` 必须和 `conversation_type` 完全一致。成功时 `message` 为 `创建成功`，`data` 为 Conversation。

### 6.3 对话详情

`GET /api/v1/conversations/{conversation_id}`

仅能读取当前用户且未删除的对话。

### 6.4 修改标题

`PATCH /api/v1/conversations/{conversation_id}`

```json
{
  "title": "新的对话标题"
}
```

`title` 必填，规则与创建对话一致。成功时 `message` 为 `更新成功`。

### 6.5 删除对话

`DELETE /api/v1/conversations/{conversation_id}`

当前实现是软删除：将 `is_enabled` 设为 `false`。删除前会中断该对话中的 `pending` / `running` 平台任务，同步失败状态，并按现有任务规则退回已预扣积分。

成功时 `message` 为 `删除成功`，`data.is_enabled=false`。删除后再访问该对话返回 `40405`。

## 7. 消息接口

### 7.1 消息列表

`GET /api/v1/conversations/{conversation_id}/messages`

查询参数：

| 参数        | 默认值 | 约束            |
| ----------- | ------ | --------------- |
| `page`      | `1`    | 大于等于 1      |
| `page_size` | `50`   | 1–200           |
| `order`     | `desc` | `asc` 或 `desc` |

文本对话优先按 `sequence_no` 排序，图像和视频按创建时间排序。响应头包含：

```http
Cache-Control: no-store
```

`data` 结构：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "page_size": 50
}
```

查询时后端最多对当页 5 条仍显示为 `pending` / `running` 的助手消息执行任务状态对账。

### 7.2 发送消息

`POST /api/v1/conversations/{conversation_id}/messages`

通用请求：

```json
{
  "content": "请继续完善女主角的设定",
  "ai_model_id": null,
  "client_message_id": "web-1724146200-001",
  "extra": {
    "temperature": 0.7
  }
}
```

| 字段                | 必填         | 约束与语义                                                                     |
| ------------------- | ------------ | ------------------------------------------------------------------------------ |
| `content`           | 是           | 1 至 `CONVERSATION_MESSAGE_MAX_CHARACTERS` 字符，默认上限 100000；不允许纯空白 |
| `ai_model_id`       | 否           | 本次消息覆盖对话默认模型；成功后会同步更新对话的 `ai_model_id`                 |
| `client_message_id` | 文本建议必填 | 1–128 字符，会去除首尾空白；只对文本消息持久化                                 |
| `extra`             | 否           | 厂商参数、媒体 URL 和生成参数                                                  |

为兼容已有调用方，多个媒体参数也允许直接放在请求顶层，后端会将它们合并到 `extra`。1.0 新接入建议统一使用 `extra`。

提交成功响应：

```json
{
  "code": 0,
  "message": "发送成功",
  "data": {
    "user_message": {},
    "assistant_message": {},
    "points_cost": 1,
    "task_record_id": "00000000-0000-0000-0000-000000000010",
    "task_status": "pending"
  },
  "timestamp": "2026-08-20T17:30:00+08:00"
}
```

接口先校验模型最低账户余额，并在同一数据库事务中完成适用的积分预扣、用户消息、助手占位消息和平台任务记录，再向 Celery 入队。文本不预扣；图像和视频仍按各自规则预扣。入队失败时任务和助手消息会转为 `failed`，已发生的预扣会退回。

### 7.3 文本对话幂等和并发规则

- 同一对话内，同一 `client_message_id` 加相同的 `content` 和 `extra` 会返回首次提交的用户消息和助手消息，不会重复扣积分或重复入队。重放请求显式传入 `ai_model_id` 时，该 ID 也必须与首次提交一致；不传时不执行模型 ID 比较。
- 同一 `client_message_id` 但请求内容不同时，返回 HTTP `409`、业务码 `40997`。
- 同一文本对话只允许一个 `pending` / `running` 文本任务。已有活跃任务时返回 HTTP `409`、业务码 `40996`，`data` 包含当前任务和助手消息 ID。
- 文本消息使用数据库行锁与唯一索引保证轮次顺序和幂等性。

### 7.4 删除单条消息

`DELETE /api/v1/conversations/{conversation_id}/messages/{message_id}`

可删除当前用户在该对话中的用户消息或助手消息。如果该消息关联了活跃平台任务，后端先中断任务、同步关联助手消息的失败状态并退回已预扣积分，然后删除指定消息。

成功时 `message` 为 `删除成功`，`data` 为已删除的 ConversationMessage 快照。

### 7.5 失败文本轮次重试

`POST /api/v1/conversations/{conversation_id}/messages/{user_message_id}/retry`

无请求体。

仅支持文本对话，且该用户消息必须属于有 `turn_id` 的新版轮次，对应的最新助手消息状态必须为 `failed`。重试会：

- 保留原用户消息和 `turn_id`；
- 新建一条 `pending` 助手消息；
- 重新校验模型最低账户余额；文本不预扣，其他类型按各自规则计算和预扣积分；
- 新建平台任务并入队。

成功响应与发送消息相同，`message` 为 `重试已提交`。

## 8. 文本多轮和多模态规则

### 8.1 后端管理上下文

前端不能传入 `extra.messages`，否则返回 HTTP `400`、业务码 `40013`。

后端从最新 60 条文本消息中扫描历史，只选取用户和助手都已 `success` 的完整轮次，最终最多取 20 条历史消息，然后附加当前用户消息。正在生成、生成失败和占位文本不会进入后续上下文。

### 8.2 文本＋图片

文本对话支持在 `extra` 中提交图片 URL，建议使用：

```json
{
  "content": "请分析这张图的角色服饰",
  "client_message_id": "web-image-chat-001",
  "extra": {
    "capability": "analyze_image",
    "uploaded_images": [
      {
        "url": "https://example.com/character.png"
      }
    ]
  }
}
```

当历史用户消息带有图片时，后端会在后续完整轮次中继续保留这些图片 URL。

APIMart 普通对话的实际厂商路由如下：

- 纯文本且没有 `tools`：流式 `/v1/chat/completions`；
- 包含图片、`tools` 或 `capability=responses`：流式 `/v1/responses`；
- Responses 在 HTTP `400/404/405/422` 且请求不含图片、视频和工具时，可回退到流式 Chat Completions；
- 已经收到部分流式内容后中断时不会自动切换接口，避免重复或混合结果。

## 9. 平台任务状态

> 进度扩展实现状态：后端已输出顶层 `progress_percent` 并支持 SSE `progress` 事件。当厂商未提供有效进度时，`progress_percent` 为 `null`。

### 9.1 JSON 状态查询

`GET /api/v1/conversations/{conversation_id}/generation-tasks/{task_record_id}`

查询参数：

| 参数           | 默认值 | 约束 | 实际行为                                                   |
| -------------- | ------ | ---- | ---------------------------------------------------------- |
| `wait_seconds` | `0`    | 0–15 | 兼容参数；当前不会阻塞等待，仅参与生成 `next_poll_seconds` |

后端会同时校验任务的 `user_id`、`business_type=conversation` 和 `business_id=conversation_id`。响应头包含 `Cache-Control: no-store`；存在下次轮询建议时还会返回 `X-Next-Poll-Seconds`。

`data` 字段：

| 字段                   | 类型            | 说明                             |
| ---------------------- | --------------- | -------------------------------- |
| `task_record_id`       | UUID            | 平台任务 ID                      |
| `conversation_id`      | UUID            | 对话 ID                          |
| `assistant_message_id` | UUID \| null    | 助手消息 ID                      |
| `status`               | string          | 平台任务状态                     |
| `task_status`          | string          | 与 `status` 相同的兼容字段       |
| `progress_percent`     | integer \| null | 厂商任务真实进度，范围为 0–100   |
| `content`              | string \| null  | 当前对外展示内容                 |
| `result`               | string \| null  | 任务记录结果                     |
| `message`              | string \| null  | 与 `content` 相同的兼容字段      |
| `failed_reason`        | string \| null  | 失败时的脱敏原因                 |
| `extra`                | object          | 任务扩展数据                     |
| `assistant_message`    | object \| null  | 归属校验通过的助手消息           |
| `stop_polling`         | boolean         | `success` / `failed` 时为 `true` |
| `next_poll_seconds`    | integer \| null | 建议下次查询间隔                 |
| `created_at`           | datetime        | 创建时间                         |
| `updated_at`           | datetime        | 更新时间                         |

进度查询响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "task_record_id": "00000000-0000-0000-0000-000000000010",
    "conversation_id": "00000000-0000-0000-0000-000000000001",
    "assistant_message_id": "00000000-0000-0000-0000-000000000020",
    "status": "running",
    "task_status": "running",
    "progress_percent": 46,
    "content": "视频正在生成",
    "result": null,
    "message": "视频正在生成",
    "failed_reason": null,
    "stop_polling": false,
    "next_poll_seconds": 10
  }
}
```

`progress_percent` 语义：

- `null`：尚未取得厂商进度，或者当前厂商不提供百分比；
- `0`–`99`：厂商任务尚未完成；
- `100`：任务成功完成；
- 任务失败时保留最后一次有效进度或返回 `null`，不会伪造成 `100`；
- 进度由厂商提供，更新可能跳跃，不保证匀速变化。

前端必须在 `stop_polling=true` 时停止轮询，并应尊重 `X-Next-Poll-Seconds`、`next_poll_seconds` 和 `Retry-After`。不得从 `extra.provider_response` 或其他厂商内部结构读取进度。

### 9.2 SSE 流式状态

`GET /api/v1/conversations/{conversation_id}/generation-tasks/{task_record_id}/stream`

该接口需要 Bearer Token，且响应不使用 JSON 通用包装。浏览器原生 `EventSource` 无法自定义 `Authorization` 请求头，前端应使用支持 Bearer Token 的 Fetch SSE 客户端或等价库。

响应头：

```http
Content-Type: text/event-stream
Cache-Control: no-cache, no-store
X-Accel-Buffering: no
```

事件类型：

| 事件        | 何时发送                         | 主要字段                                                       |
| ----------- | -------------------------------- | -------------------------------------------------------------- |
| `status`    | 连接后或任务状态变化             | `task_record_id`、`assistant_message_id`、`status`             |
| `progress`  | 厂商任务进度百分比变化           | `task_record_id`、`assistant_message_id`、`status`、`progress_percent` |
| `delta`     | 已发送内容是新内容前缀时         | `delta`、`content`、`status`                                   |
| `snapshot`  | 内容不能在已发送文本后增量追加时 | `content`、`status`                                            |
| `completed` | 任务成功                         | `status=success`、`content`、`stop_streaming=true`；媒体任务的 `progress_percent=100` |
| `failed`    | 任务失败或任务不存在             | `status=failed`、`content` 或 `message`、`stop_streaming=true`；任务存在时包含最后进度 |
| `reconnect` | 单次连接达到服务器最长时间       | `status`、`stop_streaming=false`                               |

心跳是 SSE 注释：

```text
: keep-alive
```

服务器每 0.5 秒检查一次本地任务和助手消息，只有进度百分比发生变化时才发送 `progress`，不会重复推送相同百分比。15 秒无事件时发送心跳。单次连接最长时间为 `max(60, Celery 有效硬超时秒数 + 30)`，收到 `reconnect` 后前端应重新连接同一 URL。

APIMart 文本对话会按缓冲策略持久化流式增量，因此可出现 `delta` / `snapshot`。当前未接入该持久化回调的厂商可能只返回状态事件和最终事件。

SSE 示例：

```text
event: status
data: {"task_record_id":"...","assistant_message_id":"...","status":"running"}

event: progress
data: {"task_record_id":"...","assistant_message_id":"...","status":"running","progress_percent":46}

event: completed
data: {"task_record_id":"...","assistant_message_id":"...","status":"success","progress_percent":100,"content":"https://cdn.example/result.mp4","stop_streaming":true}
```

### 9.3 厂商任务 ID 兼容查询

`GET /api/v1/conversations/{conversation_id}/tasks/{task_id}`

该接口是图像/视频旧版兼容接口，不用于文本对话。它不会直接查询厂商，而是在当前用户、当前对话最新 100 条平台任务中匹配厂商 `task_id`。新前端应优先使用 `generation-tasks/{task_record_id}`。

## 10. 图像生成

创建 `conversation_type=image` 的对话，并选择 `model_type=image` 的已启用模型。

示例：

```json
{
  "content": "16:9 电影感古城夜景，雨后地面反光",
  "extra": {
    "aspect_ratio": "16:9",
    "resolution": "2k",
    "uploaded_images": ["https://example.com/reference.png"]
  }
}
```

具体可用参数由所选模型和其 `capabilities` 决定。APIMart 图像模型会在提交前按模型规格校验尺寸、比例、参考图和其他参数。

APIMart 图像模型能力分为三组：

| 能力字段 | 前端用途 |
| --- | --- |
| `request_keys` | 普通用户生成表单，只显示当前模型真实支持的普通参数 |
| `advanced_request_keys` | 高级设置；普通用户可省略，由厂商使用默认值 |
| `platform_parameters` | 平台固定值，前端只读且不得提交修改 |

普通参数映射：

| 界面控件 | `extra` 字段 | 说明 |
| --- | --- | --- |
| 画面比例 | `size` 或 `aspect_ratio` | 使用能力中的 `ratios` |
| 分辨率 | `resolution` | 使用 `resolutions` |
| 生成数量 | `n` | 不得超过 `max_outputs` |
| 参考图 | `image_urls` | 不得超过 `max_reference_images` |
| 联网增强 | `web_search` | 仅支持该能力的 Gemini 图像模型显示；后端映射为厂商搜索参数 |
| 透明背景 | `background="transparent"` | 仅 Seedream 5；需要恰好一张参考图，后端自动使用 PNG |
| 组图生成 | `sequential_image_generation` | 仅 Seedream 4.5；值为 `auto` 或 `disabled` |
| 反向提示词 | `negative_prompt` | 仅 Qwen Image 3.0 系列 |

`official_fallback`、`optimize_prompt_options`、`layer_decomposition` 只在模型支持时出现于 `advanced_request_keys`，普通用户不传即使用默认值。所有 APIMart 图像请求由后端固定 `nsfw_check=true`；Seedream 5/4.5 同时固定 `watermark=false`。即使客户端提交相反值，也会被后端覆盖。

图像任务可以立即返回结果，也可以先返回厂商 `task_id`。后者由平台记录任务并由对账任务继续获取结果。最终媒体会按平台逻辑持久化到 OSS。

## 11. 视频生成

创建 `conversation_type=video` 的对话，并选择 `model_type=video` 的已启用模型。前端仍使用本文档第 7 节的统一消息发送接口，不直接调用厂商接口。

视频 `extra.generation_mode` 的标准值：

| 值                 | 说明            | 必要条件                                                        |
| ------------------ | --------------- | --------------------------------------------------------------- |
| `text_to_video`    | 文生视频        | 不能传参考图、参考视频、参考音频或首尾帧                        |
| `reference`        | 多模态参考生成  | 通常至少一张参考图或一个参考视频；`seedance-2.5` 允许纯音频参考 |
| `first_last_frame` | 首帧/首尾帧生成 | `first_frame_url` 必填，`last_frame_url` 可选                   |

不传 `generation_mode` 时，后端按输入自动判断：有首尾帧则为 `first_last_frame`，否则有参考媒体则为 `reference`，否则为 `text_to_video`。

文生视频示例：

```json
{
  "content": "镜头缓慢推近，角色走过雨后的古街",
  "extra": {
    "generation_mode": "text_to_video",
    "resolution": "1080p",
    "duration": 8
  }
}
```

参考生成示例：

```json
{
  "content": "保持角色一致，让人物向镜头方向走来",
  "extra": {
    "generation_mode": "reference",
    "uploaded_images": ["https://example.com/character.png"],
    "private_avatar": true,
    "resolution": "720p",
    "duration": 6
  }
}
```

`private_avatar=true` 仅对 APIMart Seedance 2.0 系列和 Seedance 2.5 生效，表示把本次请求的人物参考图纳入真人素材审核。不使用真人参考图时不要传该字段。前端不需要直接调用 APIMart 素材接口，也不需要传入 `asset://` 地址。

后端会结合模型 `capabilities`校验模式、请求字段、媒体数量和分辨率。火山方舟参考视频还会通过媒体探测校验格式、大小、时长、编码、帧率、尺寸、像素数和宽高比。

### 11.1 APIMart 视频模型

管理端把模型创建为 `vendor=apimart`、`model_type=video` 后，后端会按 `model_id` 自动合并厂商能力。当前支持：

| `model_id`                                | 主要输入                       | 时长                     | 分辨率                          | 媒体上限                  |
| ----------------------------------------- | ------------------------------ | ------------------------ | ------------------------------- | ------------------------- |
| `seedance-2.0`                            | 文本、图片、视频、音频、首尾帧 | 4-15 秒                  | `480p`、`720p`、`1080p`、`4k`   | 图片 9、视频 3、音频 3    |
| `seedance-2.0-fast` / `seedance-2.0-mini` | 同上                           | 4-15 秒                  | `480p`、`720p`                  | 图片 9、视频 3、音频 3    |
| `seedance-2.5`                            | 文本或多模态参考，也支持纯音频 | 4-30 秒，编辑模式为 `-1` | `480p`、`720p`、`1080p`         | 图片 30、视频 10、音频 10 |
| `MiniMax-H3`                              | 文本、图片、视频、音频、首尾帧 | 4-15 秒                  | `2K`、`768P`                    | 图片 9、视频 3、音频 3    |
| `pixverse-v6`                             | 文本、参考图、首尾帧、任务延长 | 1-15 秒                  | `360p`、`540p`、`720p`、`1080p` | 参考图最多 7 张           |
| `gemini-omni-flash-preview`               | 文本、图片、单个视频、任务延长 | 成片 3-10 秒，厂商自动决定 | `720p`                          | 图片 16、视频 1           |

所有模型统一提交到 APIMart `/v1/videos/generations`，返回厂商 `task_id` 后由平台任务记录和后台对账继续查询 `/v1/tasks/{task_id}`。前端只保存平台返回的 `task_record_id`。

APIMart 任务状态响应中的 `progress` 为 0–100 的整数。平台会将其标准化为对话任务字段 `progress_percent`，并通过 JSON 状态查询和 SSE `progress` 事件提供给前端。厂商的 `cost`、`credits_cost` 和完整 `provider_response` 不属于普通用户接口契约。

通用字段包括 `duration`、`resolution`、`size`/`aspect_ratio`、`image_urls`、`video_urls` 和 `audio_urls`。模型专属字段由模型选项接口返回的 `configuration.request.capabilities.request_keys` 决定。

前端必须使用 `configuration.request.capabilities.duration` 渲染时长控件：

| 字段 | 说明 |
| --- | --- |
| `min` / `max` | 可生成成片的秒数范围 |
| `default` | 未选择时的默认秒数；字段可能不存在 |
| `controllable` | `true` 才允许提交 `extra.duration` |
| `special` | 区间外的特殊值，例如 Seedance 2.5 的 `-1` |
| `mode_values` | 特定模式离散值，例如 Pixverse 首尾帧只能选择 `5` 或 `8` |
| `provider_managed` | 时长由厂商自动决定，前端只展示范围、不显示可编辑控件 |

示例：

```json
{
  "duration": {
    "min": 4,
    "max": 30,
    "default": 5,
    "special": [-1],
    "controllable": true
  }
}
```

`duration` 必须是整数。超出所选模型范围或不满足模式离散值时，提交消息返回 HTTP 400，不会自动截断后继续生成。Seedance 2.5 的 `duration=-1` 在提交时按 30 秒上限预扣，完成后仍使用现有视频结算逻辑。Gemini Omni 的 `controllable=false`，显式提交任何时长字段返回 400。

其他模型专属字段：

- Seedance 2.0/2.5：`image_with_roles`、`generate_audio`、`return_last_frame`、`seed`、`nsfw_check`、`tools`，并可提交平台字段 `private_avatar=true`；
- Seedance 2.5：另支持 `output_format`、`omni_reference_task_type`；`watermark` 由后端固定为 `false`，不是前端可编辑参数；
- MiniMax-H3：`watermark`、`webhook`、`nsfw_check`；
- Pixverse V6：`img_references`、`extend_from_task_id`、`negative_prompt`、`audio`、`motion_mode`、`generate_multi_clip_switch`；
- Gemini Omni：`extend_from_task_id`。

APIMart 专属校验规则：

- Seedance 2.0 的 `image_urls` 与 `image_with_roles` 互斥，首尾帧不能和参考视频/音频混用，音频不能单独使用；
- Seedance 2.5 的 `edit` / `extend` 需要参考视频并强制 `size=adaptive`，`edit` 强制 `duration=-1`；
- MiniMax-H3 的首尾帧与多模态参考模式互斥，音频不能单独使用；
- Pixverse V6 首尾帧必须成对提交，且该模式 `duration` 只能是 `5` 或 `8`；
- Gemini Omni 不支持提交 `duration`，成片由厂商在 3-10 秒内自动决定；`extend_from_task_id` 与 `video_urls` 互斥；
- 只有 Seedance 系列接受 `asset://` 私有素材引用；其他模型的媒体输入必须是文档允许的 HTTP(S) URL（Gemini 视频另可使用 `data:video/...`）。

Seedance 2.0 系列和 Seedance 2.5 的真人参考图处理流程如下：

1. 任务提交时仍然返回平台 `task_record_id`。
2. 后端先提交人物图：2.0 系列使用 `/v1/seedance2/private-avatar`；2.5 使用 `/v1/seedance2/private-avatar/assets` 并携带 `model=seedance-2.5`。随后通过 `/v1/tasks/{task_id}` 异步查询审核进度。
3. 审核通过后，后端缓存当前用户的 `asset://...` 引用，替换原图 URL 并自动继续原视频任务。
4. 审核失败则原视频任务失败，不会调用视频生成接口。

审核期间任务仍是 `running`，`extra.provider_stage=private_avatar_review`，顶层 `progress_percent` 和 SSE `progress` 事件返回审核进度。审核通过并切换到视频生成后，进度改为视频厂商任务进度。

Seedance 请求的 `nsfw_check` 默认为 `true`。它是每次视频请求的内容检测，与前置的真人素材审核是两个不同阶段。

## 12. 积分和失败处理

- 文本提交时只校验账户余额不低于 `configuration.billing.base_points`，不预扣；成功且厂商返回 Token usage 后，按 `configuration.billing.policy` 的普通输入、缓存输入、输出 Token 单价和倍率一次性结算。空策略使用后端内置 Token 费率。
- 图像任务配置独立策略时，以 `configuration.billing.base_points` 为基础单价，按图片数量、分辨率倍率、模型倍率和平台倍率预扣；空策略直接使用该基础积分。旧字段 `points_per_image` 已废弃，前端不得提交。
- 文本、视频成功后的实际费用高于提交时已扣积分时会完整补扣；结算可以形成负余额，用户补足前不能提交新模型任务。
- 视频提交积分按规范化时长、分辨率和参考类型（无参考、图片、视频、音频或多模态）计算，成功后使用相同策略结算。空策略继续使用原视频费率。
- APIMart 成功响应包含 `credits_cost` 或 `cost` 时，真实人民币成本为 `credits_cost × 0.7`，真实成本积分为 `ceil(credits_cost × 7)`；文本和视频最终扣费使用 `configuration.billing.multipliers.platform`（默认 1.2），图像使用 `configuration.billing.base_points` 或图片策略扣费。缺少 `credits_cost` 时使用 `cost × 10` 推导；文本策略用于 usage 回退结算，视频策略用于参数预扣和成本字段缺失时的回退。
- APIMart 文本响应没有成本字段但包含 `usage` 时，可使用 `configuration.billing.policy.pricing_unit=apimart_credits` 和定价页“我们的价格”的 Credits/百万 Token 费率计算。支持普通输入、缓存读取、缓存写入、输出和输入 Token 阶梯；真实成本积分为 `ceil(Credits 成本 × 7)`，再乘平台率得到用户最终积分。`completion_tokens` 已包含推理 Token，不重复计费。
- 实际费用超过预扣时会完整补扣；余额可因此变为负数，但普通消费不能透支，并且补足欠额前不能提交新的模型任务。业务码为 `40003`。
- 每个任务创建时冻结模型计费快照；任务执行期间管理端改价不会改变该任务最终结算。
- 入队失败、没有厂商任务 ID 的最终生成失败、任务超时或用户中断任务时，已预扣积分按任务规则退回。
- 已提交给厂商并获得厂商任务 ID 的媒体任务，本地 Worker 异常时不直接判定失败，而是转入后台对账。

## 13. 状态机

平台任务主状态：

```text
pending -> running -> success
                   -> failed
pending ----------> failed
```

`success` 和 `failed` 是终态。对于已提交厂商异步任务的图像/视频生成，平台记录可保持 `running`，再由对账任务更新为终态。

## 15. 前端必须遵守的规则

- 只使用 `/models/options` 返回的模型 UUID 创建或切换对话模型。
- 文本发送前生成 `client_message_id`，网络超时后原样重放整个请求，不要生成新幂等键。
- 不提交 `extra.messages`，多轮历史由后端管理。
- 保存平台 `task_record_id`，不要仅保存厂商 `task_id`。
- 进度功能发布后，优先使用 SSE `progress` 事件更新进度条；SSE 断开时再使用 JSON 状态接口恢复。
- `progress_percent=null` 时显示不确定进度的加载状态，不展示伪造百分比。
- 不从 `extra.provider_response.progress` 读取进度，厂商原始响应结构不是稳定的前端契约。
- SSE 收到 `completed` / `failed` 后关闭流；收到 `reconnect` 时重连。
- JSON 查询收到 `stop_polling=true` 后停止轮询。
- 不建立重复 SSE 连接或重复轮询定时器；收到 `429` 时按 `Retry-After` 重试。
- 图像和视频参数应以模型 `capabilities` 为准，不对所有模型显示同一组参数。
