# 1.0 对话型接口文档

核对日期：2026-09-30。覆盖当前 12 个对话路由。范围为普通文本、图像和视频对话，不含项目型、Agent 或管理端接口。共享登录、上传、积分和任务查询见[通用接口](0.0通用接口文档.md)，全部声明字段见[全量接口索引](0.1全量接口与请求字段索引.md)。

一个对话可以交替发送文本、图像和视频生成消息。每条消息的类型由所选模型决定，前端按消息的 `message_type` 展示内容。

## 1. 通用约定

- 对话接口前缀为 `/api/v1/conversations`，均需要 `Authorization: Bearer <access_token>`；模型选项接口不要求登录。
- 创建、修改和发送消息使用 JSON 请求体；资源 ID 使用 UUID。`ai_model_id` 是模型数据库 UUID，不是厂商 `model_id`。
- 时间按北京时间 ISO 8601 返回，精确到秒。
- JSON 接口成功时 HTTP 状态为 `200`，统一包装如下；下文的响应对象均指 `data`。SSE 不使用此包装。

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": "2026-09-14T12:00:00+08:00"
}
```

失败时使用对应 HTTP 状态码，`code` 为业务码，`message` 为错误说明，`data` 可为 `null` 或错误详情。参数校验失败为 HTTP `422`、业务码 `42200`，`data` 为脱敏后的错误数组。响应中的消息内容、任务结果和扩展数据会经过脱敏。

## 2. 模型选项

### GET /api/v1/models/options

返回已启用模型数组，不要求登录。

| 查询参数 | 必填 | 约束 |
| --- | --- | --- |
| `vendor` | 否 | 字符串，最长 64 字符 |
| `model_type` | 否 | 字符串，最长 64 字符；按模型类型筛选时使用 `text`、`image` 或 `video` |

每项包含 `id`、`nickname`、`model_id`、`vendor`、`model_type`、`remark`（可为 `null`）、`configuration`。

- `configuration.request.capabilities`：所选模型的输入能力和参数约束。
- `configuration.billing`：模型计费配置。
- `configuration.operations`：运行/维护状态。

模型规格随具体模型返回，不在本文重复维护型号、分辨率、时长和费率清单。

## 3. 响应对象

### Conversation

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | UUID | 对话 ID |
| `user_id` | UUID | 所属用户 |
| `title` | string | 标题 |
| `conversation_type` | string | 当前默认模型的类型：`text`、`image` 或 `video`，不限制历史消息类型 |
| `ai_model_id` | UUID | 当前默认模型 |
| `is_enabled` | boolean | 软删除后为 `false` |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 更新时间 |

### ConversationMessage

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | UUID | 消息 ID |
| `conversation_id` | UUID | 所属对话 |
| `user_id` | UUID | 所属用户 |
| `role` | string | `user` 或 `assistant` |
| `content` | string | 输入、生成内容或状态/失败说明 |
| `message_type` | string | `text`、`image` 或 `video` |
| `extra` | object | 媒体、参数及任务信息；助手消息可含 `task_record_id`、`task_status` |
| `ai_model_id` | UUID | 该消息使用的模型 |
| `turn_id` | UUID / null | 文本轮次 ID |
| `sequence_no` | integer / null | 三类新消息共用的会话内顺序号；旧消息可为 `null` |
| `status` | string / null | 文本用户消息创建时为 `success`，助手消息使用任务状态；图像/视频消息可为 `null` |
| `client_message_id` | string / null | 文本用户消息的幂等键 |
| `created_at` | datetime | 创建时间 |

### ConversationSendMessageOut

发送消息和失败轮次重试共用此对象。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `user_message` | ConversationMessage | 用户消息 |
| `assistant_message` | ConversationMessage | 助手消息 |
| `points_cost` | integer | 提交金额，文本新提交为 `0`；旧任务幂等重放缺少提交金额快照时，回退为任务记录金额 |
| `task_record_id` | UUID / null | 平台任务 ID，取自助手消息扩展数据 |
| `task_status` | string | 助手消息扩展数据中的任务状态，缺省为 `pending` |

## 4. 对话管理

### GET /api/v1/conversations

| 查询参数 | 默认值 | 约束 |
| --- | --- | --- |
| `page` | `1` | ≥ 1 |
| `page_size` | `20` | 1–100 |

返回 `{items: Conversation[], total, page, page_size}`。只列出当前用户未删除的对话，按 `created_at DESC, id DESC` 排序；不是按最近消息时间排序。

### POST /api/v1/conversations

```json
{
  "title": "剧本讨论",
  "ai_model_id": "00000000-0000-0000-0000-000000000001",
  "conversation_type": "text"
}
```

示例 UUID 需替换为模型选项接口返回的实际 ID。

| 请求字段 | 必填 | 约束 |
| --- | --- | --- |
| `title` | 是 | 原始输入 1–128 字符；去除首尾空白后不得为空 |
| `ai_model_id` | 是 | 初始默认模型 UUID，须已启用且类型与 `conversation_type` 一致 |
| `conversation_type` | 否 | 初始默认类型：`text`、`image`、`video`，默认 `text`；不限制后续消息选择其他类型模型 |

返回 Conversation，`message="创建成功"`。

### GET /api/v1/conversations/{conversation_id}

返回当前用户未删除的 Conversation；不存在、不属于当前用户或已删除时返回 `40405`。

### PATCH /api/v1/conversations/{conversation_id}

请求体仅定义必填字段 `title`，约束与创建时一致。此接口不提供修改类型或模型的字段。

返回 Conversation，`message="更新成功"`。

### DELETE /api/v1/conversations/{conversation_id}

软删除对话，返回 `is_enabled=false` 的 Conversation，`message="删除成功"`。删除前中断该对话的活动平台任务，并按任务规则处理失败状态及预扣退款。

## 5. 消息与文本轮次

### GET /api/v1/conversations/{conversation_id}/messages

| 查询参数 | 默认值 | 约束 |
| --- | --- | --- |
| `page` | `1` | ≥ 1 |
| `page_size` | `50` | 1–200 |
| `order` | `desc` | `asc` 或 `desc` |

返回 `{items: ConversationMessage[], total, page, page_size}`，响应头为 `Cache-Control: no-store`。

全部消息按 `sequence_no`、`created_at`、`id` 同向排序；空顺序号在升序时居前、降序时居后。新消息在会话锁内分配统一顺序号，用户消息在对应助手消息之前；旧消息之间仍按时间和 ID 排序。查询时最多同步当页 5 条活动助手消息关联的任务状态；持续跟踪生成结果使用第 7 节的任务接口。

### POST /api/v1/conversations/{conversation_id}/messages

发送消息及文本轮次重试共用生成请求校验：完成对话输入解析后，在扣费和创建新任务前校验模型维护状态、供应商支持情况及模型参数。文本、图像和视频均使用与项目画布相同的供应商校验入口；对话历史、本轮附件和视频模式解析仍按本接口约定处理。供应商不支持的时长等参数在提交阶段直接返回错误，不必等待异步任务失败。

```json
{
  "content": "请完善女主角的设定",
  "client_message_id": "web-turn-001",
  "extra": {}
}
```

| 请求字段 | 必填 | 约束与行为 |
| --- | --- | --- |
| `content` | 是 | 不得为空或纯空白；最长由 `CONVERSATION_MESSAGE_MAX_CHARACTERS` 配置，代码默认 100000 字符；内容不去除首尾空白 |
| `ai_model_id` | 否 | 可为 `null`；省略或为 `null` 时使用对话默认模型。可指定任意已启用的 `text/image/video` 模型，本条消息按该模型类型执行；新提交成功后更新默认模型及 `conversation_type` |
| `client_message_id` | 否 | 可为 `null`；非空值原始长度 1–128，去除首尾空白后不得为空；只在文本用户消息上保存 |
| `extra` | 否 | object / null；模型参数和媒体输入，省略或 `null` 按空对象处理 |
| `image_references` | 否 | 默认 `[]`，最多 32 项；选中的参考图片，可在正文用 `@` 引用，仅用于图像和视频生成，见第 6 节 |

返回 ConversationSendMessageOut，`message="发送成功"`。首次提交创建用户消息、助手占位消息及平台任务；占位内容为 `任务已提交，正在生成中`。

在同一个 `conversation_id` 下，分别指定文本模型、图像模型、视频模型的 `ai_model_id` 即可切换类型，不需要新建对话或传入 `message_type`。用户和助手消息的 `message_type`、任务的 `generation_type` 均使用本次模型类型。后续省略模型时沿用最近成功提交的默认模型；文本幂等重放和轮次重试不切换默认模型。

会话创建、修改及发送消息的外层 Schema 当前没有设置 `extra=forbid`，普通未声明字段可能被忽略；不要依赖这种行为。`image_references` 中每项则明确拒绝未声明字段。

媒体兼容字段如 `uploaded_images`、`image_urls`、`duration`、`resolution`、`generation_mode` 可以出现在顶层，后端会移入 `extra`；同名字段以 `extra` 中的值优先。新请求统一放在 `extra` 中，非兼容字段并不会自动成为模型参数。

消息、适用的预扣、任务和待投递记录一起提交。提交后队列暂时不可用时保留待处理任务并自动补偿投递，**不会仅因入队失败立即将任务置为失败或退款**。保存平台 `task_record_id`，通过任务接口继续观察状态。

新消息和文本重试共用原子提交流程：任务额度校验、业务记录写入或待投递记录登记失败时，本次预扣和新增记录一起回滚；失败的新消息提交也不会切换会话默认模型。文本重试失败不会删除原有用户消息或历史助手消息。只有数据库提交成功后才尝试发送到队列。

文本幂等及并发规则：

- 同一对话内重放同一 `client_message_id` 时，`content` 和合并后的 `extra` 必须与原请求一致；显式指定非空 `ai_model_id` 时，还需与原用户消息的模型相同。
- 匹配时返回原用户消息及该轮次**最新的助手消息**，不创建新任务或再次预扣；显式执行过轮次重试后，重放可返回重试的助手消息。
- 内容或模型不匹配返回 `40997`；缺少对应助手消息返回 `40998`。
- 同一对话只允许一个 `pending` / `running` 的文本任务，冲突返回 `40996`，`data` 含 `active_task_record_id` 和 `assistant_message_id`。图片、视频任务可与文本任务同时进行，仍受用户任务额度限制。
- `client_message_id` 只用于文本幂等；已用于文本消息的键不能复用于其他内容或模型。默认模型切换后，原文本请求仍可按原键重放。
- 网络重发保留原幂等键和请求；开始新一轮使用新键。生成失败后再次发送同一个键只会重放，主动重新生成使用下面的 `/retry`。

### DELETE /api/v1/conversations/{conversation_id}/messages/{message_id}

删除指定用户或助手消息，返回删除前的 ConversationMessage，`message="删除成功"`。如关联活动任务，先中断任务并按规则处理退款及助手状态；不会同时删除该轮次的另一条消息。

### POST /api/v1/conversations/{conversation_id}/messages/{user_message_id}/retry

无请求体。仅适用于文本用户消息，必须有 `turn_id`，且该轮次最新助手消息为 `failed`；对话不能已有活动文本任务。默认模型已切换为图像或视频时仍可重试先前的文本消息。

保留原用户消息及轮次，使用**原用户消息的模型、内容和参数**，仅从原用户消息之前的历史中选取完整成功轮次构造上下文（保留旧版历史兼容规则），不加入之后的对话；重新检查余额，新建助手消息和平台任务，文本提交金额为 `0`。旧失败回答保留，新助手消息的 `extra.retry_of_assistant_message_id` 指向它。

返回 ConversationSendMessageOut，`message="重试已提交"`。

## 6. 文本、图像和视频输入

### 文本上下文与图片

客户端不得提交 `extra.messages`，否则返回 `40013`。默认聊天模式由后端构造历史；APIMart 文本还会在非默认能力模式下构造历史，其他厂商的非 `chat` 模式直接使用其参数，不自动附加历史。

构造历史时扫描最近 60 条文本消息，筛选成功的完整新轮次及符合条件的旧版消息，最多保留 20 条历史消息，再附加本次输入。失败、活动或缺少成功回答的新轮次不参与历史。

图像、视频生成消息及结果不会自动加入文本上下文。需要文本模型分析先前生成的图片，或将图片用于视频生成时，客户端需在本次 `extra` 中显式传入对应媒体地址，并选择支持该输入的模型。

使用支持图片输入的文本模型时，可发送：

```json
{
  "content": "分析图片中的角色服饰",
  "client_message_id": "web-vision-001",
  "extra": {
    "uploaded_images": ["https://example.com/character.png"]
  }
}
```

图片会作为文本多模态内容传入模型；进入有效历史的用户消息会保留图片输入。接收媒体字段不等于所选模型支持该媒体类型，不把文本消息中的视频 URL 视作通用视频理解能力。

### 图像生成

选择图像模型，仍调用统一的消息发送接口。例如所选模型支持对应比例和参考图时：

```json
{
  "content": "电影感古城夜景",
  "extra": {
    "aspect_ratio": "16:9",
    "uploaded_images": ["https://example.com/reference.png"]
  }
}
```

按 `configuration.request.capabilities` 中存在的字段使用参数：`request_keys`、`advanced_request_keys`、`ratios`、`resolutions`、`max_outputs`、`max_reference_images`。APIMart 图像能力中的 `platform_parameters` 由后端固定，客户端修改会被覆盖。各厂商字段并不保证相同，未提供的能力不能据此假定支持。

### 视频生成

选择视频模型。`extra.generation_mode` 的标准值：

| 值 | 输入要求 |
| --- | --- |
| `text_to_video` | 不得同时传参考媒体或首尾帧 |
| `reference` | 至少参考图片或参考视频；只有能力 `allow_audio_only=true` 时允许纯音频参考 |
| `first_last_frame` | 必须有 `first_frame_url`；`last_frame_url` 是否必填由模型进一步约束 |

省略模式时，有首尾帧先选 `first_last_frame`，否则有参考媒体选 `reference`，均无则为 `text_to_video`。

`media`、`media_items`、`content` 中的 `video_url`、`audio_url` 类型对象可以省略 `role`，此时按对应参考媒体处理；显式选择文生视频时，这些输入也会被拒绝。首尾帧模式提取首尾帧后，会清除普通参考图片、视频、音频及其别名和上传容器，只保留首尾帧输入。

参考模式校验具体媒体类型和数量。`media_limits` 中对应类型为 `0` 表示不支持；不能仅根据 `multimodal_reference` 等模式名称认定模型支持任意参考媒体。不支持的输入在创建生成任务和预扣积分之前返回 `40012`。

参考生成示例（须选择支持参考图的模型）：

```json
{
  "content": "保持人物一致，让角色向镜头走来",
  "extra": {
    "generation_mode": "reference",
    "uploaded_images": ["https://example.com/character.png"]
  }
}
```

参考视频、音频可使用 `extra.video_urls`、`extra.audio_urls`；首尾帧使用 `extra.first_frame_url`、`extra.last_frame_url`。按模型能力提供时长、分辨率、比例、媒体数量及专属参数，后端仍会校验模式和输入；部分参考视频还会进行文件探测。

APIMart 视频的 `capabilities.duration` 提供 `min`、`max`，并可能提供 `default`、`special`、`mode_values`、`controllable`、`provider_managed`。`controllable=false` 时不要提交时长；可控时长须满足整数、范围及模式规则。不可把一组时长/分辨率选项用于所有视频模型。

### 选择图片与 @ 引用

使用顶层 `image_references` 提交当前输入框中本轮上传成功的图片，每项包含名称，以及 `url` 或 `image_id` 二选一。Seedance 上传审核见本节后续说明。该数组是本轮附件快照，不是历史消息图片集合；`@` 候选只能来自这个输入框的可用附件。附件会全部作为参考传入模型；需要精确指代某张图片时，在正文使用 `@` 标签，用途由用户自行描述。后端不对图片进行人物/场景分类，也不追加用途指令。例如：

```json
{
  "ai_model_id": "00000000-0000-0000-0000-000000000002",
  "content": "将@{图片1}中的衣服换成@{图片2}中的衣服，其他内容保持不变。",
  "image_references": [
    {"name": "图片1", "url": "https://example.com/1.png"},
    {"name": "图片2", "url": "https://example.com/2.png"}
  ],
  "extra": {}
}
```

`ai_model_id` 替换为支持参考图的图像或视频模型 UUID。视频省略 `generation_mode` 时会根据参考图片选择 `reference`，也可显式指定该模式。

| 字段 | 约束 |
| --- | --- |
| `name` | 必填，1–64 字符；字母、数字、中文等单词字符、下划线或连字符；同一请求内唯一，不含 `@`、空格或花括号 |
| `url` | 与 `image_id` 二选一；HTTP/HTTPS 图片地址，最长 2048 |
| `image_id` | 与 `url` 二选一；`seedance_reference` 上传返回的本平台图片 UUID，必须属于当前用户、已审核通过且供应商配置匹配 |

- 不再接受 `role` 字段；旧客户端需删除该字段，否则返回 `422`。历史消息中已有的引用数据只用于展示，不得复制到下一轮附件或候选列表。
- 前端显示 `@图片1` 标签，编辑器统一序列化为 `@{图片1}`，可直接连接中文。后端兼容用空格或标点分隔的 `@图片1`；新编辑器不要混用两种序列化方式。
- 不要求每张图片都在正文使用 `@`：上述请求的正文也可为“参考这些图片生成一张海报”，或者只引用其中一张图片。未在正文引用的图片仍会传给模型。
- 图像/视频请求中，正文有 `@{名称}` 但本轮没有附件，返回 `40016`，不会从历史消息补图。提交非空 `image_references` 时，正文中的图片标签必须有对应项，否则同样返回 `40016`。无编辑器标签时保留原有媒体参数用法；普通文本、邮箱以及旧接口的模型原生标签不自动绑定历史图片。
- 后端按数组顺序分配 `@图片1`、`@图片2` 等编号；相同 URL 共用同一编号。正文中的重复引用使用同一张图。数组最多 32 项，实际图片数量仍须符合所选模型限制。
- 使用此字段时，其他参考图片、通用媒体容器和首尾帧输入不要同时提交；图片统一放在该数组。视频须使用参考生成模式，不支持将这些引用用于文生视频或首尾帧模式。
- 原用户消息 `content` 保留原标签，引用数组保存在 `user_message.extra.image_references`，供历史回显；以 ID 引用时，历史快照还包含预览 `url`，但发送请求仍须二选一。任务 `prompt` 是编译后的提示词；Seedance 的任务图片地址转换为已审核的 `asset://`，其他模型使用原图 URL。
- `image_references` 只在请求顶层提交，不能放入请求的 `extra`。省略时沿用原有参考图参数；文本消息不能使用非空的 `image_references`。

前端对接：

1. 用户在当前输入框上传图片，成功后显示缩略图并加入本轮附件；Seedance 附件还须等待 `can_reference=true`。不提供历史消息图片入口，不读取历史消息构建候选列表。
2. 输入 `@` 时只列出本轮上传成功且未移除的附件；为空时提示“请先上传图片”。选中后插入绑定附件的标签，不发起上传或从历史中取图。名称可自动分配为“图片1”“图片2”，无需填写分类。
3. 名称与图片 URL 的绑定在本轮编辑中保持稳定；删除其他图片时不要让已有标签指向另一张图。移除图片时同步移除其正文引用；仅删除正文标签则可保留图片作为普通参考。
4. 发送完整正文及本轮附件快照。提交成功后清空该草稿的正文、附件和候选；提交失败时保留草稿供修改。切换会话时隔离草稿，上传迟到的回调不得写入其他会话或下一轮。
5. 历史回显读取 `user_message.extra.image_references`，只用于消息展示，不填入编辑器。模型仍由 `ai_model_id` 选择，引用能力和图片数量须符合所选模型限制。

后端按图片顺序转换标签并提供参考图，不执行抠图或背景合成；具体引用效果取决于所选模型。

当前接口校验标签与本次请求附件的绑定，不保存输入框草稿或上传批次，无法仅凭 URL 判断图片是否刚在浏览器上传。因此候选来源和草稿清理必须由前端按本节约定实现；这不构成服务端对上传来源的强校验。

### Seedance 上传时审核

本节说明对话型 `vendor=apimart` 的 Seedance 视频审核用法。共享审核服务也用于项目画布，但项目上传和审核登记入口不同。支持：`seedance-2.0`、`seedance-2.0-fast`、`seedance-2.0-mini`、`seedance-2.0-face`、`seedance-2.0-fast-face`、`seedance-2-0`、`seedance-2.5`。

1. `POST /api/v1/uploads/file` 使用 multipart：`file` 为图片，`purpose=seedance_reference`。真人、动漫、风景统一审核；省略用途则保持普通上传。
2. 响应保留原上传字段，增加 `image_id`、`review_status`、`can_reference`、`can_retry`、`retry_requires_confirmation`、`review_error`、`reused`。HTTP 200 表示已接收，不代表审核通过。
3. `GET /api/v1/uploads/images/{image_id}` 查询本平台状态。只有 `can_reference=true` 的本轮附件才能进入 `@` 候选；不可用附件须等待或移除后再生成。
4. 通过后提交 `image_references: [{"name":"图片1","image_id":"上传返回的 UUID"}]`。后端在创建消息、任务或扣费前校验归属与审核结果。
5. `POST /api/v1/uploads/images/{image_id}/retry-review` 手动重试，默认无请求体。`failed` 重新提交；`uncertain` 有上游任务 ID 时恢复查询，无任务 ID 时须先提示可能重复入库，由用户确认后传 `{"confirm_resubmit": true}`，否则返回 HTTP 409。前端依 `can_retry` 显示按钮，依 `retry_requires_confirmation` 决定是否二次确认。等待中或已通过不会重复提交；重试复用原图片 ID 和文件。
6. **Seedance 系列内部切换不重新审核。** 前端保留当前草稿附件的 `image_id`、URL、`review_status`、`can_reference` 和引用标签，发送时只更换 `ai_model_id` 与模型参数。不得因模型切换重置审核状态、重新上传或调用 `retry-review`；如需刷新状态，只调用上述 GET 接口。审核中的附件继续查询原 ID，已通过的附件保持可用；图片数量等模型限制单独校验。

状态：`pending` 等待投递，`processing` 提交或审核中，`ready` 可用，`failed` 明确失败，`uncertain` 提交/查询结果无法确认。更换服务地址或密钥后旧记录不可引用，应重新上传；以 `can_reference` 为准。上述接口均需登录，查询其他用户图片返回 404。

相同用户、文件内容及供应商配置复用文件与审核记录，改名不影响去重。审核不创建视频任务或扣视频积分；视频消息校验通过后按原规则计费。

Seedance 对话中的普通图片 URL、旧图片别名和首尾帧 URL 也必须对应当前用户的已审核记录；直接传入供应商 `asset://` 不能绕过校验。无图的文生视频不要求审核。首尾帧继续提交上传响应中的原图 URL，后端校验后转换素材地址。

其他供应商及图像生成不会自动应用这个视频审核门禁。项目画布和 Agent 分镜视频均已接入同一共享审核服务，审核结果可在同一用户、相同素材服务凭证范围内复用。各业务的图片绑定请求仍不同，分别见[项目素材与审核](2.1项目画布接口.md#5-项目素材与-seedance-图片审核)和 [Agent 图片审核与复用](3.0Agent接口文档.md#531-seedance-图片审核与复用)。

## 7. 平台任务状态与 SSE

### GET /api/v1/conversations/{conversation_id}/generation-tasks/{task_record_id}

所有对话类型均可使用。校验当前对话、用户和平台任务归属，并同步终态助手消息。

| 查询参数 | 默认值 | 约束与实际行为 |
| --- | --- | --- |
| `wait_seconds` | `0` | 0–15；保留兼容参数，不阻塞等待，也不再改变轮询提示 |

响应头含 `Cache-Control: no-store`；`next_poll_seconds` 非零时同时给出 `X-Next-Poll-Seconds`。

### ConversationGenerationTaskOut

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `task_record_id` | UUID | 平台任务 ID |
| `conversation_id` | UUID | 对话 ID |
| `assistant_message_id` | UUID / null | 任务扩展数据中的助手消息 ID |
| `status` | string | `pending`、`running`、`success` 或 `failed` |
| `task_status` | string | 与 `status` 相同的兼容字段 |
| `phase` | string | queued / generating / persisting / completed / failed；转存中仍为 running |
| `content` | string / null | 展示内容；终态有结果时优先使用任务结果，失败时加 `任务执行失败：` 前缀；否则使用助手内容或任务结果 |
| `result` | string / null | 任务记录结果 |
| `message` | string / null | 与 `content` 相同的兼容字段 |
| `failed_reason` | string / null | 失败时为任务结果，否则为 `null` |
| `extra` | object | 脱敏后的任务扩展数据 |
| `assistant_message` | ConversationMessage / null | 通过消息归属校验的助手对象，可能已被删除 |
| `stop_polling` | boolean | `success` / `failed` 时为 `true` |
| `next_poll_seconds` | integer / null | pending/running 为 `1`，success/failed 为 `null`；不使用历史扩展值 |
| `progress_percent` | integer / null | 媒体进度，范围 0–100；文本为 `null` |
| `created_at` | datetime | 任务创建时间 |
| `updated_at` | datetime | 任务更新时间 |

图像/视频成功时进度为 `100`，其他状态返回最后有效进度或 `null`。**是否结束以状态和 `stop_polling` 为准，不能仅凭百分比判断。** 不从厂商原始响应中推算进度。

### GET /api/v1/conversations/{conversation_id}/generation-tasks/{task_record_id}/stream

同样需要 Bearer Token，成功响应类型为 `text/event-stream`，响应头含 `Cache-Control: no-cache, no-store`、`X-Accel-Buffering: no`。建立流前的鉴权或归属错误仍是普通 JSON 错误响应。

| 事件 | 触发条件 | `data` 字段 |
| --- | --- | --- |
| `status` | 首次读取或状态改变 | `task_record_id`、`assistant_message_id`、`status` |
| `progress` | 首个有效进度或进度改变 | 上述三个字段及 `progress_percent` |
| `snapshot` | 已标记开始输出，且内容无法接在已发送内容之后；包括首次非空内容 | `content`、`status` |
| `delta` | 已标记开始输出，且已发送的非空内容是新内容的前缀 | `delta`、完整 `content`、`status` |
| `completed` | 任务成功 | `task_record_id`、`assistant_message_id`、`status`、`progress_percent`、`content`、`stop_streaming=true` |
| `failed` | 任务失败 | 与 `completed` 相同的字段；任务记录已不存在时仅含 `status`、`message`、`stop_streaming=true` |
| `reconnect` | 达到单连接时限 | `status`、`stop_streaming=false` |
| `fallback` | Redis 不可用、连接超额或租约失效 | `next_poll_seconds=2`，关闭流，前端改用 JSON/batch 查询 |

格式示例：

```text
event: snapshot
data: {"content":"角色设定","status":"running"}

event: delta
data: {"delta":"如下","content":"角色设定如下","status":"running"}
```

- 服务器订阅任务变化通知后读取状态，默认每 15 秒补读快照并发送必要心跳，取消原 0.5 秒数据库轮询。流式文本是否有中间内容，取决于执行链路是否持久化流式输出；始终处理最终事件。
- status 事件增加 phase；厂商已完成但成品仍在转存时为 persisting，前端显示“生成完成，正在保存”，不提前视为成功。
- 同一用户默认最多 3 个任务 SSE 连接，跨通用多任务流和对话流合计；媒体任务较多时优先使用通用 `/task-records/stream` 合并订阅。
- `snapshot` 替换内容，`delta` 可追加增量或使用完整 `content` 替换。每次重连从空的已发送内容开始，不提供事件 ID 续传。
- 单连接时限为 `max(60, Celery 有效硬超时秒数 + 30)`；收到 `reconnect` 后重连同一 URL。断开连接不会取消任务，可使用 JSON 状态接口恢复查询。
- 收到 `completed` / `failed` 后停止流；JSON 查询收到 `stop_polling=true` 后停止轮询。读取不到进度时显示不确定状态，不伪造百分比。

## 8. 厂商任务 ID 兼容查询

### GET /api/v1/conversations/{conversation_id}/tasks/{task_id}

查询图像/视频任务，不受当前默认模型类型限制。此处 `task_id` 是厂商任务 ID 字符串；后端在当前用户、当前对话的最新 100 条图像/视频平台任务中查找匹配项，不直接请求厂商。

返回 `ConversationTaskStatusOut`：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `task_id` | string | 厂商任务 ID |
| `task_status` | string / null | 匹配的平台任务状态 |
| `content` | string | 任务结果，无结果时为空字符串 |
| `extra` | object | 含 `task_id`、`task_status`、`task_record_id`、`record_extra` |

新接入使用第 7 节的平台任务 ID 接口，避免依赖厂商 ID 和最近 100 条的匹配范围。

## 9. 积分与失败处理

- 文本和视频有模型最低余额检查；图像仍需满足其提交金额及账户余额规则。发送响应中的 `points_cost` 只表示提交金额：文本不预扣，图像/视频按配置计算预扣。
- 任务保存计费快照，最终金额由后端结合该快照及厂商成本/用量或模型策略结算。最终费用可能与提交金额不同，补扣可形成负余额；余额不足时不能继续提交新任务。
- 生成结果成功但结算异常时，保留成功结果，后台补偿结算；不要因结算未完成重复生成。
- 最终失败、超时或用户中断时，按任务状态和已有退款标记退回适用的预扣。已有厂商任务 ID 的媒体任务遇到本地异常时，可保持 `running` 并由后台回收结果；队列暂时异常本身不等于生成失败。
- 图像、视频取得厂商任务 ID 后，生成 Worker 立即交给与项目画布共用的后台回收流程，负责查询、结果转存、消息更新及最终结算。客户端继续按原平台任务 ID 查询或订阅 SSE；无需新建消息。回收投递、查询或转存暂时失败会等待后续恢复，不据此重复生成或退款；厂商明确失败才按失败流程处理。文本流式输出不变。
- 图像、视频取得厂商任务 ID 后首次回收立即入队，未完成时默认每 2 秒查询厂商；JSON 状态接口的活动任务轮询提示统一为 1 秒，终态为 null。前端每次按最新 next_poll_seconds 调整查询，收到终态立即更新消息并停止轮询。总耗时还包含排队与成品转存，不能直接等同于厂商生成耗时。
- 活动状态为 `pending`、`running`，终态为 `success`、`failed`。执行重试可从 `running` 回到 `pending`；客户端等待终态，而不是把暂时状态变化视为新任务。

## 10. 常见错误

| HTTP | 业务码 | 含义 |
| --- | --- | --- |
| 400 | `40003` | 余额不足 |
| 400 | `40005` | 当前供应商或模型类型尚不支持 |
| 400 | `40012` | 模型或媒体参数不符合要求 |
| 400 | `40013` | 客户端提交了文本 `extra.messages` |
| 400 | `40014` | 非文本用户消息请求轮次重试 |
| 400 | `40016` | 图片引用未绑定、类型不支持、输入冲突，或审核/来源校验未通过 |
| 400 | `40021` | Comfly 视频参数不符合模型要求，例如不支持的时长或模式 |
| 401 | `401` | 缺少 Bearer 凭证 |
| 401 | `40102`、`40103` | 凭证无效/失效，或用户不存在 |
| 403 | `40302` | 账号禁用 |
| 404 | `40404` | 模型不存在、未启用或类型不匹配 |
| 404 | `40405`、`40406`、`40407` | 对话、任务或消息不存在/归属不符 |
| 409 | `40995` | 目标轮次不是失败状态 |
| 409 | `40996` | 文本对话已有活动任务 |
| 409 | `40997` | 幂等键被用于不同请求 |
| 409 | `40998` | 幂等用户消息缺少对应助手消息 |

| 503 | `50300` | 限流服务不可用 |
| 503 | `50301` | 模型维护中 |

表中不是所有厂商/执行错误的穷举。提交阶段错误由 HTTP 响应返回；异步执行失败通过平台任务状态和脱敏内容读取。
