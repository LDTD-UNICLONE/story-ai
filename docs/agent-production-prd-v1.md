## 1. 文档目的

本文档定义“整剧生产 Agent”第一版的产品目标、用户流程、功能范围、状态规则、验收标准和开发边界，用于产品评审、技术设计和开发任务拆分。

整剧生产 Agent 不重新实现章节处理、资产分析、分镜、图片和视频生成能力，而是统一编排现有能力，解决整部剧本跨剧集生产时的规划、确认、批处理、成本控制和失败恢复问题。

## 2. 前提与假设

V1 基于以下假设设计：

1. 用户从 Agent 板块上传文件或输入文本，不选择项目中心已有项目。
2. 一个剧本创建成功后自动形成一个 Agent 项目；`AgentProduction.id` 是公开的 Agent 项目 ID。
3. 实现层可创建内部 `Project` 承载章节和资产，但该项目不出现在项目中心，也不能由项目中心项目转换而来。
4. 一个 `ProjectChapter` 对应一集，而不是原始小说章节。
5. 用户输入是可直接改编的完整剧本，V1 单次最多处理 10 万中文字符。
6. V1 默认采用“监督模式”，不会在没有确认的情况下直接生成全集视频。
7. V1 的生产终点是镜头视频批量生成；配音、字幕、时间线合成不在本期强制范围内。
8. 当前仓库以 API 后端为主，本文定义信息架构和交互行为，不定义具体颜色、字号和组件视觉规范。

如果后续产品目标变为“百万字网文直接改编”，需要单独增加网文改编、剧情重写和分卷管理能力，不应直接扩大本期范围。

## 3. 背景与现状

当前系统已经支持以下单点能力：

1. 创建项目和章节。
2. 处理章节文本。
3. 从单个章节提取角色、场景和道具。
4. 生成资产参考图。
5. 从单个章节生成和细化分镜。
6. 生成分镜故事板图片和视频。
7. 使用 `UserTaskRecord` 记录异步任务、积分和厂商执行状态。

当前流程的主要限制：

- 用户需要逐集、逐阶段手动提交任务。
- 资产分析以章节为入口，容易跨集重复创建人物和场景。
- 缺少整剧级生产状态，无法快速判断全集完成到哪一步。
- 缺少人工确认关卡，前序错误可能扩大为大量图片和视频返工。
- 修改角色、场景或分镜后，系统无法精确计算受影响的下游内容。
- 单个任务失败可以查询，但缺少面向整剧的异常聚合和批量恢复。

## 4. 产品定义

### 4.1 产品定位

用户上传整部剧本并设置生产参数后，Agent 自动完成：

1. 全剧解析。
2. 剧集规划。
3. 故事圣经和资产提取。
4. 分镜批量生成。
5. 关键帧批量生成。
6. 视频批量生成。
7. 异常聚合和局部返工。

Agent 负责计划、调用、等待、检查和恢复；现有业务服务负责执行具体生成任务。

### 4.2 产品原则

- 先理解全剧，再生产单集。
- 先确认低成本内容，再提交高成本媒体任务。
- 批量生产，但允许逐集、逐镜修改。
- 修改只影响有依赖关系的内容。
- 失败任务可恢复，不阻断无依赖的其他任务。
- 所有积分消耗可预估、可追踪、可停止。

## 5. 产品目标

### 5.1 核心目标

用户完成以下三个动作，即可推进一部漫剧的主要生产流程：

1. 上传整部剧本并设置画幅、风格等生成参数。
2. 确认剧集规划、故事圣经和核心资产。
3. 处理 Agent 汇总的异常内容。

### 5.2 V1 成功标准

- 10 万字符以内剧本能够进入异步解析流程。
- Agent 能生成可编辑、可确认的剧集规划。
- 确认后能批量创建正式项目章节。
- 跨集同名、别名角色不会被无条件重复创建。
- 用户可以按阶段、按剧集查看进度。
- 支持暂停、恢复、取消后续调度和失败项人工处理。
- 批量图片、视频生成前展示预计积分消耗。
- 单个镜头失败不会导致整剧任务直接失败。
- 服务或 Worker 重启后可从数据库状态继续运行。

### 5.3 非目标

V1 不包含：

- 全自动发布到第三方内容平台。
- 专业非线性剪辑器。
- 多人实时协作和审批流。
- 多个自治 Agent 互相自由对话。
- 自动训练角色 LoRA 或自定义视频模型。
- 百万字网文的一次性全自动改编。
- 无人工确认直接生成并发布整部成片。

## 6. 目标用户与核心场景

### 6.1 目标用户

- AI 漫剧个人创作者。
- 漫剧工作室的导演、编剧或制片人。
- 需要持续批量生产竖屏剧情内容的小团队。

### 6.2 核心用户故事

1. 作为创作者，我希望上传整部剧本后看到合理的拆集方案，而不是手动创建几十个章节。
2. 作为导演，我希望在批量生成视频前确认角色、场景和画风。
3. 作为制片人，我希望看到全剧进度、实际积分和异常任务。
4. 作为编辑，我希望修改某个角色或镜头时，只重做受影响内容。
5. 作为创作者，我希望任务中断后能够继续，而不是重新生成全部内容。

## 7. 核心术语

| 术语 | 定义 |
| --- | --- |
| 整剧生产 | 从完整剧本输入到全部镜头视频生成的生产过程 |
| 生产实例 | 用户针对一个项目发起的一次 Agent 执行记录 |
| 生产阶段 | 全剧解析、拆集、资产、分镜、关键帧、视频等阶段 |
| 确认关卡 | Agent 必须暂停并等待用户确认的位置 |
| 故事圣经 | 全剧统一的世界观、时间线、人物关系和视觉约束 |
| 核心资产 | 主要角色、常驻场景和重要道具 |
| 叶子任务 | 现有 `UserTaskRecord` 表示的单次模型生成任务 |
| 失效 | 上游内容变化后，下游结果不再代表最新版本，但不立即删除 |
| 异常处理箱 | 汇总失败、阻塞、失效和需要人工处理内容的入口 |

## 8. 端到端用户流程

| 阶段 | Agent 行为 | 用户行为 | 完成条件 |
| --- | --- | --- | --- |
| 创建 | 保存剧本和生成配置 | 上传或输入剧本、选择画幅和风格 | 生产实例创建成功 |
| 全剧解析 | 分块解析、合并结果、生成全剧摘要 | 查看预计集数、镜头数和成本 | 用户确认生产方案 |
| 剧集规划 | 生成每集钩子、冲突、高潮、结尾和原文范围 | 编辑、合并、拆分、排序剧集 | 用户确认剧集规划 |
| 故事圣经 | 提取人物关系、时间线、场景和道具 | 修正别名、设定和资产状态 | 用户确认故事圣经 |
| 核心资产 | 创建资产并生成核心参考图 | 选择或上传主资产参考图 | 核心资产全部锁定 |
| 分镜 | 按集生成结构化分镜并执行质检 | 按集确认或修改 | 目标剧集分镜确认 |
| 批量生产 | 分批提交全部剧集的分镜、关键帧和视频 | 查看进度、暂停或调整 | 所有可执行任务结束 |
| 异常收尾 | 汇总失败和失效任务 | 显式重新生成、跳过或人工替换 | 无未处理的阻塞异常 |

## 9. 功能需求

### 9.1 P0：创建整剧生产实例

#### FR-001 上传整部剧本

支持：

- 粘贴纯文本。
- 上传 `.txt` 文件。
- 上传文件后显示文件名、字符数和内容预览。
- 计算内容哈希，防止用户重复提交同一版本。

限制：

- 空内容禁止提交。
- V1 最大 10 万中文字符，限制应由配置项控制。
- 文件解析失败时不创建生产实例。

#### FR-002 生产参数

剧本文件上传或文本粘贴成功后，先创建未配置的 Agent 草稿并展示正文预览；用户随后在独立
配置步骤中选定整体风格、目标画幅和运行模式。三项配置未保存前不得启动剧本分析。

必填参数：

- 目标画幅。
- 项目风格。
- 每集目标时长。

可选参数：

- 目标集数，未填写时由 Agent 推荐。
- 单镜默认时长。
- 视频分辨率。
- 是否生成音频。

用户不选择文本和图片模型：文本固定使用后台启用的 `model_id=gpt-5.5`，图像固定使用
`model_id=gpt-image-2`。新建界面不提供任何模型选择，也不提供自动重试、试播集或整剧
积分预算配置。

启动时解析文本和图像固定模型并保存执行快照。视频模型延迟到全剧生产进入 `videos` 阶段
后由用户选择并锁定；选择前不得提交视频生成任务。后续修改模型配置不应改变已经固化的
生产实例模型快照。固定模型未配置时允许保存草稿，但禁止启动。

#### FR-003 运行模式

V1 提供：

- `supervised`：关键阶段必须确认，默认模式。
- `automatic`：在账户余额和强制关卡约束内自动运行。

即使选择自动模式，核心资产仍应设置为强制确认点。

### 9.2 P0：全剧解析与剧集规划

#### FR-010 分层解析

Agent 应按以下顺序处理长文本：

1. 将原文切分为带顺序和字符范围的文本块。
2. 每个文本块分别提取事件、角色、场景、道具和时间信息。
3. 合并角色别名和重复实体。
4. 生成全局故事线和时间线。
5. 根据生产配置生成剧集规划。

禁止把完整长文本无条件作为一次模型请求提交。

#### FR-011 生产方案预览

全剧解析完成后展示：

- 全剧摘要。
- 故事类型和目标观众。
- 建议集数。
- 每集预计时长。
- 预计镜头总数。
- 角色、场景、道具数量。
- 文本、图片和视频预计积分。
- 当前用户积分余额。

用户确认前不得创建正式剧集或提交媒体生成任务。

#### FR-012 剧集规划

每集必须包含：

- 集数和标题。
- 开场钩子。
- 本集叙事目标。
- 主要冲突。
- 高潮。
- 结尾悬念。
- 对应原文字符范围或文本块 ID。
- 预计时长。
- 预计镜头数。
- 出场角色和场景。

用户可以：

- 编辑标题和内容。
- 合并相邻剧集。
- 拆分单集。
- 调整顺序。
- 修改目标时长。
- 要求 Agent 重新规划指定范围。

#### FR-013 剧集物化

用户确认剧集规划后，系统批量创建 `ProjectChapter`：

- `title` 保存剧集标题。
- `content` 保存对应原始剧本片段。
- `processed_content` 保存确认后的漫剧化剧本。
- `sort_order` 保存集数顺序。
- `extra` 保存剧集钩子、高潮、结尾、来源范围和版本信息。

重复点击确认接口不得重复创建章节。

### 9.3 P0：故事圣经和资产

#### FR-020 故事圣经

内容至少包括：

- 世界观和时代背景。
- 主线和支线。
- 全剧时间线。
- 角色关系。
- 角色基础设定。
- 场景基础设定。
- 重要道具。
- 全局视觉风格。
- 连续性和禁止冲突项。

故事圣经必须版本化。已开始下游生产的版本不得直接覆盖。

#### FR-021 实体合并

Agent 对候选实体进行合并时，应保留：

- 标准名称。
- 别名列表。
- 来源剧集。
- 合并置信度。
- 合并原因。

低置信度合并必须进入人工确认列表。

#### FR-022 角色状态

同一角色允许拥有多个状态，例如：

- 年龄阶段。
- 服装。
- 身份伪装。
- 受伤或战斗状态。

V1 可先在资产 `extra` 中保存状态集合，但分镜必须引用稳定的角色 ID 和状态 ID，不能只保存角色名称。

#### FR-023 核心资产锁定

主要角色和常驻场景至少选定一张参考图后才能开始全部剧集批量生产。

锁定后修改核心资产时，系统必须展示受影响的分镜、关键帧和视频数量。

### 9.4 P0：分镜批量生成

#### FR-030 分镜结构

每个分镜至少包含：

- 镜号。
- 来源剧本。
- 场景 ID 和场景状态。
- 角色 ID、角色状态 ID。
- 道具 ID。
- 景别、机位和运镜。
- 动作、表情和对白。
- 音效和氛围。
- 建议时长。
- 图片提示词。
- 视频提示词。
- 上一镜和下一镜的连续性信息。

#### FR-031 分镜质检

Agent 自动检查：

- 镜头总时长与目标集时长的偏差。
- 对白长度是否超过镜头可承载范围。
- 是否引用不存在或未锁定的资产。
- 角色服装、时间和场景是否无理由跳变。
- 是否遗漏关键事件。
- 是否存在重复或无法执行的镜头。

质检结果分为：

- `error`：阻止批量生产。
- `warning`：允许用户确认后继续。
- `info`：仅作为优化建议。

#### FR-032 分镜确认

支持按集确认，不强制一次确认全集。修改已确认分镜时，应使对应镜头下游结果失效。

### 9.5 P0：全部剧集批量生成

#### FR-040 批量任务计划

核心资产确认后直接进入全部剧集批量生产，不设置试播范围或试播确认关卡。

每次提交媒体任务前展示：

- 任务数量。
- 涉及剧集和镜头范围。
- 预计积分。
- 预计批次数量。

用户确认后，Agent 根据当前用户队列限制逐批创建 `UserTaskRecord`，不得绕过现有并发限制。
每个叶子任务只自动提交一次；失败后直接进入异常处理箱，不自动重试。

#### FR-041 暂停和恢复

暂停时：

- 不再创建新的叶子任务。
- 已提交给模型厂商的任务继续轮询并保存结果。
- 当前阶段状态变为 `paused`。

恢复时：

- 重新核对已完成和执行中的任务。
- 只为缺失且仍有效的内容创建新任务。

#### FR-042 取消

取消整剧生产时：

- 停止创建新任务。
- 不删除已经生成的章节、资产、分镜或媒体。
- 不默认取消已提交到外部厂商的任务。
- 生产实例状态变为 `cancelled`。

### 9.6 P0：异常处理箱

#### FR-050 异常分类

至少支持：

- 模型审核不通过。
- 厂商执行失败。
- 厂商长时间无结果。
- 账户积分余额不足。
- 上游资产缺失。
- 上游版本已变化。
- 提示词或参数不合法。
- 人工暂停。

#### FR-051 异常操作

用户可以：

- 单个显式重新生成。
- 修改提示词后重新生成。
- 上传外部参考素材。
- 跳过非关键镜头。

显式重新生成是新的付费任务，不得覆盖旧结果，仍使用现有生成历史保存候选版本。

### 9.7 P1：自然语言指令

用户可以向 Agent 提交项目级修改，例如：

- “第 1 集冲突提前出现。”
- “把第 8 至 12 集合并成 3 集。”
- “重新生成审核失败的视频。”
- “暂停视频生成，先完成全部分镜。”

Agent 执行前必须展示：

- 计划修改内容。
- 受影响剧集和镜头。
- 将失效的已有结果。
- 预计新增积分。

V1.0 可以不实现自由文本指令，但数据结构和事件日志应预留指令来源。

## 10. 页面与信息架构

### 10.1 入口

整剧 Agent 是独立板块。用户从上传文件或输入剧本文本开始，不选择项目中心已有项目。

入口状态：

- 尚未创建：展示“上传剧本文件”和“输入剧本文本”。
- 已创建：进入最近一次生产实例。
- 已完成或取消：允许新建另一个 Agent 项目。

### 10.2 生产驾驶舱

页面必须包含：

- 整体进度。
- 当前阶段和下一确认点。
- 已消耗积分和预计剩余积分。
- 运行、暂停、恢复状态。
- 剧集与生产阶段矩阵。
- 异常数量和入口。
- 最近 Agent 事件。

剧集矩阵列：

| 列 | 状态示例 |
| --- | --- |
| 剧本 | 草稿、待确认、已确认、已失效 |
| 资产 | 缺失、提取中、待确认、已完成 |
| 分镜 | 未开始、生成中、待确认、已完成、已失效 |
| 关键帧 | 未开始、排队中、部分完成、已完成、失败 |
| 视频 | 未开始、排队中、部分完成、已完成、失败 |

### 10.3 右侧详情面板

选择剧集、资产或镜头时展示：

- 当前内容。
- 当前版本。
- 依赖来源。
- 生成历史。
- 质检问题。
- 可执行操作。

### 10.4 确认弹窗

确认弹窗必须展示“确认后会发生什么”，包括：

- 将创建或更新的数据数量。
- 将启动的任务数量。
- 预计积分消耗。
- 可能失效的下游内容。
- 是否可以撤销。

## 11. 状态模型

### 11.1 生产实例状态

| 状态 | 含义 | 可进入状态 |
| --- | --- | --- |
| `draft` | 已保存配置，尚未运行 | `planning`, `cancelled` |
| `planning` | 正在解析或规划 | `waiting_approval`, `partially_failed`, `paused`, `cancelled` |
| `waiting_approval` | 等待用户确认 | `running`, `cancelled` |
| `running` | 正在调度生产任务 | `waiting_approval`, `paused`, `partially_failed`, `completed`, `cancelled` |
| `paused` | 用户主动暂停 | `running`, `cancelled` |
| `partially_failed` | 存在异常，但仍保留已完成结果 | `running`, `paused`, `cancelled`, `completed` |
| `completed` | 所有目标内容完成或被显式跳过 | 终态 |
| `cancelled` | 停止后续调度 | 终态 |

### 11.2 阶段状态

`not_started`、`queued`、`running`、`waiting_approval`、`completed`、`failed`、`invalidated`、`skipped`。

### 11.3 叶子任务状态

继续复用 `UserTaskRecord` 的 `pending`、`running`、`success`、`failed`。整剧暂停、等待确认和上游失效不加入叶子任务状态。

## 12. 依赖和失效规则

| 修改对象 | 自动失效对象 | 不受影响对象 |
| --- | --- | --- |
| 原始剧本版本 | 未确认的剧集规划及其下游 | 已归档旧生产实例 |
| 剧集内容 | 当前集分镜、关键帧、视频 | 其他无共享资产的剧集 |
| 角色基础形象 | 引用该角色状态的关键帧和视频 | 不含该角色的镜头 |
| 角色音色 | 该角色配音和成片 | 图片和无音频视频 |
| 场景参考图 | 引用该场景的关键帧和视频 | 其他场景镜头 |
| 分镜图片提示词 | 当前镜头关键帧和依赖关键帧的视频 | 其他镜头 |
| 分镜视频提示词 | 当前镜头视频 | 当前镜头关键帧 |
| 视频模型参数 | 尚未锁定的视频任务 | 已确认并锁定的结果 |

失效规则：

1. 失效只改变“当前有效版本”，不物理删除旧数据。
2. Agent 不自动重新消费积分，必须进入新的执行计划。
3. 批量重建前必须展示影响范围和预计积分。
4. 共享资产变化时，根据稳定资产 ID 查找引用，禁止按名称模糊匹配。

## 13. 成本和任务调度规则

### 13.1 成本预估

成本预估按阶段保存快照：

- 文本阶段：按预计模型调用次数和模型积分计算。
- 图片阶段：按待生成资产和关键帧数量计算。
- 视频阶段：按镜头数量、模型、分辨率和时长计算。

预估值只作为提示，最终以现有积分结算逻辑为准。

### 13.2 按量扣费

- 不设置 `max_points` 或其他整剧预算。
- 每个真实模型任务提交时复用现有积分结算，执行多少扣多少。
- 账户余额不足时不创建该叶子任务，并将对应项目标记为失败或异常。
- 系统不会因为失败自动重新提交或再次扣费。

### 13.3 并发控制

- Agent 必须复用现有用户任务上限。
- Agent 每次只填充允许的任务窗口，不一次创建全集所有媒体任务。
- 文本、图片、视频分别按现有 Celery 队列路由。
- 同一镜头同一版本同一生成类型必须使用稳定幂等键。

## 19. 验收标准

### AC-001 完整主流程

给定一个 5 万字剧本和已配置的系统默认模型：

1. 创建整剧生产实例。
2. 完成全剧解析并进入等待确认。
3. 用户将推荐 20 集调整为 18 集。
4. 确认后只创建 18 个正式章节。
5. Agent 提取并合并角色别名。
6. 用户确认核心角色和场景。
7. Agent 完成指定剧集分镜。
8. 核心资产锁定后直接启动全部剧集批量生产。

### AC-002 幂等确认

同一剧集规划确认请求重复提交两次，项目章节数量不增加。

### AC-003 暂停恢复

批量视频生成中暂停：

- 已提交任务继续回收结果。
- 不再创建新视频任务。
- 恢复后只提交尚未生成且仍有效的视频任务。

### AC-004 局部失败

一个镜头视频审核失败：

- 该镜头进入异常处理箱。
- 系统不自动重试或再次扣费。
- 其他无依赖镜头继续执行。
- 整剧状态为 `partially_failed`，不是直接 `failed`。

### AC-005 依赖失效

用户修改主角参考图：

- 系统展示受影响的镜头数量。
- 只把引用该角色状态的关键帧和视频标记失效。
- 旧生成历史仍可查看。
- 未经用户确认不自动重新扣费生成。

### AC-006 积分不足

提交叶子任务时账户积分不足：

- 不创建该叶子任务。
- 对应项目进入失败或异常状态。
- 异常原因显示为账户积分不足。
- 充值后由用户显式选择是否重新生成。

### AC-007 重启恢复

API 或 Worker 重启后：

- 能从数据库读取当前生产阶段。
- 不重复提交成功或仍在厂商执行的任务。
- 可以继续未完成的有效任务。

3. C1-C6：全剧分层解析 Worker。

5. E1-E5：故事圣经和跨集资产合并。

8. H1-H5：仅保留旧生产实例兼容，不进入新 Agent 流程。
9. I1-I5：全部剧集分阶段补位、暂停恢复和异常收敛。
10. J1-J5：生产矩阵、异常分类、显式重新生成、人工处理和审计。
11. K1-K5：自动续调度、任务精确归属和生产化恢复。

## 23. 风险与处理

| 风险 | 影响 | V1 处理 |
| --- | --- | --- |
| 长剧本解析结果前后矛盾 | 拆集质量下降 | 分块提取后增加全局合并阶段 |
| 角色别名错误合并 | 多集角色混乱 | 保存置信度，低置信度人工确认 |
| 一次生成任务过多 | 队列拥塞 | 分批填充现有队列窗口 |
| 状态只存在 Celery 内存 | 重启后无法恢复 | 数据库状态作为唯一事实来源 |
| 上游修改导致重复扣费 | 用户投诉 | 先失效和预估，确认后再重建 |
| Agent 绕开现有服务直接调用模型 | 积分和幂等失效 | 编排层只调用已有服务入口 |

## 24. 待确认决策

进入 V1.0 开发前只需确认以下产品决策：

1. `ProjectChapter` 是否正式定义为“剧集”。
2. V1 剧本字符上限是否采用 10 万字。
3. 剧集规划确认后，是否允许删除并重新物化尚未生产的全部章节。
4. 故事圣经是否必须由用户确认后才能写入正式资产库。
5. V1.0 是否只做到剧集规划和资产合并，媒体批量生产放到 V1.1。
