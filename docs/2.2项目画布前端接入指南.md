# 2.2 项目画布前端接入指南

代码核对日期：2026-09-30。本文按当前后端接口说明前端调用顺序；完整字段与限制见[项目画布接口](2.1项目画布接口.md)，项目管理和全部路由分类见[项目型接口文档](2.0项目型接口文档.md)。以下页面行为是接入要求，不代表本仓库已实现前端。

注册登录、上传、模型选项、积分和通用任务按[通用接口](0.0通用接口文档.md)接入，不套用 Agent 或管理端对象。项目审核和 Agent 资产业务审核含义不同，不能仅按同名 review_status 合并状态。

## 1. 页面和本地状态

按“项目列表 → 项目中的画布列表 → 当前画布”组织页面。项目创建后没有默认画布，画布创建后没有默认节点。都允许空列表，前端展示创建入口，不将空数据渲染为模型错误。

| 前端状态 | 后端来源 |
| --- | --- |
| 项目基本信息 | ProjectOut |
| 画布列表 | CanvasSummary 分页 |
| 当前节点、连线、视口 | CanvasOut |
| 本地待保存修改 | 前端维护，不能被后台轮询直接覆盖 |
| 图片/视频展示 | 节点 media_id → media/batch |
| 文本已选结果 | selected_generation_id → generations/batch 的 result.text |
| 当前活动任务 | 画布 tasks；后续可按 task_record_id 使用通用任务 batch |
| @ 候选 | 目标节点 reference-inputs |
| 审核状态 | media.review 或审核状态接口 |

将输入文本和输出文本分别展示：content.text 是输入，生成结果不会自动写回这个字段。没有 selected_generation_id 时展示“尚未生成/未选择结果”，不能从输入推断已有结果。

## 2. 初始化与恢复页面

1. `GET /projects` 获取项目；创建用 `POST /projects`，只传 name/cover/description。
2. 进入项目后读取详情及 `GET /projects/{project_id}/canvases`。没有画布时显示空态；用户创建时调用 POST 同一路径。
3. 选择画布后 GET 画布详情，保存 revision 及每个节点的 content_revision。
4. 收集节点和图片连线的 media_id，每批最多 100 个读取 media/batch；节点当前图片与连线固定图片可能不同，二者都要读取。
5. 收集 selected_generation_id，每批最多 100 个读取 generations/batch 恢复选中结果；需要查看历史时再分页查询节点 generations。
6. GET 画布 tasks，status=active；多页时继续翻页，不能把第一页当作全部任务。仅恢复当前页面所需轮询。

所有路径默认加 `/api/v1`。项目资源请求带 Bearer Token。使用返回 UUID，不混用 media_id、image_id、generation_id、task_record_id。

## 3. 编辑与保存队列

| 操作 | 使用的请求字段/接口 |
| --- | --- |
| 新增节点 | PATCH 画布 upsert_nodes，客户端生成 UUID |
| 修改提示词、模型、标题、媒体、分组 | PATCH 画布 update_nodes |
| 拖动、缩放节点、平移/缩放视口 | PATCH 画布 /layout |
| 新增/更新连线、刷新引用 | PATCH 画布 upsert_edges |
| 删除节点/连线 | PATCH 画布 delete_node_ids/delete_edge_ids |
| 改画布名称 | PATCH 画布 name |

同一画布的保存请求串行发送，每次使用最近确认的 revision。高频拖动可在本地合并后发送布局请求。upsert_nodes 是完整替换，不能用于只发送一个修改字段；局部编辑用 update_nodes。upsert_edges 同样需要完整可写字段，遵守固定图片/文本的保留规则。

请求成功后用响应更新本地版本；完整 PATCH 返回完整画布，layout 只返回修改节点的几何字段，不要当作全量节点覆盖。

出现 40978 时重新读取画布，将未保存的本地操作与服务端状态合并后提交；不要只替换版本号盲目重发旧全量对象。提交生成和选择结果也会改画布版本，生成自动应用可能异步改版本，因此不能只依赖上一次编辑响应。

## 4. 图片上传、绑定与复用

1. 上传文件到 `POST /projects/{project_id}/media/images`，multipart 字段为 file，保存返回的 ProjectMediaOut。
2. 创建 image 节点或用 update_nodes 绑定 media_id。上传接口本身不创建节点。
3. 把源图片节点连接到目标节点，使用 reference 或首尾帧连线。创建时省略 media_id，后端固定源节点当前图片。
4. 通过目标节点 reference-inputs 获取该图片候选并插入引用。

已在项目媒体列表中的图片直接复用 media_id；本人已有用户级 Seedance 图片通过 media/imports 导入后使用新的项目 media_id。无需为每个画布重新上传同一个文件。

图片连线固定旧版本后，源节点换图不会同步替换下游。source_changed=true 时提示“来源已更新”；用户选择更新时，将该连线完整字段与 media_id=null 一起保存。保留原图则不改绑定，不自动触发审核重试。

## 5. 文本引用与 @ 交互

文本可以引用到文本、图像或视频节点。由用户选择来源是“输入文本”还是“已选生成结果”，保存为 input=text 的连线及 text_source=input/result。

1. 先保存源文本；若选择生成结果，先确保源节点有已选中的成功结果。
2. 保存 text 连线。后端生成快照，前端不能提交 text_snapshot。
3. GET 目标节点 reference-inputs，按 kind 展示图片/文本候选，禁用 available=false 的项。
4. 编辑器可显示“图片1”“文本1”或自定义芯片标签，持久化使用 `@{reference_id}`。这里 reference_id 是连线 ID，不是源节点 ID。
5. 保存目标 content.text，再提交生成。

候选仅包含目标节点已连接的输入。选其他节点为来源时，先建立连接再引用；不要把项目所有素材直接伪装成候选，也不要调用对话历史消息引用接口。

同源同目标只能有一条 text 连线；更换 input/result 模式时修改这条连线。源内容变化后显示 source_changed 提示，但固定快照继续有效；用户选择“更新引用”时，在完整连线请求中传 refresh_text=true。

连线未在提示词中出现：文本不自动追加，图片仍作为模型输入。不要把这两种行为混为一谈。图片候选 available=true 只表示来源可用，Seedance 能否生成还要检查审核状态。

删除连线或源节点后，前端应清理或标红相关文本标签并保存目标提示词；后端不会自动替换它们。嵌入文本只展开一层，不显示为自动执行工作流。

## 6. Seedance 审核交互

**项目图片上传不自动审核。** 选中受共享审核门禁约束的 Seedance 模型后，检查该目标的全部图片输入，包括参考图和首尾帧。

| 状态 | 前端行为 |
| --- | --- |
| source_verified=false | 提示重新上传原文件并替换绑定，不发起审核 |
| review=null | 调用 POST 项目 media/{media_id}/review 登记，保存返回的 image_id |
| pending/processing | 展示审核中，轮询 GET uploads/images/{image_id} |
| can_reference=true | 允许该图片通过审核门禁 |
| failed/uncertain 且 can_retry=true | 展示 review_error 与重试入口 |
| retry_requires_confirmation=true | 用户确认重提后，retry-review 传 confirm_resubmit=true |
| can_reference/can_retry 均 false 且配置变化 | 按返回提示重新登记/上传，不能自行改为通过 |

审核登记返回 SeedanceImageOut，不包含项目 media_id；保留 media_id→image_id 的关联，不能用审核返回对象覆盖整个媒体对象。有审核对象但 failed/uncertain 时，重复调用项目 review 仅复用状态；重试走专用 retry-review。

同一审核配置下切换 Seedance 型号，保留附件、media_id、连线及已审核记录。切换动作只修改目标模型参数，并刷新已有状态；不要先清空审核再上传。后端没有自动识别非真人并免审核的开关。

此门禁不是所有图像生成或所有视频模型的统一要求；适用模型白名单以接口文档和服务代码为准。图片素材可先在画布中展示/连线，审核未通过时阻止的是受门禁约束的生成。

## 7. 生成、轮询与选结果

1. 等待当前保存队列完成，确认目标模型、提示词、引用及必要审核均可用。
2. 读取最新 content_revision，用新 UUID 作为本次 idempotency_key，提交节点 generations；请求体只有这两个字段。
3. 保存返回的 generation.id 与 task_record_id，展示任务状态。HTTP 200 仅表示提交/幂等复用成功。
4. 优先将当前页面的 task_record_id 合并订阅通用 `GET /task-records/stream?ids=<UUID>&ids=<UUID>`（最多 50 个 ID），携带 Bearer 鉴权。snapshot 更新任务 status/phase/progress_percent；persisting 显示“生成完成，正在保存”。连接期间不重复 HTTP 轮询，终态立即读取业务结果。收到 fallback 后关闭 SSE，改为每 2 秒 batch 查询；断线重连重新读取快照，不依赖历史事件重放。

   未接入 SSE 时按任务提示轮询。通用 task-records/batch 每批最多 50 个任务 ID，支持外层 stop_polling/next_poll_seconds；画布 tasks 为分页列表，只在 item 中提供提示。

   活动任务（文本、图像、视频）的状态查询提示为 1 秒，终态为 null。每次响应后更新计时器，不要继续沿用旧的 60 秒间隔。优先合并当前页面任务使用 batch 查询；检测到成功后立即读取 generations/batch 更新对应节点，不再额外等待一个轮询周期。媒体后台首次立即查询厂商，未完成时默认每 2 秒查询一次，前端频繁读取平台状态不会直接触发同频率的厂商查询。
5. 成功后用 generations/batch 读结构化 result，并重新读取画布版本、selected_generation_id 和媒体。不要把通用任务的 result 字符串当成画布结果对象。
6. 有本地未保存编辑时保留本地修改，合并服务端状态；auto_applied=false 不应强行覆盖当前节点。
7. 手动选择历史结果时发送当前 expected_content_revision 和 result_index，更新返回的节点与画布版本。选结果不会恢复历史提示词/模型配置。

网络响应丢失时重发原幂等键和原内容版本，不新建键。主动“再生成一次”使用新键。40979 表示节点内容版本变化，重新读取并确认输入；40980 表示旧键与提交版本不匹配。

失败只依据任务 status=failed 和 failed_reason 展示；空 content.text、空 cover、null selected_generation_id、空历史不展示“模型响应失败”。模型选择列表来自 /models/options，ai_model_id 使用 UUID id；节点类型分别选择 text/image/video 模型。

## 8. 删除入口

### 8.1 项目列表删除

调用 `DELETE /projects/{project_id}`，无版本参数。成功 data 为 ProjectOut 且 is_enabled=false。删除列表项、退出该项目、清理本地选择/缓存/保存队列及轮询。

项目软删除会将活动项目任务标记失败并按已有逻辑处理退款；不应提示“仅隐藏项目、任务继续执行”。

### 8.2 画布菜单删除

先停止产生新的编辑请求，处理已在途保存，再携带最新 revision 调用 `DELETE /projects/{project_id}/canvases/{canvas_id}?expected_revision=...`。

成功 data 为 `{id,deleted:true}`。关闭画布，清理它的选中对象、待保存操作、自动保存计时器和轮询；刷新画布列表并选择剩余画布或显示空态。最后一张可以删除，不自动调用新建接口补回。

画布删除不取消已提交任务、不自动退款；项目素材和生成历史保留。不要用继续请求已删除画布的 tasks 来等待这些任务，确需跟踪可使用已有 task_record_id 的共享任务接口。

### 8.3 节点、分组、连线删除

统一使用画布 PATCH。删除分组默认保留子节点并解除直接从属关系；“删除分组及内容”须计算全部后代 ID 后显式提交，遵守单次 500 操作限制。节点/连线删除不会清理已登记媒体，也不会取消生成任务。

## 9. 接入检查清单

- 项目与最后一张画布可以删除；项目 DELETE 与画布 DELETE 的响应结构不同。
- 空项目、空画布、空节点正确显示草稿/空态。
- 普通编辑、布局保存、生成异步更新共用正确的画布版本；并发冲突保留本地输入。
- 文本输入与输出分开显示，文本引用使用固定快照并支持显式刷新。
- 图片替换后旧连线版本不会悄悄改变；删除引用后不会继续提交失效标签。
- Seedance 模型切换保留附件和审核；审核重试只走专用接口。
- media/generations/task-records 三种 batch 的 ID、数量上限、缺失处理及响应字段分别处理。
- 前端不显示未实现的后端能力：章节模式、素材删除、全图自动执行、服务端撤销、单任务取消和通用生成重试接口。

本文是代码对应的接入说明，不代表已经完成前端实现、真实供应商联调或数据库部署。
