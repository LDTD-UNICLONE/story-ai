# 0.0 通用接口文档

代码核对日期：2026-09-30。覆盖 31 个共享接口，供对话、项目画布、Agent、作品及管理页面按需调用。完整路由、查询参数和请求字段声明见[全量接口索引](0.1全量接口与请求字段索引.md)。

## 1. 通用约定

“通用”表示多个业务共用，不代表允许匿名访问。每个接口是否需要登录，以其鉴权列和说明为准。

默认 API 前缀 `/api/v1`，下文省略此前缀。JSON 接口通常返回 `{code,message,data,timestamp}`，成功 HTTP 200、code=0；字段校验失败 HTTP 422/code 42200，data 为 type/loc/msg 数组。媒体重定向、SSE 和微信成功回调有独立格式，不能套用 JSON 外层。

需要登录的请求携带 `Authorization: Bearer <access_token>`。可匿名接口若声明可选登录，缺少凭证按匿名处理，提供无效凭证仍返回错误。管理员接口还检查 is_admin；账号禁用、令牌失效会被拒绝。公共公告、模型和风格选项没有登录依赖。

时间按服务器配置时区序列化，默认 Asia/Shanghai。接口响应经过公共脱敏；空字符串和空业务对象不是任务失败。错误码须与具体接口一起判断，同一业务码可能在不同模块表达不同含义。

分页默认 page=1、page_size=20，page≥1、page_size 为 1–100，除非具体接口另有声明。分页响应为 items/total/page/page_size。

### 2.1 注册短信与注册

短信请求：

```json
{"phone":"13800138000"}
```

phone 必须为 11 位数字；服务层进一步要求大陆手机号格式 `^1[3-9]\d{9}$`。已注册手机号返回 409/code 40902。发送间隔、验证码有效期和验证次数上限取配置；过于频繁返回 42910，验证次数超限返回 42911。成功不返回验证码正文。

注册请求：

```json
{
  "account":"creator001",
  "password":"example-password",
  "nickname":"创作者",
  "phone":"13800138000",
  "sms_code":"123456"
}
```

account 长度 3–64，password 8–128，nickname 1–64，sms_code 4–8 位数字，均必填；avatar 可选/可空、最长 512，email 可选/可空、最长 255。avatar/email 的空白字符串规范化为 null；未指定头像使用配置的默认头像。账号、手机号、非空邮箱重复返回 40901；验证码错误/过期返回 40010。注册成功创建普通启用账号、赠送 100 积分并消费验证码，返回用户对象，不自动返回 Token。

### 2.2 登录与用户响应

登录 JSON：

```json
{"identifier":"creator001","password":"example-password"}
```

identifier 必填，长度 1–255，可用账号/手机号/邮箱；password 必填，长度 1–128。不是 OAuth 表单，也没有 refresh_token 字段。

TokenOut：access_token、token_type（bearer）、expires_in（秒）、user（UserOut）。UserOut 字段为 id/account/nickname/avatar/phone/email/is_admin/is_enabled/points_balance；可空字段为 avatar/phone/email，不返回密码哈希或 token_version。

缺少凭证返回 401；凭证格式、过期或版本失效为 40102；用户不存在为 40103；账号禁用为 40302。管理端重置密码使旧 Token 失效。

### 2.3 个人资料修改

`PATCH /api/v1/users/me/profile` 必须携带 `Authorization: Bearer <access_token>`。后端通过 `get_current_user` 校验登录状态，并使用当前登录用户的 ID 更新资料；不能指定其他用户 ID。缺少或无效凭证返回 HTTP 401，账号禁用返回 HTTP 403。

仅接受 nickname、avatar，拒绝额外字段；省略保持原值，允许空对象。nickname 字符串长度 1–64；avatar 最长 512，null 或空白用于清空。当前 nickname 的 Schema 声明允许 null，但服务直接写入非空数据库列，不能将 null 当作可成功清空昵称的合同；前端修改昵称时提交有效字符串。此处记录现有实现边界。

| GET | `/materials/{material_id}` | 登录 | MaterialBaseOut |
| GET | `/materials/{material_id}/image` | 登录 | HTTP 307 重定向到签名图片地址 |
| GET | `/styles` | 公开 | StyleBaseOut 数组 |
| GET | `/styles/{style_id}` | 公开 | StyleOut |
| GET | `/models/options` | 公开 | vendor/model_type 可选，各最长 64 / AiModelOptionOut 数组 |
| GET | `/models/{ai_model_id}` | 公开 | 启用模型 AiModelOut |

公告只返回启用且处于发布时段的记录，按 sort_order、created_at 倒序；不存在/未发布为 40420。AnnouncementBaseOut：id/title/content/content_format/image_url/link_url/announcement_type/display_position/style_config/sort_order/start_at/end_at。内容及链接经过安全处理；不要把管理端预览对象当作公开公告对象。

StyleBaseOut：id/name/cover/version；StyleOut 额外含 prompt/is_enabled/created_at/updated_at。只读取启用风格，列表按 created_at 倒序。普通项目画布不需要选择风格，Agent 仍使用 style_id。

AiModelOptionOut：id/nickname/model_id/vendor/model_type/remark/configuration；AiModelOut 额外含 is_enabled/is_agent_default/created_at/updated_at。选项过滤停用和维护模型；模型详情仅要求启用，维护状态看 configuration.operations。ai_model_id 使用 UUID id；供应商 model_id 是另一字段。能力与计费配置定义见[管理端模型章节](5.0管理端整体接口文档.md#4-ai-模型管理)，画布还受其独立参数白名单限制。

## 4. 通用上传与图片审核（3 项）

| 方法 | 路径 | 请求 | 响应 data |
| --- | --- | --- | --- |
| POST | `/uploads/file` | multipart：file 必填，category 默认空字符串，purpose 默认空字符串 | 普通用途 UploadFileOut；seedance_reference 用途 SeedanceImageOut |
| GET | `/uploads/images/{image_id}` | 无正文 | SeedanceImageOut |
| POST | `/uploads/images/{image_id}/retry-review` | 可省略正文；SeedanceImageRetryRequest | SeedanceImageOut |

全部要求登录。purpose 仅允许空字符串或 seedance_reference；后者只接受图片，使用共享审核上传目录，category 不参与该分支。普通上传受允许扩展名、内容检测及 max_upload_size_mb 配置约束。

UploadFileOut：url/object_key/filename/content_type/size/file_type/media_info，media_info 可空。SeedanceImageOut 在此基础上增加 image_id/review_status/can_reference/can_retry/retry_requires_confirmation/review_error/reused。状态取 pending/processing/ready/failed/uncertain；内部 submitting 对外归为 processing。

`purpose=seedance_reference` 上传成功即登记异步审核，但 HTTP 200 不表示通过。图片须非空、小于 30MB 且不超过平台上传上限；相同用户、图片内容和当前供应商配置复用记录，重命名不强制重审。

重试默认 confirm_resubmit=false，必须为布尔值；failed 可重新提交，uncertain 有供应商任务 ID 时恢复查询，无任务 ID 时须确认重提，否则 40999。can_reference/can_retry 同时受当前供应商配置兼容性影响。ready/pending/processing 重试不重新提交。查询其他用户记录返回 40420。

对话使用上述上传用途；项目画布的 media/images 上传不自动审核，另调项目 media/{media_id}/review。两者复用审核服务但入口行为不同，详见[对话](1.0对话型接口文档.md#seedance-上传时审核)与[画布](2.1项目画布接口.md#5-项目素材与-seedance-图片审核)。普通上传只返回 URL 时，不得自行伪造 image_id。

## 5. 通用任务查询（5 项）

| 方法 | 路径 | 请求 | 响应 data |
| --- | --- | --- | --- |
| GET | `/task-records` | business_type/generation_type 可选各最长 32；分页 | UserTaskRecordOut 分页 |
| GET | `/task-records/options` | 无正文 | business_types/generation_types/statuses |
| POST | `/task-records/batch` | JSON ids，1–50 个 UUID | items/total/stop_polling/next_poll_seconds |
| GET | `/task-records/stream` | ids 为重复查询参数，1–50 个 UUID | SSE：snapshot、fallback |
| GET | `/task-records/{task_record_id}` | 任务 ID 字符串，服务校验 UUID | UserTaskRecordOut 加轮询提示 |

全部要求登录。UserTaskRecordOut：id/user_id/ai_model_id/points_transaction_id/business_type/business_id/generation_type/status/title/prompt/result/points_cost/extra/created_at。可空字段包括 ai_model_id、points_transaction_id、business_id、result。result 为字符串或 null，不是画布生成的结构化结果对象。

列表不额外附加 stop_polling/next_poll_seconds。单条和 batch 的每个 item 会附加这两个字段及 phase，终态 success/failed 停止轮询；batch 外层也有聚合提示，取活动项最小建议间隔，空结果 stop_polling=true。batch 去重并保持请求顺序，缺失/非本人记录省略，没有 missing_ids。

活动任务（pending/running）的客户端 `next_poll_seconds=1`，终态为 null；历史 extra 中的 next_poll_seconds 不控制顶层提示。这是读取平台状态的间隔，不是查询厂商的频率。对话、画布及 Agent 媒体生成统一后台回收：首次立即入队，未完成时由 PROVIDER_TASK_POLL_INTERVAL_SECONDS 控制查询间隔，默认 2 秒。读取成功结果后立即更新界面，不再加固定延迟。

`phase` 为 queued（排队）、generating（生成中）、persisting（厂商已完成，成品正在保存）、completed 或 failed。现有 status 不变；转存期间 status=running，不因转存失败重新生成或退款。provider_completed_result 属于内部字段，不返回给前端。

**多任务状态通知**：`GET /api/v1/task-records/stream?ids=<UUID>&ids=<UUID>`，需要 Authorization Bearer Token，最多 50 个 ID，重复 ID 去重。使用支持自定义鉴权头的 fetch SSE 客户端，不把 Token 放在 URL。每次快照都按当前用户过滤任务，不存在或非本人任务放入 missing_ids。

```text
event: snapshot
data: {"items":[{"task_record_id":"<UUID>","status":"running","phase":"persisting","progress_percent":80}],"missing_ids":[],"stop_streaming":false}
```

snapshot 是完整当前状态，items 仅含上述 4 个字段；不包含提示词、成品正文、原始厂商响应。建立连接先返回快照，有变化后发送新快照。所有找到的任务均为终态（或没有找到任何任务）时 stop_streaming=true 并关闭连接；成功后立即调用对应业务结果接口。没有变化时发送 `: keep-alive` 注释。

通知通过 Redis 唤醒，数据库作为最终依据；默认每 15 秒读取快照补偿漏通知，重连重新读取快照，不提供事件 ID 续传。每用户同时最多 3 个任务 SSE 连接（含对话专属 SSE）；超过上限、Redis 不可用或连接租约失效时发送 `event: fallback`、`data: {"next_poll_seconds":2}` 并关闭，前端改用合并 batch 查询，不要立即无限重连。降级查询遇到 HTTP 429/503 时按 Retry-After 等待，Redis 整体故障时其他接口也可能暂时不可用。新建任务后更新订阅 ID 集合需重新建立连接。

单条与 batch 返回 Cache-Control:no-store；有建议间隔时提供 X-Next-Poll-Seconds。任务读取可能触发现有超时检查及失败处理，并非所有 GET 都是纯数据库读取。options 返回当前注册枚举，含普通项目画布和独立 Agent 内部仍使用的 project 任务类型。

此组没有普通用户取消或通用重试入口。对话失败文本轮次重试、Agent jobs/retry、图片审核 retry-review 是不同业务操作，不能混用。

## 6. 用户积分与微信充值（7 项）

| 方法 | 路径 | 鉴权 | 请求 / 响应 data |
| --- | --- | --- | --- |
| GET | `/points/balance` | 登录 | `{points_balance:integer}` |
| GET | `/points/transactions` | 登录 | 分页参数 / PointsTransactionOut 分页 |
| POST | `/points/recharges` | 登录 | RechargeCreateRequest / RechargeOrderOut |
| GET | `/points/recharges` | 登录 | status 可选最长 32、分页 / RechargeOrderOut 分页 |
| GET | `/points/recharges/{order_id}` | 登录 | RechargeOrderOut，仅本人订单 |
| POST | `/points/recharges/{order_id}/sync` | 登录 | 无正文 / RechargeOrderOut |
| POST | `/points/wechat/notify` | 微信签名验签 | 微信原始通知正文 / 独立成功格式 |

PointsTransactionOut：id/user_id/amount/balance_after/transaction_type/remark/created_at。积分余额可能因成功任务实际成本补扣形成负数，不能固定为非负 UI 类型。流水按创建时间、ID 倒序。不能通过个人资料接口修改积分。

充值请求：

```json
{"amount_yuan":"10.0"}
```

amount_yuan 为必填正 Decimal，支持 JSON 数值/十进制字符串。服务先按两位小数四舍五入，再要求金额分数能被 10 整除，即最小充值单位 0.1 元；1 元对应 10 积分。创建微信 Native 订单，使用 code_url 生成支付二维码；创建订单不表示到账。当前没有客户端充值幂等键，不要因超时盲目重复创建订单。

RechargeOrderOut：id/user_id/points_transaction_id/refund_points_transaction_id/out_trade_no/transaction_id/out_refund_no/refund_id/amount_cents/points_amount/pay_type/trade_type/status/code_url/description/paid_at/refunded_at/extra/created_at/updated_at。金额使用分整数，积分为整数；支付/退款 ID 和时间可空，pay_type=wechat_native、trade_type=NATIVE。

当前主要状态为 pending/paid/refunding/refunded。读取本人列表会清理到期且上游仍未支付的 pending 订单，并限量同步 pending/refunding；详情也会检查到期并同步状态，因此查询可能访问微信或改变本地订单，已清理订单可返回 40440。到期时间取 wechat_pay_native_expire_minutes 配置。

支付成功以服务端验签、解密、交易与金额核对后入账为准。回调由微信发送，前端不能用它模拟充值；成功直接返回 `{"code":"SUCCESS","message":"成功"}`，没有 data/timestamp。到账与积分流水按现有订单锁/状态避免重复记账。退款由[管理端充值接口](5.0管理端整体接口文档.md#7-充值订单与退款)处理，用户入口不提供退款操作。

## 7. 健康检查（1 项）

`GET /health` 无登录依赖。检查数据库 SELECT 1 与 Redis ping；两者成功返回 HTTP 200/code 0，data 为 status=ok/database=true/redis=true/time。任一失败返回 HTTP 503/code 50300，status=unavailable 并标明各依赖布尔值。它不验证供应商、OSS 或 Celery Worker 是否可用。

## 8. 代码依据与边界

路由：`app/api/v1/endpoints/` 中 auth、users、announcements、materials、styles、models、uploads、task_records、points、health。权限见 `app/api/deps.py`；字段见对应 `app/schemas/`；业务见 auth、phone_verification、users、materials、seedance_images、billing/recharges、generation/task_records。
