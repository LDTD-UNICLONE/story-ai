# 2.0 管理端整体接口文档

本文档对应当前后端代码，覆盖管理端登录及 `/api/v1/admin/**` 接口。文档中的“删除”以实际代码语义为准：部分资源采用停用或软删除，并不代表数据库物理删除。

## 1. 通用约定

### 1.1 基础地址与数据格式

- API 前缀：`/api/v1`
- 管理端资源前缀：`/api/v1/admin`
- JSON 请求：`Content-Type: application/json`
- 素材新增、编辑：`Content-Type: multipart/form-data`
- 日期：`YYYY-MM-DD`
- 日期时间：ISO 8601；接口按北京时间序列化，例如 `2026-08-20T21:30:00+08:00`
- UUID 参数必须是合法 UUID，否则返回 422。

除素材图片读取接口外，成功响应统一为：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": "2026-08-20T21:30:00+08:00"
}
```

错误响应结构相同，但 HTTP 状态码和业务 `code` 不为成功值：

```json
{
  "code": 42200,
  "message": "参数校验失败",
  "data": [
    {
      "type": "string_too_short",
      "loc": ["body", "title"],
      "msg": "String should have at least 1 character"
    }
  ],
  "timestamp": "2026-08-20T21:30:00+08:00"
}
```

每次响应都带有 `X-Request-ID` 响应头。前端报错时应记录该值，便于后台日志追踪。客户端也可以发送合法的 `X-Request-ID`；允许字符为字母、数字、`-`、`_`、`.`，最长 128 个字符。

### 1.2 管理员登录与鉴权

管理端复用普通登录接口，不存在独立管理员登录端点。

#### 登录

`POST /api/v1/auth/login`

请求：

```json
{
  "identifier": "admin",
  "password": "your-password"
}
```

`identifier` 可以是账号、手机号或邮箱。成功响应的 `data`：

```json
{
  "access_token": "jwt-token",
  "token_type": "bearer",
  "expires_in": 86400,
  "user": {
    "id": "uuid",
    "account": "admin",
    "nickname": "管理员",
    "avatar": null,
    "phone": null,
    "email": null,
    "is_admin": true,
    "is_enabled": true,
    "points_balance": 0
  }
}
```

所有 `/api/v1/admin/**` 请求都必须携带：

```http
Authorization: Bearer <access_token>
```

后端会同时校验 JWT、用户是否存在、账号是否启用、令牌版本和 `is_admin`。常见鉴权错误：

| HTTP |  code | 含义                     |
| ---- | ----: | ------------------------ |
| 401  | 40102 | 凭证无效或令牌版本已失效 |
| 401  | 40103 | 用户不存在或已删除       |
| 403  | 40301 | 当前用户不是管理员       |
| 403  | 40302 | 账号已禁用               |

重置用户密码会递增该用户的令牌版本，使其已有访问令牌立即失效。

### 1.3 分页与 PATCH 语义

所有分页接口统一使用：

| 参数        | 默认值 | 约束     |
| ----------- | -----: | -------- |
| `page`      |      1 | `>= 1`   |
| `page_size` |     20 | `1..100` |

分页响应的 `data` 统一包含：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "page_size": 20
}
```

所有列表均使用稳定排序，并以资源 ID 作为同时间值下的次级排序键，避免翻页时重复或遗漏。

`PATCH` 仅修改请求体中实际提交的字段。数据库必填字段不允许显式提交 `null`；需要保持原值时应省略该字段。公告的 `image_url`、`link_url`、`start_at`、`end_at`，以及用户的 `avatar`、`phone`、`email` 等可空字段可以提交 `null` 清空。

## 2. 公告管理

### 2.1 接口清单

| 方法   | 路径                                             | 用途     |
| ------ | ------------------------------------------------ | -------- |
| GET    | `/admin/announcements`                           | 公告列表 |
| POST   | `/admin/announcements`                           | 新增公告 |
| GET    | `/admin/announcements/{announcement_id}`         | 公告详情 |
| GET    | `/admin/announcements/{announcement_id}/preview` | 公告预览 |
| PATCH  | `/admin/announcements/{announcement_id}`         | 编辑公告 |
| DELETE | `/admin/announcements/{announcement_id}`         | 停用公告 |

### 2.2 列表

`GET /api/v1/admin/announcements`

查询参数：

| 参数                 | 类型             | 说明               |
| -------------------- | ---------------- | ------------------ |
| `keyword`            | string，最长 255 | 模糊搜索标题和正文 |
| `announcement_type`  | string，最长 32  | 精确匹配公告类型   |
| `display_position`   | string，最长 32  | 精确匹配展示位置   |
| `is_enabled`         | boolean          | 是否启用           |
| `page` / `page_size` | integer          | 分页               |

列表按 `created_at DESC, id DESC` 排序。

### 2.3 新增与编辑

新增：`POST /api/v1/admin/announcements`

编辑：`PATCH /api/v1/admin/announcements/{announcement_id}`

请求字段：

| 字段                | 类型          | 新增时 | 约束/默认值                               |
| ------------------- | ------------- | ------ | ----------------------------------------- |
| `title`             | string        | 必填   | 1..128，去除首尾空格                      |
| `content`           | string        | 必填   | 不允许纯空白                              |
| `content_format`    | string        | 可选   | `plain`、`markdown`、`html`；默认 `plain` |
| `image_url`         | string/null   | 可选   | 最长 512                                  |
| `link_url`          | string/null   | 可选   | 最长 512                                  |
| `announcement_type` | string        | 可选   | 1..32；默认 `notice`                      |
| `display_position`  | string        | 可选   | 1..32；默认 `home`                        |
| `style_config`      | object        | 可选   | 默认 `{}`                                 |
| `sort_order`        | integer       | 可选   | 默认 0                                    |
| `start_at`          | datetime/null | 可选   | 发布时间下界                              |
| `end_at`            | datetime/null | 可选   | 发布时间上界                              |
| `is_enabled`        | boolean       | 可选   | 默认 `true`                               |

示例：

```json
{
  "title": "系统维护通知",
  "content": "平台将于今晚进行维护。",
  "content_format": "markdown",
  "announcement_type": "notice",
  "display_position": "home",
  "style_config": { "theme": "warning" },
  "sort_order": 10,
  "start_at": "2026-08-20T22:00:00+08:00",
  "end_at": "2026-08-21T02:00:00+08:00",
  "is_enabled": true
}
```

业务规则：

- `start_at` 不能晚于 `end_at`，否则返回 `40020`。
- 公告内容按 `content_format` 清洗；图片和跳转地址经过安全校验。
- 预览接口在公告字段外增加 `preview_style`，由默认样式和 `style_config` 合并得到。
- 删除接口只把 `is_enabled` 设为 `false`，响应停用后的公告对象。

公告对象字段：`id`、上述业务字段、`is_enabled`、`created_at`、`updated_at`。

```json
}
```

### 3.3 新增与编辑

请求类型必须是 `multipart/form-data`。

新增：`POST /api/v1/admin/materials`

| 字段          | 类型    | 必填 | 说明                                |
| ------------- | ------- | ---- | ----------------------------------- |
| `file`        | file    | 是   | 仅支持真实图像文件                  |
| `name`        | string  | 是   | 清理后最长 128                      |
| `category`    | string  | 是   | 清理后最长 64                       |
| `description` | string  | 否   | 最长 2000                           |
| `tags`        | string  | 否   | JSON 数组字符串或英文逗号分隔字符串 |
| `sort_order`  | integer | 否   | `>= 0`，默认 0                      |
| `is_enabled`  | boolean | 否   | 默认 true                           |

`tags` 示例：`["古风","室内"]` 或 `古风,室内`。后端会去空、去重，单个标签最多 64 字符，最多保留 20 个标签。

编辑：`PATCH /api/v1/admin/materials/{material_id}`

字段与新增相同，但全部可选；提交 `file` 时替换图片。未提交字段以及值为 `null` 的字段不会修改原值；要清空描述或标签可提交空字符串。

业务规则：

- 非图像返回 `40020`。
- 标签 JSON 格式错误返回 `40022`。
- 删除只把 `is_enabled` 设为 `false`，响应 `data: null`。
- 图片接口鉴权后返回 `307 Temporary Redirect` 到短期签名的 OSS 地址，并带私有缓存控制；它不返回统一 JSON 包装。

```json
  "model_type": "video",
```

### 4.3 手动新增与编辑

新增：`POST /api/v1/admin/models`

编辑：`PATCH /api/v1/admin/models/{ai_model_id}`

| 字段               | 类型        | 新增时 | 约束/默认值                                            |
| ------------------ | ----------- | ------ | ------------------------------------------------------ |
| `nickname`         | string      | 必填   | 1..64，去除首尾空格                                    |
| `model_id`         | string      | 必填   | 1..128；在同一 `vendor` 内唯一                          |
| `vendor`           | string      | 必填   | 当前为 `comfly`、`volcengine_ark`、`apimart`            |
| `model_type`       | string      | 必填   | `text`、`image`、`video`                               |
| `remark`           | string/null | 可选   | 空白字符串规范化为 null                                |
| `is_enabled`       | boolean     | 可选   | 默认 true                                              |
| `is_agent_default` | boolean     | 可选   | 默认 false                                             |
| `configuration`    | object      | 可选   | 唯一动态配置字段；包含请求能力、计费和运行状态，见下文 |

业务规则：

- 同一 `model_type` 最多保留一个 Agent 默认模型。设置新的默认模型会清除该类型原默认标记。
- 未启用模型不能设为 Agent 默认模型；停用模型会同步清除默认标记。
- `vendor="模型服务"` 是兼容输入：已识别的火山视频模型转为 `volcengine_ark`，其他转为 `comfly`。
- 厂商名写入时转小写。未知厂商返回 `40005`；`volcengine_ark` 当前只允许 `video`。APIMart 文本接受兼容端点支持的文本模型 ID，图像和视频只允许后端已有调用契约的模型 ID，未接入的 ID 返回 `40005`。
- APIMart 图像、视频模型在 `configuration.request.capabilities` 为空时自动填入项目内置能力描述；响应时也会合并不可覆盖的真实能力范围。
- 新建或导入 APIMart 模型且未显式提交 `configuration.billing.multipliers.platform` 时，文本和视频模型自动使用平台率 1.2，图像模型使用 1。管理员可以通过编辑统一配置调整平台率。
- 模型被历史任务引用后，`model_id`、`model_type` 仍不可修改；需要更换模型标识或类型时应新建模型并停用旧模型。`vendor` 可以在不存在 `pending`、`running` 活动任务时修改，后端会先为缺少快照的历史任务补写旧厂商、旧模型 ID、旧类型及旧计费配置，再切换厂商并刷新新厂商内置能力。存在活动任务时返回业务码 `40904`，响应 `data` 包含 `changed_fields=["vendor"]` 和 `active_task_count`。昵称、积分、平台率、能力和启用状态始终可编辑。
- APIMart 视频模型的真实时长能力固定输出在 `configuration.request.capabilities.duration`，包括 `min`、`max`、可选 `default`、`special`、`mode_values`，以及 `controllable`。管理端保存的同名字段不能覆盖内置真实范围。
- APIMart Seedance 2.0 系列和 Seedance 2.5 会在 `configuration.request.capabilities.private_avatar` 返回真人素材审核能力，并在 `request_keys` 中包含 `private_avatar`。该字段是平台的前置审核开关，不是直接透传给视频生成接口的厂商参数。
- Seedance 2.5 的 `watermark` 由后端固定为 `false`，不会出现在 `configuration.request.capabilities.request_keys` 中；管理端和生成页面都不应渲染该开关。
- 同一厂商内重复 `model_id` 返回 `40902`；不同厂商可以使用相同 `model_id`。前端必须始终以模型数据库 UUID `id` 作为选择值、详情参数和任务参数，不能把 `model_id` 当作全局主键。
- 删除为停用，响应停用后的模型对象。
- `configuration` 是唯一动态配置字段。已删除的旧模型配置字段不再接受也不再响应；提交未知字段会返回 HTTP 422。

#### 4.3.1 统一模型配置

`configuration` 是管理端维护模型动态参数的唯一入口。`vendor`、`model_id`、`model_type` 仍是不可混入 JSON 的路由身份字段，`nickname`、`remark`、`is_enabled`、`is_agent_default` 仍是可查询的管理字段。密钥、Base URL 等厂商凭据继续由服务端环境变量管理，不允许写入模型配置。

统一结构版本当前固定为 1：

```json
{
  "version": 1,
  "request": {
    "capabilities": {
      "resolutions": ["720p", "1080p"],
      "durations": [5, 10],
      "request_keys": ["resolution", "duration", "image_urls"]
    }
  },
  "billing": {
    "base_points": 10,
    "multipliers": {
      "model": "1",
      "cache": "1",
      "completion": "1",
      "platform": "1.2"
    },
    "policy": {}
  },
  "operations": {
    "status": "active",
    "maintenance_message": null
  }
}
```

字段规则：

- `version` 只支持整数 `1`。顶层及三个分区出现未知字段会返回 `40064`，避免拼写错误被静默保存；`billing.policy` 及 APIMart 文本阶梯中的未知字段返回 `40062`。
- `request.capabilities` 是自由 JSON 对象，用于不同厂商和文本、图像、视频类型的请求字段、默认值、枚举和媒体限制。Comfly、火山引擎和 APIMart 的已知模型仍会合并后端内置的真实能力范围。
- `billing.base_points` 是非负整数。文本、视频模型表示“使用该模型所需的最低账户余额”，只校验、不扣除；图像模型保持原逻辑，空策略时作为固定扣分，有图片策略时作为策略基础单价。
- `billing.multipliers` 四项均为非负 Decimal；可省略单项，后端按厂商及模型类型补默认值。`model`、`cache`、`completion`、`platform` 分别表示模型、缓存输入、输出和平台倍率。
- `billing.policy` 使用下文的文本、图像或视频计费策略，类型必须与 `model_type` 一致；APIMart 专属策略仍会校验 `vendor=apimart`。
- `operations.status` 支持 `active`、`maintenance`。维护态模型不会出现在普通用户模型选项中，所有新生成任务在调用厂商前统一返回 HTTP 503、业务码 `50301`；`maintenance_message` 可自定义提示，最长 500 字符。既有异步任务仍可继续查询状态和完成结算。

配置可以省略内部可选值，后端会返回完整规范化结果。管理端再次编辑时建议回传上一响应中的完整 `configuration`。PATCH 示例：

```json
{
  "configuration": {
    "version": 1,
    "request": {"capabilities": {}},
    "billing": {
      "base_points": 10,
      "multipliers": {"platform": "1.2"},
      "policy": {}
    },
    "operations": {
      "status": "maintenance",
      "maintenance_message": "模型升级中，请稍后重试"
    }
  }
}
```

数据库升级会先把存量模型配置回填到 `configuration`，然后删除旧列。任务提交时只快照完整统一配置，因此运行中的任务不会被后续改价影响。

新增厂商时，不需要改变统一配置结构：后端需先实现厂商 Adapter、支持的模型类型、能力合并、计费和测试，再把厂商加入允许列表；管理与计费继续读取相同的 `request`、`billing`、`operations`。管理端不能提前保存一个尚无运行时 Adapter 的厂商。新增不兼容结构时必须提升 `version`，不能在版本 1 顶层直接增加字段。

#### 管理端简化展示约定

管理端普通表单默认只展示 `nickname`、`model_id`、`vendor`、`model_type`、`remark`、`is_enabled` 和 `is_agent_default`，再按“厂商＋模型类型”映射 `configuration` 内的必要路径：

| 厂商/类型    | 普通表单额外展示                                      | `billing.base_points` 含义                       | 平台率                                      |
| ------------ | ----------------------------------------------------- | ------------------------------------------------ | ------------------------------------------- |
| APIMart 文本 | `billing.base_points`、`billing.multipliers.platform` | 使用模型所需最低账户余额，不作为任务预扣         | 省略时后端使用 `1.2`                        |
| APIMart 图像 | `billing.base_points`；有分档时展示图片策略            | 空策略为固定扣分；非空策略按分辨率和参考图计费   | 不展示，省略时为 `1`                        |
| APIMart 视频 | `billing.base_points`、`billing.multipliers.platform` | 使用模型所需最低账户余额；参数预扣独立计算       | 省略时后端使用 `1.2`                        |
| 其他厂商文本 | `billing.base_points`                                 | 使用模型所需最低账户余额，不作为任务预扣         | 默认不展示，使用 `1`                        |
| 其他厂商图像 | `billing.base_points`                                 | 空计费策略下的固定扣分                           | 默认不展示，使用 `1`                        |
| 其他厂商视频 | `billing.base_points`                                 | 最低账户余额；预扣按时长、分辨率和参考类型计算   | 默认不展示，使用 `1`                        |

APIMart 图像、APIMart 视频和已支持的 Comfly/火山视频模型能力由后端自动补齐到 `configuration.request.capabilities`。

隐藏字段应当从请求中省略，不要提交 `null`。编辑时只提交用户实际改动的字段，避免用表单默认值覆盖已有的高级配置。

前端配置控件规则：

- `configuration.request.capabilities` 只用于生成用户侧请求表单，不参与管理端计费计算。优先使用其中的 `request_keys`、`resolutions`、`ratios`、`duration`、`media_limits` 等能力；前端不得把整份能力描述作为生成参数提交。
- APIMart 图像模型的 `request_keys` 仅用于普通用户表单：画面比例、分辨率、生成数量、参考图，以及当前模型支持的 `web_search`、`background`、`sequential_image_generation`、`negative_prompt`。不支持的字段不会返回，前端不得固定展示全部控件。
- APIMart 图像模型的 `advanced_request_keys` 当前可包含 `official_fallback`、`optimize_prompt_options`、`layer_decomposition`；普通用户省略即可。`platform_parameters` 至少包含 `nsfw_check=true`，Seedream 5/4.5 还包含 `watermark=false`；这些字段不显示可编辑控件。
- 管理端可以展示积分预览，但最终积分以任务提交响应和任务详情中的 `points_cost` / `extra.points_billing.user_points_cost` 为准。尤其 APIMart 文本、视频最终费用由后端根据厂商成本或 usage 结算，前端不要自行复算。
- Decimal 倍率与费率使用字符串输入和回显；不要转换成 JavaScript `Number` 后再保存，以免产生精度漂移。

#### 4.3.2 每模型独立积分策略

策略只写入 `configuration.billing.policy`。空策略使用后端内置默认计费规则。配置非空策略时，`type` 必须与模型的 `model_type` 相同；非法字段、未知字段和非法费率均返回业务码 `40062`。通用策略中的费率单位为平台积分；`pricing_unit=apimart_credits` 是例外，单位为 APIMart Credits。

前端按策略类型只提交下表字段，不要透传 UI 临时字段：

| 策略 | 允许字段 |
| --- | --- |
| 通用文本 | `type`、`input_points_per_million`、`cached_input_points_per_million`、`output_points_per_million`、`minimum_points` |
| APIMart 文本 | `type`、`pricing_unit`、`tiers`、`minimum_points`；每个 `tiers[]` 只允许 `max_input_tokens` 和四个 Credits 费率字段 |
| 图像 | `type`、`default_resolution`、`resolution_multipliers`、`pixel_tiers`、`free_reference_images`、`points_per_additional_reference_image` |
| 视频 | `type`、`default_duration_seconds`、`default_resolution`、`rates` |

除 `type` 及各策略下文标记的必要字段外，可选字段应直接省略。不要提交空字符串、`null`、布尔值代替数字，也不要提交已经废弃的 `points_per_image`。

文本模型：

```json
{
  "type": "text",
  "input_points_per_million": "3",
  "cached_input_points_per_million": "1",
  "output_points_per_million": "8",
  "minimum_points": 2
}
```

成功且厂商返回 Token usage 后，实际积分向上取整：

```text
((普通输入 Token × input_points_per_million × multipliers.model)
 + (缓存输入 Token × cached_input_points_per_million × multipliers.model × multipliers.cache)
 + (输出 Token × output_points_per_million × multipliers.completion))
÷ 1,000,000 × multipliers.platform
```

最终结果不低于 `minimum_points`。提交时仅使用 `configuration.billing.base_points` 校验账户最低余额，不发生文本预扣；完成后按厂商成本或 Token 用量一次性结算。因此文本模型应配置合理的准入余额，并确保厂商能够返回成本或 Token usage。

APIMart 文本模型的响应只返回 `usage` 时，使用 Credits 策略按 APIMart 定价页“我们的价格”重建成本：

```json
{
  "type": "text",
  "pricing_unit": "apimart_credits",
  "tiers": [
    {
      "max_input_tokens": 272000,
      "input_credits_per_million": "40",
      "cached_input_credits_per_million": "4",
      "cache_write_credits_per_million": "50",
      "output_credits_per_million": "240"
    },
    {
      "input_credits_per_million": "80",
      "cached_input_credits_per_million": "8",
      "cache_write_credits_per_million": "100",
      "output_credits_per_million": "360"
    }
  ],
  "minimum_points": 0
}
```

这个 JSON 写入 `configuration.billing.policy`。`type` 必须是 `text`，`pricing_unit` 固定为 `apimart_credits`，且该单位只允许 `vendor=apimart`。费率单位为 APIMart Credits/百万 Token，管理员只填定价页“我们的价格”，不填官方价格，也不再叠加厂商折扣率。

阶梯数组最多 10 项，必须按 `max_input_tokens` 严格递增；最后一项不填 `max_input_tokens`，作为无上限阶梯。只有一档价格时，唯一阶梯也不填上限。所有 Credits 费率必须是非负数。

```text
普通输入 Token = prompt_tokens - cached_tokens - cache_write_tokens
Credits 成本 =
  (普通输入 × 输入费率
   + 缓存输入 × 缓存读取费率
   + 缓存写入 × 缓存写入费率
   + 输出 × 输出费率) ÷ 1,000,000
真实人民币成本 = Credits 成本 × 0.7
真实成本积分 = ceil(Credits 成本 × 7)
用户最终积分 = max(minimum_points, ceil(真实成本积分 × multipliers.platform))
```

阶梯按整次请求的 `prompt_tokens` 选择。`completion_tokens` 已包含推理 Token，`completion_tokens_details.reasoning_tokens` 只记录不重复计费。响应没有缓存明细时，缓存读取和写入均按 0 处理。`multipliers.model`、`multipliers.cache` 和 `multipliers.completion` 不参与这个 Credits 策略，避免对“我们的价格”重复加价；平台加价统一由 `multipliers.platform` 控制。

截至 2026-08-22，以下 APIMart 文本模型已由迁移 `0056_apimart_text_billing` 写入独立策略。费率来自 APIMart 模型定价接口的 `pricing.effective_rates`，先按 `1 USD/M Token = 10 Credits/M Token` 换算；平台率统一为 `1.2`。

| 模型 ID | 输入 Token 档位 | 输入 | 缓存读取 | 缓存写入 | 输出 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `gemini-3.7-flash` | 全部 | 6 | 0.6 | 6* | 30 |
| `grok-4.6` | `<= 199999` | 16 | 4 | 16* | 48 |
| `grok-4.6` | `>= 200000` | 32 | 8 | 32* | 96 |
| `qwen3.8-max` | 全部 | 13.714288 | 1.714288 | 17.142856 | 41.142856 |
| `claude-opus-5` | 全部 | 40 | 40* | 40* | 200 |
| `kimi-k3` | 全部 | 24 | 2.4 | 24* | 120 |
| `gpt-5.6-sol` / `gpt-5.6` | `<= 272000` | 40 | 4 | 50 | 240 |
| `gpt-5.6-sol` / `gpt-5.6` | `>= 272001` | 80 | 8 | 100 | 360 |
| `deepseek-v4-pro` | 全部 | 3.48 | 0.029 | 3.48* | 6.96 |

表中费率单位均为 APIMart Credits/百万 Token。`*` 表示 APIMart 没有给出该缓存类型的折扣价，因此使用普通输入价作为保守回退，避免把缺失价格错误当成免费。`qwen3.8-max` 同时公布了更低的显式缓存读取价，但当前 Chat Completions `usage` 不能稳定区分显式与隐式缓存命中，结算统一使用普通缓存读取价；缓存写入仍使用其独立价格。

图像模型：

```json
{
  "type": "image",
  "default_resolution": "1k",
  "resolution_multipliers": {
    "1k": "1",
    "2k": "2",
    "default": "1"
  },
  "pixel_tiers": {},
  "free_reference_images": 0,
  "points_per_additional_reference_image": "0"
}
```

积分公式：

```text
ceil(
  (configuration.billing.base_points × 图片数量 × 分辨率倍率
   + 计费参考图数量 × points_per_additional_reference_image)
  × multipliers.model × multipliers.platform
)
```

图片数量依次识别 `n`、`count`、`num_images`、`number_of_images`，默认 1。参考图数量依次识别 `image_urls`、`reference_images`、`images`、`uploaded_images`、`image_url`、`reference_image`；`计费参考图数量 = max(实际参考图数量 - free_reference_images, 0)`。

分辨率优先识别 `size` 中的档位关键字，其次识别 `resolution` 或 `quality`。`size` 为精确 `宽x高` 时，按总像素匹配 `pixel_tiers` 中从小到大的第一个档位；请求分辨率没有独立倍率时，依次使用 `default`、`default_resolution` 对应倍率，最后使用 1。该策略对 Comfly、APIMart 及后续厂商统一生效；空策略仍使用 `configuration.billing.base_points`。

`points_per_image` 是已废弃的历史兼容输入。后端读取旧数据时会忽略并从规范化响应中移除该字段；新管理端不得展示或提交它。图像基础售价只有一个来源：`configuration.billing.base_points`。

| 720p | 0.032 | 2.24 | 0.04 | 2.8 |
| 1080p | 0.064 | 4.48 | 0.08 | 5.6 |

迁移只写入空的 `configuration.billing.policy`，不会覆盖管理员自定义策略，也不会修改 `configuration.billing.base_points`。该字段只作为视频模型的最低账户余额；视频任务的预计预扣仍由请求参数计算，不再被基础积分抬高。任务成功后最终收费始终优先使用 APIMart 实际成本与平台率结算。

空策略下，文本使用每百万普通/缓存输入 2 积分、输出 5 积分的内置结算；图像使用固定 `configuration.billing.base_points`；视频使用项目内置的 Seedance/参考视频费率或通用费率。只有显式保存非空策略后才启用自定义公式。

平台在创建任务时把模型 ID、厂商、类型和完整 `configuration` 写入任务的 `extra.model_billing_snapshot`。后续成功结算使用该快照，不受管理员在任务运行期间修改模型价格的影响；新价格只作用于修改后提交的新任务。

#### 4.3.3 APIMart 成本结算

APIMart 任务成功后，如果厂商响应包含有效的 `credits_cost` 或 `cost`，后端先计算厂商真实人民币成本与真实成本积分。平台固定兑换关系为 `100 人民币 = 1000 平台积分`，即 1 元等于 10 积分。

```text
credits_cost = cost × 10
厂商真实人民币成本 = credits_cost × 0.7 = cost × 7
真实成本积分 = ceil(厂商真实人民币成本 × 10) = ceil(credits_cost × 7)
```

不同模型类型的用户最终扣费规则：

- 文本：`ceil(真实成本积分 × configuration.billing.multipliers.platform)`，默认平台率为 1.2。
- 图像：空策略使用 `configuration.billing.base_points`；配置图片策略后按请求的分辨率、精确像素和参考图数量扣费。厂商成本只用于后台成本和毛利统计，不覆盖管理端售价。
- 视频：`ceil(真实成本积分 × configuration.billing.multipliers.platform)`，默认平台率为 1.2。

文本、视频提交前都先校验账户余额不低于 `configuration.billing.base_points`。文本不预扣，成功后按厂商成本或 Token 用量结算；视频继续按请求时长、分辨率和参考类型计算预计预扣，但基础积分不再充当预扣下限。厂商返回 `credits_cost/cost` 时优先按厂商成本结算；APIMart 文本仅返回 `usage` 时，按 `apimart_credits` 策略结算并标记 `billing_source=provider_usage`。成本与 usage 都不可用的文本任务不会推测扣费。图像提交和最终扣费均使用任务提交时快照的管理端图片策略；没有策略时使用基础积分。

当文本或视频的厂商实际费用高于预扣且余额不足时，后端仍完整记录补扣流水和负余额，保证任务最终费用与厂商实际返回一致。负余额只允许由成功任务的实际费用结算产生；普通消费仍禁止透支。用户充值补足至非负数前，所有新的模型任务提交统一返回业务码 `40003`。任务的预扣、补扣或退款与 `points_settled` 标记在同一数据库事务中完成，重复执行不会再次结算。对话任务若在“生成结果已保存、积分尚未结算”的窗口发生进程退出，Celery Beat 会周期扫描 `points_settled=false` 的成功任务并恢复结算；扫描只处理新契约显式标记的任务，不会自动追扣历史旧任务。

例如视频任务返回 `cost=0.3104`、`credits_cost=3.104`：真实成本为 `2.1728` 元、真实成本积分为 22；平台率 1.2 时，用户最终消费 `ceil(22 × 1.2) = 27` 积分。任务数据库内部的 `extra.provider_cost_billing` 记录：

```json
{
  "billing_type": "apimart_actual_cost",
  "billing_source": "provider_credits_cost",
  "provider_cost_usd": "0.3104",
  "provider_credits_cost": "3.104",
  "provider_cost_cny": "2.1728",
  "provider_cost_points": 22,
  "pricing_mode": "actual_cost_platform_rate",
  "platform_rate": "1.2",
  "user_points_cost": 27,
  "user_charge_cny": "2.7",
  "gross_profit_cny": "0.5272",
  "gross_margin": "0.1952592592592592592592592593",
  "credits_to_cny_rate": "0.7",
  "points_per_cny": "10"
}
```

图像空策略任务的 `pricing_mode` 为 `fixed_admin_points`，使用图片策略时为 `admin_image_policy`。后端优先使用 `credits_cost`；缺少时使用 `cost × 10`。两者同时存在但不满足 `credits_cost = cost × 10` 时，仍以 `credits_cost` 记录成本，并在 `provider_cost_discrepancy` 记录差值。厂商失败任务仍按任务失败规则退还已预扣积分。

APIMart Credits 文本任务在 `extra.provider_cost_billing` 中使用 `billing_type=apimart_usage_credits`、`billing_source=provider_usage`、`pricing_mode=usage_credits_platform_rate`，并记录命中阶梯、Token 拆分、Credits 成本、人民币成本、真实成本积分和用户最终积分。这是根据厂商 `usage` 和管理端价格重建的成本，不标记为厂商直接返回成本。

普通用户任务响应不会返回 `provider_cost_billing`，只会在 `extra.points_billing` 中看到 `billing_type`、`billing_source`、`user_points_cost` 和 `user_charge_cny`。管理员可通过任务详情接口顶层的 `provider_cost_billing` 查看成本和毛利。

约束：`name` 1..64、`cover` 1..512、`prompt` 非空、`version` 1..32；所有必填文本去除首尾空格并拒绝纯空白。编辑字段全部可选，但提交时不得为 null。风格名重复返回 `40903`。

风格对象：`id`、`name`、`cover`、`prompt`、`version`、`is_enabled`、`created_at`、`updated_at`。删除只停用，响应 `data: null`。

## 10. 系统日志

`GET /api/v1/admin/system-logs`

| 参数         | 类型    | 默认值/说明                                    |
| ------------ | ------- | ---------------------------------------------- |
| `lines`      | integer | 默认 300，范围 1..2000；返回过滤后最后 N 条    |
| `keyword`    | string  | 最长 128，对原始日志行做不区分大小写包含匹配   |

日志文件读取在线程池执行，不阻塞异步事件循环。`log_file` 最终只取文件名并限定在配置的日志目录内，不能通过路径参数读取任意系统文件。

## 11. 任务记录管理

### 11.1 接口清单

| 方法 | 路径                                             | 用途           |
| ---- | ------------------------------------------------ | -------------- |
| GET  | `/admin/task-records`                            | 任务摘要列表   |
| GET  | `/admin/task-records/options`                    | 获取筛选项枚举 |
| GET  | `/admin/task-records/{task_record_id}`           | 任务详情       |
| POST | `/admin/task-records/{task_record_id}/interrupt` | 中断未结束任务 |

### 11.2 列表

`GET /api/v1/admin/task-records`

参数：`user_id`、`business_type`（最长 32）、`generation_type`（最长 32）、`status`（最长 32）、`page`、`page_size`。建议先从 `/options` 获取枚举，不要在前端硬编码。

列表项字段：

```json
{
  "id": "uuid",
  "user_id": "uuid",
  "ai_model_id": "uuid-or-null",
  "points_transaction_id": "uuid-or-null",
  "business_type": "conversation",
  "business_id": "uuid-or-null",
  "generation_type": "video",
  "status": "running",
  "title": "视频生成",
  "prompt_preview": "最多 500 个数据库字符",
  "result_preview": null,
  "points_cost": 10,
  "created_at": "2026-08-20T21:30:00+08:00",
  "updated_at": "2026-08-20T21:31:00+08:00"
}
```

排序为 `created_at DESC, id DESC`。列表只查询提示词和结果前 500 个字符，避免大字段拖慢管理端。

### 11.3 筛选枚举

`GET /api/v1/admin/task-records/options`

响应包含：

- `business_types`：`conversation`（对话型）、`project`（项目型）。
- `generation_types`：文本、图像、视频、章节处理、Agent 剧本与资产分析、分镜及资产媒体生成等当前后端注册类型，每项含 `label`、`value`、`business_type`。
- `statuses`：`pending`、`running`、`success`、`failed`。

### 11.4 详情

`GET /api/v1/admin/task-records/{task_record_id}`

返回完整 `prompt`、`result` 和 `extra`，以及 `id`、用户/模型/积分流水/业务 ID、业务类型、生成类型、状态、标题、积分消耗、`created_at`。APIMart 已完成实际成本结算时，顶层额外返回 `provider_cost_billing`；普通用户任务接口不会返回该字段。对外序列化会清理厂商原始响应和内部错误细节，管理端也不会直接获得密钥或未清洗的厂商负载。

### 11.5 中断

`POST /api/v1/admin/task-records/{task_record_id}/interrupt`

请求体可以省略，也可以提交：

```json
{ "reason": "管理员手动终止异常任务" }
```

`reason` 最长 200。仅 `pending` 或 `running` 可中断；已结束任务返回 `40035`。成功后任务状态变为 `failed`，记录中断管理员和时间，并按现有任务结算逻辑同步业务状态、处理需要退还的积分。返回任务详情对象。

```json

  "status": "hidden"
}
```

审核通过：`POST /api/v1/admin/works/{work_id}/approve`

## 14. 前端对接规则

1. 登录成功后必须检查 `data.user.is_admin === true`，否则不要进入管理端路由；后端仍会对每个管理接口二次校验。
2. 统一拦截 401：清除令牌并跳转登录；40301 显示无管理员权限；40302 显示账号已禁用。
3. 分页请求只更新当前页，不要一次抓取全部数据；切换筛选条件时把 `page` 重置为 1。
4. 对退款、任务中断、用户禁用、作品删除等操作增加二次确认，并在请求进行中禁用重复点击。
5. 充值列表和详情是本地快照；只在管理员点击“同步”时调用 `/sync`。
6. 使用任务列表的摘要字段展示表格，需要完整内容时再请求详情。
7. 素材图片必须使用鉴权请求访问 `/admin/materials/{id}/image`，并允许客户端跟随 307 跳转。
8. 遇到错误时同时记录 HTTP 状态、业务 `code`、`message` 和 `X-Request-ID`。
9. 模型下拉框以数据库 UUID `id` 为 value，以 `nickname` 为主标签，可附带 `vendor / model_id`；不同厂商允许出现相同 `model_id`。
10. 模型编辑页以 GET 详情返回的规范化 `configuration` 初始化。图像基础售价只绑定 `billing.base_points`，不要再创建 `points_per_image` 表单项。
11. 基础积分建议使用 `recommended_base_points`；保留读取 `recommended_precharge_points` 仅用于兼容旧后端，不能同时显示成两个字段。
