## 目标与范围

补齐普通项目的 Seedance 素材审核、提交参数校验、请求去重和生成结果回写保护，避免无效排队、重复计费及旧结果覆盖。参考图超过模型限制时明确反馈，不自行丢弃后继续生成。

- 主要范围：项目角色/场景/道具、资产图片、分镜图片、分镜视频及相关生成历史。
- 通用上传已支持 Seedance 审核；项目资产绑定和视频生成尚未接入审核校验及素材地址转换。项目/Agent 的业务审核状态不等于供应商素材审核通过。
- 优先复用现有审核、任务投递和积分服务，不重新实现一套相同能力，不整体重写项目模块。
- 修改共享服务时必须回归对话与 Agent 调用方。Agent 独立的审核交互改造不默认纳入本轮。
- 不在实施过程中直接修改生产数据、提交真实付费生成任务或执行生产迁移；部署与真实供应商联调单独记录。

## 执行与状态约定

1. 每次实施一项；开始前标注“进行中”。状态统一为：待开始、进行中、已完成、受阻、暂缓。
2. 每项先保留或建立问题回归用例，再修改实现；行为变更同步更新对应接口文档。
3. **验收通过后，必须在总表标注“已完成”、填写完成日期，并更新进度和执行记录。** 仅写完代码或测试被跳过不能算完成。
4. 涉及事务、积分、并发或数据库约束的改动，必须用隔离 PostgreSQL 验证；需要迁移时增加迁移验收。
5. 执行记录填写实际改动、测试命令与结果、未验证范围；遇到阻塞填写原因和恢复条件。

## 分项实施与验收

### POPT-01：项目接入 Seedance 素材审核与复用

**现状**：项目视频直接使用收集到的图片 URL，没有经过对话流程已有的审核校验与 `asset://` 转换。项目资产主要保存 `reference_image`，没有明确关联可复用的审核记录。

**实施范围**：

- 以现有 `SeedanceImage` 和审核服务为基础，确定项目资产、分镜图片、生成历史与审核图片 ID 的绑定方式；实施时明确是否需要数据库迁移及旧 URL 的兼容策略。
- 覆盖用户上传图、项目生成图、故事板图以及首尾帧；项目生成图通过有归属校验的服务端资源登记，不能仅提供任意 URL 就取得他人审核结果。
- 在项目 Seedance 视频提交前汇总并校验实际使用的图片，未通过时返回可定位到附件/资产的状态信息；通过后才创建任务、扣费并转换供应商素材地址。
- 复用现有内容去重、状态查询与手动重试机制。更换图片后重新绑定对应记录；切换 Seedance 型号不清空已有审核结果。
- 其他供应商和无参考图的文生视频保留各自原有规则。

**主要代码入口**：[审核服务](../app/services/seedance_images.py)、[项目资产](../app/services/projects/assets.py)、[项目视频](../app/services/projects/storyboard_videos.py)、[生成历史](../app/services/projects/generated_assets.py)、[资产响应结构](../app/schemas/project_asset.py)。

**验收标准**：

- 未审核、审核中、审核失败、结果待核对的图片均不能用于需要审核的项目视频，且没有新增生成任务或积分流水。
- 已通过图片在 Seedance 2.0、Fast、2.5 间复用同一审核结果，不重复提交审核；原图 URL 仍用于预览。
- 跨用户引用、配置不匹配以及客户端直接提交未授权 `asset://` 不能绕过校验。
- 项目生成图及首尾帧与上传图走相同审核规则；审核重试不等于审核通过。
- 对话已有审核与复用行为不回退；项目接口文档明确资产绑定、状态展示及重试方式。

### POPT-02：完整参数校验前置

**现状**：无效首帧 URL 可以先创建收费任务，再被供应商适配器拒绝。项目提交阶段目前只做部分模式和媒体检查。

**实施范围**：审核素材解析后，复用对应供应商已有的请求构建/校验规则，完整校验最终提交参数；不再维护另一套独立、容易失配的限制。校验置于创建任务和扣费之前。

**主要代码入口**：[项目视频提交](../app/services/projects/storyboard_videos.py)、[项目视频请求结构](../app/schemas/project_storyboard.py)、[供应商适配器](../app/integrations/apimart.py)。

**验收标准**：

- 非法 URL、缺少必需参考媒体、不支持的模式、时长或分辨率，在提交阶段返回明确错误。
- 四种项目视频模式（文生视频、参考生成、首尾帧、故事板）均覆盖有效与无效输入。
- 非法请求没有任务、扣费及投递记录；有效参数与 Worker 实际使用的参数一致。
- 供应商特有合法格式继续可用，特别是服务端解析出的审核素材地址。

### POPT-03：请求幂等与重复提交保护

**现状**：相同项目视频请求可以创建多个任务并分别计费。现有任务 ID、Outbox 和 Worker 重复消费保护不提供 HTTP 请求幂等。

**实施范围**：为项目生成请求增加明确的客户端请求标识，界定用户、操作和请求内容的匹配规则，通过数据库约束与事务保护串行和并发重发。先落地视频，再覆盖资产图片、分镜图片及章节/分镜文本任务；明确旧客户端省略标识时的兼容行为。

**主要代码入口**：[项目生成请求](../app/schemas/project_storyboard.py)、[项目任务提交](../app/services/projects/storyboard_videos.py)、[任务记录](../app/services/generation/task_records.py)、[积分服务](../app/services/billing/points.py)。

**验收标准**：

- 同一用户、操作和请求标识的相同请求，串行及并发提交均返回原任务，只扣一次积分。
- 同一标识对应不同参数时明确拒绝，不能误复用其他请求；不同用户之间不能读取或复用对方任务。
- 用户主动再次生成使用新标识，可以创建新候选；网络重试保留原标识，不转成新任务。
- 数据库提交后响应丢失，再次提交能够找回原任务；Outbox 补偿与 Worker 防重继续有效。
- 请求标识的作用域、保存位置、兼容方式及需要的迁移写入文档。

### POPT-04：旧任务结果与资源版本隔离

**现状**：同一分镜先提交 A、再提交 B，A 较晚返回时仍可覆盖当前任务指针及结果。任务自身的终态保护不能判断它是否仍代表资源的最新生成请求。

**实施范围**：提交时保存目标资源的任务归属及必要输入版本；Worker 和后台结果回收均检查当前任务/版本再更新资源。旧任务结果保留为历史候选，历史记录、积分结算和当前选择分别处理。同步检查资产图、分镜图和章节处理的相同问题。

**主要代码入口**：[历史结果回写](../app/services/projects/generated_assets.py)、[分镜编辑](../app/services/projects/storyboards.py)、[视频执行](../app/services/projects/storyboard_videos.py)、[图片执行](../app/services/projects/storyboard_images.py)、[章节任务](../app/tasks/project_chapter.py)。

**验收标准**：

- A、B 乱序完成，以及旧任务失败/重试回调，均不覆盖新任务状态。
- 生成期间编辑输入或替换资产图片，旧结果不能被自动标记为新版本有效结果。
- 用户手动选择历史候选后，迟到结果不能无条件替换该选择。
- Worker 和后台结果回收路径遵循同一规则；旧任务仍可正确记录历史、结算或退款，不重复处理。
- 对话任务终态和 Agent 已有版本/候选选择机制不受破坏。

### POPT-05：参考图超限明确报错

**现状**：普通项目会将超限参考图自动截断。例如诊断中 15 张图片只保留 9 张；提交响应没有直接说明遗漏了哪些参考图。

**实施范围**：对最终解析、去重后的媒体输入统一检查数量。超限时返回当前数量、允许数量及可定位的附件/资产信息，让用户调整；故事板只使用一张图等已有模式语义单独明确，不与参考模式混淆。

**主要代码入口**：[参考图数量处理](../app/services/projects/storyboard_videos.py)、[项目生成响应](../app/schemas/project_storyboard.py)。

**验收标准**：

- 边界数量可提交；超过限制即报错，不创建任务、不扣费、不静默丢弃图片。
- 用户上传图、角色/场景/道具图及别名参数合并后的输入均受校验，不能通过 `extra` 绕过限制。
- 错误信息足够前端指出需要调整的附件；切换模型只重新校验数量，不使审核状态失效。

### POPT-06：文档收尾与整链路回归

**实施范围**：每项实施时同步文档，本项最后核对整体一致性、迁移顺序和前端联调流程。无需为本轮问题进行无关模块重命名或大规模拆分。

**验收标准**：

- [项目型接口文档](../docs/2.0项目型接口文档.md)、[Seedance 图片审核](../docs/Seedance图片上传审核.md)及受影响的对话文档与实际字段、错误码和状态一致。
- 前端要求写明审核状态、重试、同图跨模型复用、请求标识、超限提示与历史候选选择。
- 完整验证“上传或生成图 → 审核 → 绑定项目资产 → 提交生成 → 结果回收 → 选择历史”的成功与失败路径。
- 相关单元测试、隔离 PostgreSQL 集成测试及新增迁移测试通过；涉及投递行为时补充真实测试队列验证。
- 生产部署、真实供应商联调及未验证范围分别列明，不能用模拟测试替代联调结论。
