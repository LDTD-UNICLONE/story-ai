# 项目中心重新设计计划

创建日期：2026-09-23。当前设计变更：普通项目仅保留画布，COPT-04 双向互通已下线。以下阶段记录保留为历史，不代表现行接口；当前合同见[项目画布接口](../docs/2.1项目画布接口.md)，转换执行记录见[画布唯一模式改造计划](项目画布唯一模式改造计划.md)。COPT-05 前端开发仍待完成。

## 设计目标

项目管理内容，无限画布组织创作，节点负责编辑与生成。用户可以直接创建文本、图像、视频节点，不必先创建章节和分镜；普通项目旧章节和分镜通过0067迁移为节点，独立 Agent 内部流程保留。第一版支持单节点主动生成，连线、拖动和保存不触发付费任务。

设计参考：[TapNow 节点与连接](https://docs.tapnow.ai/zh/docs/canvas/understand-nodes-and-connections)、[LibTV 官网](https://www.liblib.tv/)。参考公开交互，不推断其内部数据库或接口实现。

## 产品与数据规则

1. 节点类型为 `text/image/video/group`。人物、场景、道具是名称或标签，不是图片引用类型。每个生成节点自行选择对应类型的模型。
2. 当前节点显式添加的图片构成 `@` 候选；拖入图片或建立输入连接使用同一份引用关系。不能自动读取全画布、历史消息或其他未连接节点。此规则不改变对话接口仅使用当前草稿附件的规则。
3. 引用使用稳定 ID，并固定具体素材/结果版本；显示名称和编号不作为身份。参考图顺序显式保存，不能根据坐标推断。首帧、尾帧是视频输入位置，不是人物/背景分类。
4. 上游重新生成不自动替换下游输入；用户确认更新。断开的引用应标记失效，阻止生成，不能悄悄忽略。
5. 一次生成保存模型、提示词、参数、实际素材版本快照；布局版本和内容版本分开。旧任务结果只进入自己的历史，不覆盖后续编辑或已选结果。
6. 同一次提交的网络重试复用幂等键，主动再次生成使用新键。任务、扣费和 Outbox 同事务提交。POPT-03、POPT-04 的幂等及旧结果保护是生成阶段的前置要求。
7. 同一素材的多个节点只增加引用，不复制 OSS 文件。删除节点不自动删除媒体，不撤销已发生的供应商调用，也不自动退款。任务结果不能复活已删除节点。
8. Seedance 审核跟随图片内容、用户和供应商配置复用，不能绑定节点或模型型号。未审核图片可以布局、连线、写提示词，提交 Seedance 生成前必须通过后端校验。其他供应商沿用自身规则。

## COPT-01 初始接口合同

统一前缀 `/api/v1/projects/{project_id}/canvases`，登录用户必须拥有启用的普通项目。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | 空路径 | 创建画布，`name` 必填 |
| GET | 空路径 | 分页查询画布摘要，不包含所有节点 |
| GET | `/{canvas_id}` | 获取完整编辑图和 `revision` |
| PATCH | `/{canvas_id}` | 以 `expected_revision` 批量提交修改；原子保存，冲突 409 |
| DELETE | `/{canvas_id}?expected_revision=N` | 按版本删除画布及编辑数据；不删除业务资产 |

节点客户端生成 UUID，ID 在画布内唯一；节点包含 `kind/title/x/y/width/height/parent_id` 和 `content`。内容第一阶段仅为提示文本 `text`，不接收客户端伪造的任务状态、结果 URL、审核状态。图像/视频节点在本阶段是可保存的草稿，不提供上传或生成接口。素材绑定、模型参数在 COPT-02/03 扩展严格 Schema。

PATCH 使用 `upsert_nodes/delete_node_ids/upsert_edges/delete_edge_ids`；upsert 是指定对象的完整替换，未列出的对象保持原样。每批最多 500 次操作，单画布最多 1000 节点、3000 连线，超限明确报错。批量保存名称/视口也走相同版本检查；同一版本并发保存只有一个成功，失败方重新读取后合并，不能盲目覆盖。

节点坐标是画布绝对坐标，分组仅组织内容，不改变坐标系；父节点必须是同画布 group，不允许分组循环。删除分组保留子节点并解除分组。删除节点同时移除入边/出边。连线两端必须存在且非 group，不允许自连、重复输入顺序或循环。输入口为 `reference/first_frame/last_frame`；首尾帧仅允许 image → video，每个输入口最多一个；通用参考按显式 `position` 排序，实际模型兼容性留到生成校验。

`revision` 每次成功 PATCH 增加 1；`content_revision` 在节点文本或输入连接变化时增加，坐标/标题/分组变化不增加。第一阶段连线只是编辑关系，尚不能表示审核通过或可生成；COPT-02 必须增加固定素材版本后才能用于生成。

## 保存与运行分离

后续节点生成接口拟为 `POST /{canvas_id}/nodes/{node_id}/generations`，包含内容版本和幂等键；历史通过同路径 GET 获取。生成前解析稳定媒体引用并验证归属、模型参数及审核，之后创建任务。跨节点关系变化应更新受影响节点内容版本，生成快照必须包含实际输入版本，不能只依赖画布位置版本。

前端拖动只更新本地状态，结束后批量保存；不要每次鼠标移动都提交完整画布。第一版单用户编辑通过乐观版本控制保护多标签页，暂不加入 CRDT/WebSocket 协作。视口缩放与节点数量均设置边界；大媒体只加载缩略图，视频按需播放。后续按运行中任务批量恢复状态。
