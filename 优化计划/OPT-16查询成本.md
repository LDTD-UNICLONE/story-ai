# OPT-16 Agent 查询成本对比

验证日期：2026-09-14。使用独立 PostgreSQL 16 / `story_ai_opt16_test`，无业务数据、外部模型调用或缓存。

## 数据和测量方法

- 典型样本：3 集、15 个分镜、45 个 Agent 视频任务。
- 大样本：40 集、1,000 个分镜、3,000 个 Agent 视频任务。
- 每个分镜有 3 次失败尝试，其中第 1 次带退款标记；按集/镜头顺序产生异常。另有一条不属于该制作的任务，用于确认过滤。
- 章节正文/处理正文、分镜原文/提示词各填充 4,096 个中文字符；任务提示词填充 8,192 个中文字符，模拟生成链路的文本负载。原始模型正文与提示词不属于这些监控响应。
- 使用 [seed_monitoring](../tests/test_agent_monitoring_integration.py) 构造样本。将修改前源码快照以独立模块加载，在同一数据上依次执行前后版本，每次使用新的 SQLAlchemy Session，共 3 次，记录中位数。
- SQL 数由 `before_cursor_execute` 记录；ORM 对象数由 `loaded_as_persistent` 记录，指每次调用实例化的对象数量，并非数据库扫描行数。
- 耗时由 `perf_counter` 记录，包含连接、查询及 Python 组装；内存由 `tracemalloc` 记录每次调用的峰值 Python 分配量，不含 PostgreSQL 内存或进程完整 RSS。测量包含追踪开销，数值用于本机前后对比，不作为生产延迟承诺。
- 费用、完整矩阵、异常页及工作台中的矩阵/费用/控制器/动作逐项比较，前后完全一致。工作台制作对象仅比较 ID 和状态；其完整 HTTP 响应由既有集成测试覆盖。

## 实际优化

1. 费用查询只读取任务类型、金额和退款标记；不加载章节、分镜、批量步骤、完整任务实体或模型提示词。归属仍为当前用户/项目下的制作标记或历史步骤引用，重复引用只计一次。
2. 制作矩阵使用 `load_only` 选择组装所需字段，排除章节正文、分镜正文/提示词、任务提示词等列。先按章节建立分镜索引，将每集重复遍历全部分镜改为一次分组；保留原排序。
3. 矩阵和异常列表共用逐集组装。矩阵只累计异常数量，异常列表只保留当前页结果和当前集的临时结构，保留总数及镜头图片 → 视频 → 章节异常的原有顺序。
4. 工作台通过已授权的制作对象一次加载监控上下文，矩阵和费用共享任务数据；保留原有制作详情、来源文档校验和控制器查询。

## 回归约束与剩余成本

[监控集成测试](../tests/test_agent_monitoring_integration.py) 包含空数据、典型/大样本的金额与分页一致性、历史任务去重/手动任务排除、12 类 JSON 退款值、权限，以及查询数和无用字段加载约束。费用、矩阵、异常、工作台在有章节的固定样本中分别不超过 3、6、6、10 次 SQL；不以易波动的耗时作为 CI 成败条件。

退款金额继续以 `points_cost` 和退款标记的 Python 真值计算，保留空值、布尔、数字、字符串及集合的历史语义，未改为按账本重新统计。聚合仍在 Python 中执行，但输入只含三列；未新增 SQL JSON 真值规则、缓存、索引或迁移。

异常总数与“最新任务/尝试次数”仍需遍历制作范围内的全部记录，数据库没有改为仅查询一页异常。矩阵仍返回全部集和分镜；任务 `extra`、失败结果、批量质量问题仍按现有语义读取。超大历史任务量或超大 JSON 下的进一步数据库聚合/分页，需要另立数据基线与兼容性验证。
