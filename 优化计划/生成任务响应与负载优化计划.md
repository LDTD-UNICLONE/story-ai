## 实现

- `provider_reconciliation.py`：查询只保存状态。成功结果保存到内部 provider_completed_result，设置 generation_phase=persisting，并在同一事务登记媒体转存 outbox。转存任务读取保存结果；失败退避重试，不重新提交生成，也不继续查询已成功的厂商任务。领取锁通过 claim_id 与租约防止重复执行和过期结果覆盖。
- `provider_budget.py`：接入厂商、地址、密钥的哈希作为额度作用域（不含明文密钥）。Redis 原子维护滑动窗口请求数、在途租约及 Retry-After 冷却。等待额度时释放 Worker，Redis 不可用时延后，不退化为无限查询。Worker 意外退出后租约自动过期。
- 查询超时默认 10 秒，SDK 查询不自动重试，统一由调度退避；正常未完成默认 2 秒。错误重试指数递增并带少量抖动，本地上限 60 秒；厂商 Retry-After 可以超过该上限。旧 task.extra.next_poll_seconds 不参与后台调度。
- `task_events.py`：事务提交后发布任务 ID 通知，不发布厂商结果正文。每用户默认最多 3 个 SSE 连接；通知只用于唤醒，数据库是最终依据。默认 15 秒补读快照；Redis 不可用、连接限额或租约失效时发送 fallback，前端转为合并 batch 查询。
- 新增 GET `/api/v1/task-records/stream?ids=<UUID>&ids=<UUID>`，最多 50 个任务。每次快照按当前用户过滤，不泄露非本人任务状态；全部已完成后停止流。对话 SSE 保留原内容事件，改为通知驱动。
- 单条/batch 平台任务、对话任务与画布任务列表增加 phase：queued、generating、persisting、completed、failed。status 不变；转存时仍为 running，只有业务结果保存成功才为 success。
- 转存来源是内部字段，公共响应移除 provider_completed_result。保存 provider_completed_observed_at、media_transfer_started_at、media_persisted_at 时间，配合已有提交/领取时间区分生成、等待与转存耗时。
- 同步直接返回成品的模型仍在原生成 Worker 完成转存；图片审核、Agent 工作流调度不并入生成任务状态机。

## 部署与前端

1. 本轮不新增数据库迁移，依赖现有 task_dispatch_outbox 表和任务 extra。
2. 启动 story_ai_query 与 story_ai_media 的独立 Worker。开发脚本已经增加两者；systemd 需要安装新增的 query/media 模板。停止旧版 Worker 并等待进行中任务退出后，再一并启用新版 API、全部 Worker 与 Beat，避免旧代码消费新阶段任务。不得清空旧队列。
3. 默认查询 Worker 并发 4、转存并发 2。query Worker 每 1000 个任务回收子进程，减少高频短任务造成的进程重启开销。转存额度按所有实例合计，仍需结合单次 GENERATED_MEDIA_TRANSFER_CONCURRENCY 计算。
4. 前端优先一个页面订阅一组任务；连接正常时停止 HTTP 轮询，终态立刻读取结果。fallback 后每 2 秒 batch 查询，不立即无限重连；无 SSE 支持时继续使用既有顶层 next_poll_seconds。
5. 接受厂商任务 ID 后的 Redis/存储故障不触发重新生成或自动退款。媒体查询/转存仍有默认 180 秒的丢失投递安全扫描；正常路径使用立即调度，失败的 outbox 投递由 10 秒扫描补偿。

未重启业务服务、未发送真实生成请求。查询限额是保护初值；如果活跃任务总量超过可支持额度，检测时间会增长，不能保证无限并发下仍每 2 秒查询一次。目标服务器压测应记录队列延迟、查询耗时及 429、数据库连接、内存、磁盘与转存带宽，再确定并发和准入容量。
