# 管理端接口检查与修复

检查日期：2026-09-30。范围为现有管理端接口及其直接调用的用户、积分、充值、公告、素材服务。沿用现有接口结构，针对代码中可复现的缺陷修复。

| 编号 | 已确认问题 | 修复与验收标准 | 状态 |
| --- | --- | --- | --- |
| MOPT-01 | 新建或编辑用户时，账号与邮箱分别命中不同用户，唯一性查询抛出多行异常 | 存在性查询限制一条结果；跨多用户冲突返回 HTTP 409 / `40901`，保留数据库唯一约束兜底 | 已完成 |
| MOPT-02 | 禁用再启用、撤销再授予权限后，旧令牌可能恢复有效；密码重置使用缓存版本时可能丢失递增 | 修改前锁定并刷新用户；实际权限变化及密码重置递增令牌版本；普通资料修改不使令牌失效 | 已完成 |
| MOPT-03 | 积分操作虽有行锁，但 Session 已加载的用户可能仍保留旧余额 | 获取行锁时刷新实体；并发调整按最新余额记账；余额不足校验不能被旧缓存绕过 | 已完成 |
| MOPT-04 | 退款校验余额后未持有余额锁就请求微信，并发消费可能造成退款后扣积分失败 | 调用支付服务前锁定并校验余额，直到本地事务结束；订单也重新读取，避免缓存状态导致重复退款 | 已完成 |
| MOPT-05 | 公告无时区时间与已有带时区时间比较或写入时可能返回 500 | 创建、编辑统一按项目时区规范化；正常请求成功、逆序范围返回 `40020`、显式 null 可清空 | 已完成 |
| MOPT-06 | 素材编辑超长字段在处理函数内校验而返回 500；新增空白名称在文件上传之后才校验 | 表单层限制长度并返回 `42200`；元数据不合法时不上传文件；有效上传及仅修改资料均通过验证 | 已完成 |

- 合计：90 个单元测试、138 个不重复集成用例通过；Ruff 与 `git diff --check` 通过。

## 使用与验证边界

无需数据库迁移，加载新代码后生效。实际改变账号启用状态或管理员权限后，前端应提示用户重新登录。退款调用期间会锁定该用户的余额，同一用户的并发积分变更需等待事务结束。

测试未连接业务数据库，未调用真实支付或 OSS。此次退款修复覆盖余额并发和缓存状态问题；微信请求成功但应用在本地提交前中断的跨系统一致性场景，仍需单独设计持久化退款意图和恢复处理，不属于已完成验收范围。
